# チケット95：メールアドレス確認必須化とパスワード再設定時の本人確認整理

## 背景

現在は、ユーザー登録時に到達不能な適当なメールアドレスでも登録できてしまう可能性がある。

その場合、パスワードを忘れたときに再設定メールを受け取れず、アカウント復旧できなくなる。

また、パスワード再設定メール送信時に、登録されていないメールアドレスを入力しても、画面上は「送信しました」系のメッセージが出るため、ユーザー視点では何が起きたかわかりにくい。

## 目的

アカウント作成時点で、実際に受信できるメールアドレスであることを確認する。

さらに、パスワード再設定時は「そのアカウントに紐づいたメールアドレス」に送る仕様を明確化する。

## 対象ファイル（推定）

```text
js/supabaseAuth.js
js/actions.js
js/render.js
js/config.js
styles.css
README.md
docs/ticket_status.json
```

Supabase管理画面での設定確認も必要になる可能性がある。

## 仕様方針

### 1. ユーザー登録時はメール確認を必須にする

新規ユーザー登録後、登録メールアドレスへ確認メールを送る。

確認メールを完了するまでは、通常ログイン・ゲーム利用・ランキング登録などを許可しない。

表示メッセージ例:

```text
確認メールを送信しました。メール内のリンクを開いて登録を完了してください。
```

### 2. メール未確認ユーザーはログイン後に利用させない

Supabase Auth上でメール確認が未完了の場合は、ログイン成功扱いにしない。

期待動作:

```text
ログイン画面に戻す
ゲーム画面へ遷移しない
ユーザーデータ画面へ遷移しない
ランキングへ記録しない
```

表示メッセージ例:

```text
メールアドレスの確認が完了していません。確認メールを開いて登録を完了してください。
```

### 3. 確認メール再送導線を用意する

ユーザーが確認メールを見失った場合に備えて、ログイン画面または登録完了後の画面に確認メール再送導線を用意する。

表示例:

```text
確認メールを再送する
```

### 4. パスワード再設定は登録済みメールアドレス宛に送る

パスワード再設定メールは、アカウントに紐づいた登録済みメールアドレスへ送る。

ユーザー入力欄については、以下どちらかの方式から実装時に安全な方を選ぶ。

#### 案A：メールアドレスのみ入力

```text
メールアドレスを入力
送信ボタン
```

表示メッセージは、登録有無にかかわらず同一にする。

```text
入力されたメールアドレスに一致するアカウントがある場合、再設定メールを送信します。
```

メリット:

```text
アカウント存在確認に悪用されにくい
一般的なパスワードリセット仕様に近い
```

デメリット:

```text
未登録メールを入力したユーザーには、メールが届かない理由がわかりにくい
```

#### 案B：ユーザー名 + メールアドレスの一致確認

```text
ユーザー名
登録メールアドレス
```

両方が一致した場合のみ再設定メールを送る。

一致しない場合は送信しない。

表示メッセージ例:

```text
ユーザー名またはメールアドレスが一致しません。
```

メリット:

```text
ユーザー視点では間違いに気づきやすい
登録外メールに送ったつもりになる混乱を減らせる
```

デメリット:

```text
アカウント情報の存在確認に使われる可能性がある
RLSや取得方法の設計に注意が必要
```

### 5. 推奨方針

本チケットでは、まず以下を推奨する。

```text
ユーザー登録時のメール確認必須化を優先する
パスワード再設定は案Aの安全寄り文言にする
ユーザー名 + メール一致確認方式は、必要なら別チケットで検討する
```

理由:

```text
適当なメールアドレスで登録できる問題の根本対策は、登録時のメール確認必須化であるため
パスワード再設定画面で登録有無を明示しすぎると、アカウント列挙リスクがあるため
```

## 実装内容

### 1. Supabase Authのメール確認設定を確認する

Supabase側でメール確認が有効か確認する。

必要に応じて、登録確認メールの有効化、Redirect URL、メールテンプレートを確認する。

### 2. 登録完了後メッセージを変更する

登録直後のメッセージを、ログイン誘導ではなくメール確認誘導に変更する。

変更例:

```text
確認メールを送信しました。メール内のリンクを開いて登録を完了してください。
```

### 3. メール未確認状態でのログインを防ぐ

ログイン後にSupabase Authのユーザー情報を確認し、メール未確認の場合は利用を止める。

確認対象の候補:

```text
user.email_confirmed_at
user.confirmed_at
```

既存のSupabase Authレスポンス構造に合わせる。

### 4. 確認メール再送を追加する

メール未確認ユーザー向けに、確認メール再送導線を追加する。

Supabaseの既存機能を使う場合は、既存クライアント構成に合わせる。

### 5. パスワード再設定時の表示文言を調整する

未登録メールでも「送信しました」と断定しない。

変更後の推奨文言:

```text
入力されたメールアドレスに一致するアカウントがある場合、再設定メールを送信します。
```

## 受け入れ条件

### 新規登録

```text
新規登録後、確認メール送信メッセージが出る
確認メールを開くまでゲーム利用できない
確認完了後、通常ログインできる
```

### 適当なメールアドレス対策

```text
到達不能なメールアドレスで登録しても、メール確認できないため通常利用できない
ゲームプレイできない
ランキング登録されない
```

### メール未確認ログイン

```text
メール未確認アカウントでログインしようとすると、ログイン画面に戻る
メール確認未完了メッセージが表示される
```

### パスワード再設定

```text
登録済みメールアドレスでは再設定メールが届く
未登録メールアドレスでは、送信断定ではなく安全寄りの案内文が表示される
```

### 既存ユーザー

```text
既存ユーザーへの影響を確認する
必要なら既存ユーザーは確認済み扱いにする運用手順をREADMEへ記載する
```

## メモ

このチケット95は仕様整理を含む。

実装前に、以下を先に決めること。

```text
パスワード再設定時は案Aの安全寄り文言で進めるか
ユーザー名 + メールアドレス一致確認まで行うか
既存ユーザーをどう扱うか
```

チケット94の「新パスワード設定画面」と合わせて実装すると、パスワード再設定フローが完結する。
