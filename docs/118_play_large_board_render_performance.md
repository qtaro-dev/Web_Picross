# チケット118：大盤面の描画負荷軽減

## 目的

Endlessや20×20以上の大盤面で、プレイ画面が重くなる問題を改善する。

特に、マウス移動・セルクリック・ドラッグ操作・ハイライト更新時に処理が重くならないよう、盤面描画とDOM更新の負荷を軽減する。

## 対象ファイル（推定）

- `js/render.js`
- `js/actions.js`
- `js/state.js`
- `styles.css`
- `js/config.js`
- `README.md`
- `docs/ticket_status.json`

## 実装内容（具体的変更指示）

- 大盤面での再描画処理を見直す。
- セルクリックや右クリック時に、可能な限り盤面全体を再描画しない。
- 変更されたセルだけを更新できる場合は、対象セルのclassやtextContent更新に限定する。
- マウス移動時の行・列ハイライト更新を軽量化する。
  - 毎回全セルのclassを付け替えない。
  - 前回ハイライトした行・列だけを解除し、新しい行・列だけを付与する。
  - 必要であれば `requestAnimationFrame` や簡易throttleを使って更新頻度を抑える。
- ヒント数字やパレットなど、毎回再生成する必要がないDOMは、不要に再生成しない。
- 大盤面で不要なレイアウト再計算が頻発しないようにする。
- `querySelectorAll` などの全セル走査を、マウス移動やセル操作ごとに過剰実行しないようにする。
- 既存ゲームロジックは変更しない。
- 正解判定、ヒント、ギブアップ、ランキング保存などの内部仕様は変更しない。
- 既存テーマ・ボタンデザイン・ICommand構造を崩さない。
- スクロール位置保持はチケット117で扱うが、チケット118実装後もスクロール位置保持が壊れないようにする。
- パフォーマンス改善のために挙動を変える場合は、READMEまたはチケット状態に理由を記録する。

## 受け入れ条件（目視確認基準）

### Endless #01 / #02 の操作感

- ユーザーがEndless #01またはEndless #02を開く。
- ユーザーが盤面上でマウスを動かす。
- OK：マウス移動時のハイライトが極端にカクつかないこと。
- NG：マウスを少し動かすだけで画面全体が重くなること。

### セルクリック

- ユーザーが大盤面でセルをクリックして塗る。
- OK：クリック後の反応が明らかに遅くならないこと。
- OK：クリックしたセルだけが自然に更新されること。
- NG：1クリックごとに画面全体が固まるように感じること。

### 右クリック×操作

- ユーザーが大盤面で右クリックして×を付ける。
- OK：×表示が自然に反映されること。
- NG：右クリックのたびに大きく処理落ちすること。

### ドラッグ操作

- ユーザーが大盤面で複数セルをドラッグして塗る。
- OK：ドラッグ操作が極端に遅延しないこと。
- NG：ドラッグ中にセル反映が大幅に遅れること。

### ハイライト表示

- ユーザーが大盤面でマウスを動かす。
- OK：行・列ハイライトが表示されること。
- OK：前回のハイライトが残り続けないこと。
- NG：ハイライトが大量に残る、または表示が乱れること。

### カラー問題

- ユーザーがカラーの大盤面を開く。
- ユーザーが色を選んでセルを塗る。
- OK：色選択とセル反映が従来どおり動くこと。
- NG：パフォーマンス改善後に色が反映されない、別色になる、選択状態が壊れること。

### スクロール位置との併用

- ユーザーが盤面コンテナ内をスクロールする。
- ユーザーがスクロールした位置でセルを操作する。
- OK：チケット117のスクロール位置保持が壊れていないこと。
- NG：チケット118実装後に、再びスクロール位置が初期位置へ戻ること。

### 既存機能

- ユーザーが通常サイズのBeginner / Easy / Normal / Hardを開く。
- OK：小さい盤面でも従来どおり遊べること。
- OK：やりなおし、判定、ヒント、ギブアップ、メニューへ戻る、セレクトに戻るが従来どおり動くこと。
- NG：大盤面最適化の影響で、小さい盤面の表示や操作が壊れること。
