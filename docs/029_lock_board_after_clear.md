# チケット29: クリア後の盤面操作ロックとクリア通知の多重表示防止

## 目的

ゲーム中に一度クリアしたあとも、盤面セルを削ったり、×を付けたりできてしまい、そのたびに何度でも「クリアしました」系のモーダルが表示される問題を修正する。

一度クリアしたパズルは、クリア後の盤面操作をロックし、セル状態を変更できないようにする。  
また、クリア通知モーダルが多重表示されないようにする。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\engine.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 実装内容

### 1. クリア済み状態をstateで管理する

ゲーム中の現在パズルがクリア済みかどうかをstateで管理する。

状態候補:

```js
gameStatus: "playing" | "cleared" | "timeout" | "giveup"
```

または既存構造に合わせて、以下のような値を持たせてもよい。

```js
isCleared: true / false
isGameLocked: true / false
```

期待動作:

```text
ゲーム開始時:
- playing
- isCleared = false
- isGameLocked = false

クリア時:
- cleared
- isCleared = true
- isGameLocked = true
```

### 2. クリア後は盤面入力を受け付けない

クリア済み状態では、盤面セルの入力処理をすべて無視する。

無視する操作:

```text
- 左クリック
- 左ドラッグ
- 右クリック
- 右ドラッグ
- パレット選択後のセル配置
- ×の配置
- セルの解除
```

注意:

- パレットの選択自体は許可してもよいが、盤面は変更しない
- クリア後にドラッグ状態が残らないようにする
- モーダル表示中も盤面入力を受け付けない

### 3. クリア通知を1回だけ表示する

クリア判定がtrueになったとき、クリア通知モーダルは1回だけ表示する。

期待動作:

```text
初回クリア
→ クリアモーダル表示

その後、判定処理が再実行されても
→ クリアモーダルを再表示しない
```

注意:

- `判定` ボタンを再度押しても多重表示しない
- 盤面入力で再度クリア判定が走っても多重表示しない
- クリアモーダルのOKを押した後も、盤面はロックされたままにする

### 4. クリア後も完成盤面は表示する

クリア後は、完成した盤面を見られるようにする。

許可してよい操作:

```text
- セレクトへ戻る
- メニューへ戻る
- リトライが存在する場合はリトライ
```

無効化する候補:

```text
- 全消去
- ヒント
- 判定
- ギブアップ
```

最小実装では、ボタン自体は残してもよいが、クリア後は効果を持たせない。

### 5. リトライや別問題開始時はロックを解除する

新しいゲーム開始、リトライ、別問題選択時には、クリア済み状態とロック状態を初期化する。

### 6. タイマーを停止する

クリア時にはタイマーを停止する。

### 7. エディットプレイでも同じ挙動にする

通常問題だけでなく、エディットプレイでもクリア後は同じように盤面操作をロックする。

## 受け入れ条件

- ゲーム画面を開ける
- パズルをクリアできる
- クリア時にクリアモーダルが1回だけ表示される
- クリア後、左クリックでセルが変化しない
- クリア後、左ドラッグでセルが変化しない
- クリア後、右クリックでセルが変化しない
- クリア後、右ドラッグでセルが変化しない
- クリア後、×を付けたり消したりできない
- クリア後、塗りや色を変更できない
- クリア後、判定ボタンを押してもクリアモーダルが多重表示されない
- クリア後、完成盤面は見られる
- クリア後、タイマーが停止する
- セレクトへ戻って別問題を選ぶと、通常どおり操作できる
- リトライ機能がある場合、リトライ後は通常どおり操作できる
- エディットプレイでも同じ挙動になる
- `node --check js/state.js` が通る

- `node --check js/render.js` が通る
