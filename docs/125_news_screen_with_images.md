# チケット125：お知らせ画面の実装（画像対応）

## 目的

現在未実装の「お知らせ」画面を実装し、ユーザーが更新情報・メンテナンス情報・機能追加案内などを確認できるようにする。

UIは左カラムにお知らせ一覧、右カラムに本文を表示する2カラム構成とし、本文内には画像も表示できるようにする。  
お知らせ内容は簡単に書き換えられる構成にし、まずはJSONファイル管理で実装する。

## 対象ファイル（推定）

- `index.html`
- `styles.css`
- `js/render.js`
- `js/actions.js`
- `js/state.js`
- `js/config.js`
- `data/news.json`（新規追加候補）
- `assets/news/`（画像格納先候補）
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. お知らせデータをJSONで管理する

- お知らせ本文を簡単に書き換えられるように、まずはJSONファイルで管理する。
- 新規ファイル候補：
  - `data/news.json`
- JSONは配列形式とする。
- 各お知らせは、最低限以下の項目を持てるようにする。
  - `id`
  - `date`
  - `title`
  - `body`
  - `images`
- 例：

```json
[
  {
    "id": "2026-06-01-build-141",
    "date": "2026-06-01",
    "title": "Build #141を公開しました",
    "body": "判定ボタンの表示文言を調整しました。",
    "images": [
      {
        "src": "assets/news/build141_sample.png",
        "alt": "Build #141の画面例",
        "caption": "判定メッセージの表示例"
      }
    ]
  }
]
```

- `images` は省略可能とする。
- 画像がないお知らせでも正常に表示できるようにする。
- お知らせは新しい日付順に表示する。
- 同日の並び順が必要な場合は、JSON記載順または任意の `order` を使えるようにしてもよい。

### 2. 画像の格納先を用意する

- お知らせ用画像を格納するディレクトリを用意する。
- 候補：
  - `assets/news/`
- 画像パスは `data/news.json` から参照できるようにする。
- 画像ファイルが存在しない場合でも、画面全体が壊れないようにする。
- 画像読み込み失敗時は、altテキストまたは代替表示にする。

### 3. お知らせ画面を2カラム構成にする

- UIは以下の2カラム構成にする。
  - 左カラム：お知らせ一覧
  - 右カラム：選択したお知らせの本文
- 左カラムには以下を表示する。
  - 日付
  - タイトル
- 右カラムには以下を表示する。
  - タイトル
  - 日付
  - 本文
  - 画像
  - 画像キャプション
- 最初に表示するお知らせは、最新のお知らせとする。
- 左カラムで別のお知らせを選択すると、右カラムの本文が切り替わるようにする。
- 選択中のお知らせが分かる見た目にする。

### 4. 本文表示に対応する

- `body` はまずはプレーンテキストとして表示する。
- 改行を反映できるようにする。
- 将来的にMarkdown対応する余地を残してもよいが、本チケットでは必須にしない。
- 外部HTMLをそのまま挿入する実装は避ける。
- XSS対策のため、JSON内の文字列をHTMLとして無条件に展開しない。

### 5. 画像表示に対応する

- `images` 配列がある場合、本文下または本文中に画像を表示する。
- 画像は画面幅に合わせて縮小表示する。
- 右カラムからはみ出さないようにする。
- キャプションがある場合は画像下に表示する。
- altがある場合は `alt` 属性に設定する。
- 画像クリック時の拡大表示は本チケットでは必須にしない。
- ただし、画像が大きすぎてもレイアウトが崩れないようにする。

### 6. お知らせが0件の場合の表示

- `data/news.json` が空配列の場合でも画面が壊れないようにする。
- 表示例：
  - `現在お知らせはありません`
- JSON読み込みに失敗した場合も、エラーで白画面にならないようにする。
- 表示例：
  - `お知らせを読み込めませんでした`

### 7. 既存画面からお知らせ画面へ遷移できるようにする

- 既存の「お知らせ」ボタンまたはお知らせエリアから、お知らせ画面を表示できるようにする。
- 一般ユーザーでも閲覧できるようにする。
- 管理者専用にしない。
- ただし、お知らせ編集機能は本チケットでは実装しない。
- 管理者画面から編集する機能は将来チケット扱いにする。

### 8. レスポンシブ対応

- PC画面では2カラム表示にする。
- 画面幅が狭い場合は、上下配置に切り替えてもよい。
  - 上：お知らせ一覧
  - 下：本文
- 1024×768程度でも本文が読めること。
- 画像が横にはみ出さないこと。
- スクロールが必要な場合でも操作不能にならないこと。

### 9. 既存仕様を壊さない

- 既存のメニュー、ログイン、ゲーム選択、実プレイ、エディタ、管理者画面の動作を壊さない。
- 既存テーマ・背景・ボタンデザインを維持する。
- 既存ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。
- Supabase連携は本チケットでは必須にしない。
- 管理者によるお知らせ編集機能は本チケットでは実装しない。

## 受け入れ条件（目視確認基準）

### お知らせ画面表示

- ユーザーがメニューまたは既存のお知らせ入口を押す。
- OK：お知らせ画面が表示されること。
- OK：左カラムにお知らせ一覧が表示されること。
- OK：右カラムに最新のお知らせ本文が表示されること。
- NG：お知らせ画面が未実装表示のままであること。
- NG：白画面やJavaScriptエラーになること。

### 左カラム一覧

- ユーザーがお知らせ画面を開く。
- OK：左カラムに日付とタイトルが表示されること。
- OK：新しい日付のお知らせが上に表示されること。
- OK：選択中のお知らせが分かること。
- NG：一覧が空なのに本文だけ表示されること。
- NG：日付やタイトルが崩れて読めないこと。

### 右カラム本文

- ユーザーがお知らせ一覧から任意のお知らせを選択する。
- OK：右カラムのタイトル・日付・本文が切り替わること。
- OK：本文の改行が読みやすく表示されること。
- NG：別のお知らせを選んでも本文が変わらないこと。
- NG：本文がHTMLとして危険に展開されること。

### 画像ありのお知らせ

- ユーザーが画像付きのお知らせを選択する。
- OK：本文内または本文下に画像が表示されること。
- OK：画像が右カラムからはみ出さないこと。
- OK：キャプションがある場合は画像下に表示されること。
- OK：altが設定されていること。
- NG：画像が大きすぎてレイアウトが崩れること。
- NG：画像読み込み失敗で画面全体が壊れること。

### 画像なしのお知らせ

- ユーザーが画像なしのお知らせを選択する。
- OK：本文のみ自然に表示されること。
- NG：画像枠だけが不自然に残ること。
- NG：`images` がないことでエラーになること。

### お知らせ0件

- `data/news.json` を空配列にした状態を想定する。
- ユーザーがお知らせ画面を開く。
- OK：`現在お知らせはありません` 相当の表示が出ること。
- NG：白画面になること。
- NG：JavaScriptエラーになること。

### JSON読み込み失敗

- `data/news.json` が取得できない状態を想定する。
- ユーザーがお知らせ画面を開く。
- OK：`お知らせを読み込めませんでした` 相当の表示が出ること。
- NG：白画面になること。
- NG：他の画面遷移まで壊れること。

### レスポンシブ確認

- ユーザーが1920×1080相当でお知らせ画面を開く。
- OK：2カラムで自然に表示されること。
- ユーザーが1366×768相当でお知らせ画面を開く。
- OK：一覧と本文が読めること。
- ユーザーが1024×768相当でお知らせ画面を開く。
- OK：必要に応じてスクロールしながら読めること。
- OK：画像が横にはみ出さないこと。

### 回帰確認

- ユーザーがメニューへ戻る。
- ユーザーがゲーム選択画面を開く。
- ユーザーが実プレイ画面を開く。
- ユーザーがエディタ画面を開く。
- 管理者が管理者画面を開く。
- OK：既存画面が従来どおり動くこと。
- NG：お知らせ画面追加の影響で既存画面が壊れること。
