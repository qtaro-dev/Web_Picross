# チケット73: ユーザーデータ画面の管理・デバッグ情報非表示化

## 目的

ユーザーデータ画面に表示されている管理者向け・開発者向け・デバッグ向け情報を、一般ユーザー画面から削除する。

管理者アカウント向けのユーザーデータ改変やデバッグ操作は、今後別途「管理者専用ページ」として実装する前提にし、このチケットではユーザーデータ画面から該当要素を消すことを目的とする。

## 背景

現在のユーザーデータ画面には、一般ユーザーには不要な内部情報・開発用情報が表示されている。

例:

```text
権限
ユーザーID
ログイン種別
保存方式
保存キー
最終結果
開発データ
ユーザーデータJSON出力
現在ユーザーJSON出力
クリア状況リセット
ユーザーデータ削除
```

これらは一般ユーザーに見せる必要がなく、管理者にとっても通常のユーザーデータ画面上に常時表示する必要はない。

将来的には、管理者専用ページを作り、そこでユーザー情報の確認・改変・デバッグ操作を行う。

## 対象ファイル（推定）

```text
js/render.js
js/actions.js
js/state.js
js/config.js
styles.css
README.md
```

## 実装内容

### 1. ユーザーデータ画面の基本情報から不要項目を非表示にする

ユーザーデータ画面の「基本情報」から、以下の項目を非表示にする。

```text
権限
ユーザーID
ログイン種別
保存方式
保存キー
最終結果
```

このチケットでは、一般ユーザーだけでなく管理者ユーザーでも、通常のユーザーデータ画面上には表示しない。

表示してよい項目は最低限以下とする。

```text
ユーザー名
表示名
メールアドレス
登録日時
最終ログイン
最終更新日時
最終読込
最終保存
```

ただし、既存データの有無によって表示できない項目がある場合は `-` 表示でよい。

### 2. ゲームセレクト画面の開発データを非表示にする

ゲームセレクト画面に表示されている「開発データ」折りたたみ項目を、一般画面から削除する。

対象:

```text
開発データ
クリアラン
保存方式
ファイル直保存
保存キー
対象
最終読込
最終保存
保存結果
全件
ユーザーデータJSON出力
現在ユーザーJSON出力
クリア状況リセット
ユーザーデータ削除
```

このチケットでは、一般ユーザー・管理者ユーザーどちらの場合でも、ゲームセレクト画面には表示しない。

### 3. 開発データ削除後のレイアウト調整

「開発データ」を削除した分、ゲームセレクト画面のパズルカード一覧を上に寄せる。

現在、開発データ表示があるため、パズル一覧の開始位置が下がっている。  
開発データ削除後は、余白が残らないように調整する。

### 4. 管理者専用ページは別チケットに分離する

このチケットでは管理者専用ページは作らない。

ただし、後続チケットで以下を実装できるように、必要ならコメントやREADMEに方針だけ残す。

```text
管理者専用ページ
管理者のみアクセス可
ユーザー一覧確認
ユーザーデータ確認
ユーザーデータ修正
ランキング修正
デバッグ操作
JSON出力
クリア状況リセット
```

## UI仕様

- 既存テーマを壊さない
- 不要項目を単に隠すだけでなく、余白が残らないようにする
- ゲームセレクト画面ではパズルカード一覧を上に寄せる
- スマホ幅でも崩れない
- ユーザーデータ画面の見た目を一般ユーザー向けに整理する
- 管理者向けの操作ボタンはこの画面には表示しない

## 受け入れ条件

- ユーザーデータ画面に `権限` が表示されない
- ユーザーデータ画面に `ユーザーID` が表示されない
- ユーザーデータ画面に `ログイン種別` が表示されない
- ユーザーデータ画面に `保存方式` が表示されない
- ユーザーデータ画面に `保存キー` が表示されない
- ユーザーデータ画面に `最終結果` が表示されない
- ゲームセレクト画面に `開発データ` が表示されない
- ゲームセレクト画面に `ユーザーデータJSON出力` が表示されない
- ゲームセレクト画面に `現在ユーザーJSON出力` が表示されない
- ゲームセレクト画面に `クリア状況リセット` が表示されない
- ゲームセレクト画面に `ユーザーデータ削除` が表示されない
- 開発データ削除後、パズルカード一覧が上に寄っている
- 一般ユーザー・管理者ユーザーのどちらでも、通常画面上には開発データが表示されない
- プレイ数・クリア数・難易度別データなど、ユーザー向け情報は引き続き表示される
- 既存のログイン・ランキング・ユーザーデータ読み込み処理が壊れていない
- `node --check` が通る
- ビルド番号を +1 する
