# チケット102：Vercel公開後のSupabase設定と本番確認手順整備

## 背景

WebピクロスはGitHub連携でVercelにデプロイ済み。

Vercel上でタイトル画面の表示は確認できた。

今後、Supabase連携、メール確認、パスワード再設定、管理者ログイン、ランキング保存などを本番URLで確認する必要がある。

ただし、確認手順が開発者視点で省略されると、テスターがどこを見ればOKか分かりにくい。

## 目的

Vercel公開後に必要なSupabase設定と、本番URLでの確認手順をREADMEまたはdocsへ整理する。

テスターが初見でも追えるように、誰が、どの画面で、どのボタンを押し、どのDB列を見て、何ならOK/NGかを明記する。

## 対象ファイル

推定対象:

```text
README.md
docs/vercel_supabase_production_checklist.md
docs/ticket_status.json
```

必要に応じて:

```text
docs/supabase/README.md
```

## 実装内容

### 1. Vercel URLを記録する

READMEまたはdocsに、現在利用するVercel URLを記載する。

例:

```text
https://web-picross.vercel.app/
https://web-picross-f7uyvvoxs-qtaro-devs-projects.vercel.app/
```

本番URLとPreview URLの違いがある場合は、どちらを確認対象にするか明記する。

### 2. Supabase Redirect URLs設定手順を記載する

Supabase Dashboardで、以下の場所へ進む手順を書く。

```text
Supabase Dashboard
→ Authentication
→ URL Configuration
→ Redirect URLs
```

追加するURL例:

```text
https://web-picross.vercel.app/
https://web-picross-f7uyvvoxs-qtaro-devs-projects.vercel.app/
http://127.0.0.1:8000/
```

ローカル確認も続ける場合はローカルURLも残す。

### 3. メール確認テスト手順を書く

新規ユーザー登録後、確認メールが届き、確認後にログインできるかを確認する手順を書く。

テスト手順例:

```text
1. テスターがVercel版Webピクロスを開く
2. ログイン画面で新規ユーザー名、メールアドレス、パスワードを入力する
3. 「ユーザー登録」を押す
4. 画面に確認メール案内が出ることを確認する
5. 入力したメールアドレスの受信箱を開く
6. Supabaseからの確認メールを開く
7. 確認リンクを押す
8. Vercel版Webピクロスへ戻ることを確認する
9. 同じユーザーでログインする
10. メニュー画面へ入れればOK
```

OK条件:

```text
確認メールが届く
確認リンクがVercel URLへ戻る
確認後にログインできる
```

NG条件:

```text
確認メールが届かない
確認リンクがlocalhostへ戻る
確認後もメール未確認扱いになる
```

### 4. パスワード再設定テスト手順を書く

パスワードを忘れた場合の再設定メール送信から、新パスワード設定完了までの確認手順を書く。

テスト手順例:

```text
1. テスターがVercel版Webピクロスを開く
2. ログイン画面のメールアドレス欄に登録済みメールを入力する
3. 「パスワードを忘れた場合」を押す
4. 画面に再設定メール送信案内が出ることを確認する
5. メール受信箱を開く
6. Supabaseからのパスワードリセットメールを開く
7. リセットリンクを押す
8. Vercel版Webピクロスで新パスワード設定画面が出ることを確認する
9. 新しいパスワードを入力する
10. 更新後、ログイン画面へ戻ることを確認する
11. 新しいパスワードでログインする
12. メニュー画面へ入れればOK
```

OK条件:

```text
再設定メールが届く
リンク先がVercel版になる
新パスワード設定画面が出る
新パスワードでログインできる
```

NG条件:

```text
リンク先がlocalhostになる
新パスワード設定画面が出ない
更新後に旧パスワードでログインできる
```

### 5. 管理者ログイン確認手順を書く

AdminQtaroでログインし、管理者ページへ入れることを確認する。

手順例:

```text
1. テスターがVercel版Webピクロスを開く
2. AdminQtaroでログインする
3. メニュー画面へ進む
4. 画面上にADMIN表示が出るか確認する
5. 管理者ページボタンを押す
6. 管理者ページが表示されればOK
```

OK条件:

```text
管理者ページへ入れる
ユーザー一覧が表示される
管理者専用ボタンが表示される
```

NG条件:

```text
管理者なのに管理者ページへ入れない
一般ユーザーで管理者ページへ入れる
```

### 6. ランキング保存確認手順を書く

一般ユーザーでゲームをクリアし、ランキングへ反映されるか確認する。

手順例:

```text
1. テスターが一般ユーザーでログインする
2. メニュー画面でゲームセレクトを押す
3. 任意のパズルを選ぶ
4. パズルをクリアする
5. ランキング画面を開く
6. クリアしたユーザー名と記録が表示されればOK
7. Supabaseの ranking_records テーブルを開く
8. 対象ユーザーの記録が追加されていればOK
```

OK条件:

```text
ランキング画面に記録が出る
Supabaseのranking_recordsに記録がある
```

NG条件:

```text
ゲーム上はクリアしたがランキングに出ない
ranking_recordsに保存されない
```

### 7. パスワードクリア確認手順を書く

チケット97の機能を本番URLで確認する手順を書く。

手順例:

```text
1. 管理者アカウントでログインする
2. 管理者ページを開く
3. 対象ユーザーの詳細を開く
4. 「パスワードクリア」ボタンを押す
5. 確認モーダルで対象ユーザー名とメールアドレスが合っていることを確認する
6. 実行する
7. Supabaseのprofilesテーブルを開く
8. 対象ユーザーのpassword_clear_requiredがtrueならOK
9. 対象ユーザーでログインする
10. 新パスワード設定画面が出ればOK
11. 新パスワードを設定する
12. Supabaseのprofilesテーブルを再確認する
13. 対象ユーザーのpassword_clear_requiredがfalseならOK
```

NG条件:

```text
password_clear_required がtrueにならない
trueなのに通常メニューへ入れる
新パスワード設定後もfalseに戻らない
```

### 8. 確認結果を書ける欄を用意する

docsにチェックリスト形式で、確認結果を書き込める欄を用意する。

例:

```text
[ ] Vercelタイトル画面表示
[ ] ログイン成功
[ ] 新規登録メール確認
[ ] パスワード再設定
[ ] 管理者ページ表示
[ ] ランキング保存
[ ] パスワードクリア
```

## 受け入れ条件

```text
READMEまたはdocsにVercel公開後の確認手順がある
Supabase Redirect URLsの設定場所が書かれている
各確認手順に、誰が、どの画面で、何を押すかが書かれている
OK条件とNG条件が書かれている
```

## NG条件

```text
「確認する」だけで具体的な操作が書かれていない
DBのどのテーブル・列を見るかが書かれていない
一般ユーザー確認と管理者確認が混ざっている
```

## メモ

このチケットは実装機能の追加ではなく、公開後の運用・確認手順整備を目的とする。

今後のテスト説明は、開発者ではなくテスターが初見で追える粒度にする。
