# チケット75: 管理者専用ユーザーデータ編集機能

## 目的

管理者専用ページから、ユーザー情報・進行状況・プレイ履歴を確認し、必要な範囲で編集できるようにする。

Supabase Table Editorを直接操作しなくても、アプリ上の分かりやすいUIでユーザーデータを管理できるようにする。

## 背景

ユーザー管理や進行状況の修正を毎回Supabase Dashboard上で行うのは手間がかかる。

また、DBを直接編集すると誤操作のリスクもあるため、管理者専用ページ上に必要な操作だけを整理して表示する。

## 前提

- チケット74で管理者専用ページが追加済みであること
- 管理者判定は `profiles.role = admin` を使う
- service role key はフロントへ絶対に出さない
- フロントから可能な範囲はSupabase RLSに従って操作する
- RLS上できない操作は無理に実装せず、管理者用APIやEdge Functionを後続で検討する

## 実装内容

### 1. ユーザー一覧表示

管理者ページにユーザー一覧を追加する。

表示項目:

```text
ユーザー名
表示名
メールアドレス
権限
登録日時
最終更新日時
ユーザーID
```

UI仕様:

```text
検索欄
ユーザー名検索
メールアドレス検索
権限フィルター
更新ボタン
```

### 2. ユーザー詳細表示

ユーザー一覧からユーザーを選択すると、詳細情報を表示する。

表示項目:

```text
profiles情報
user_progress集計
play_history最新履歴
ranking_records件数
```

### 3. ユーザー情報編集

管理者が編集できる項目を限定する。

編集候補:

```text
表示名
権限
```

注意:

```text
メールアドレス変更はSupabase Auth側の扱いがあるため、このチケットでは原則編集しない
Authユーザー削除はservice roleが必要になる可能性が高いため、このチケットでは実装しない
```

### 4. 進行状況編集

対象ユーザーの `user_progress` を確認・編集できるようにする。

編集候補:

```text
cleared
best_clear_time_ms
latest_clear_time_ms
clear_count
fail_count
giveup_count
hint_used_count
last_played_at
cleared_at
```

危険操作なので、保存前に確認ダイアログを出す。

表示例:

```text
このユーザーの進行状況を変更します。よろしいですか？
```

### 5. プレイ履歴確認

対象ユーザーの `play_history` を一覧表示する。

表示項目:

```text
難易度
ステージ番号
結果
クリア時間
ヒント使用回数
プレイ日時
```

このチケットでは、履歴の削除や改変は原則行わない。  
必要なら後続チケットで実装する。

### 6. 誤操作防止

- 変更前後の値を表示する
- 保存前に確認ダイアログを出す
- 危険操作は赤系ボタンにする
- 一般ユーザーは絶対に表示・操作できない
- 管理者自身の権限変更は特に注意する
- 最後の管理者を `user` に戻せないようにするか、警告を出す

## UI仕様

- ユーザー検索 → 詳細 → 編集 → 保存の流れが分かりやすいこと
- DBカラム名をそのまま並べすぎず、日本語ラベルを付ける
- 必要であれば内部IDは折りたたみ表示にする
- 変更ボタン・保存ボタン・キャンセルボタンを明確に分ける
- 既存テーマに合わせる
- スマホ幅でも最低限操作できる

## 受け入れ条件

- 管理者のみユーザー管理画面を開ける
- 一般ユーザーはユーザー管理画面を開けない
- ユーザー一覧が表示される
- ユーザー検索ができる
- ユーザー詳細が表示される
- 表示名を編集できる
- 権限を編集できる
- 進行状況を確認できる
- 進行状況を編集できる
- 編集保存前に確認ダイアログが出る
- プレイ履歴を確認できる
- service role key をフロントに出していない
- RLS上できない操作は無理に実装せず、未対応として表示する
- 既存の通常ユーザー画面が壊れていない
- `node --check` が通る
- ビルド番号を +1 する
