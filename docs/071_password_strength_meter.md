# チケット71: パスワード強度メーターと弱いパスワード警告の追加

## 目的

ユーザー登録・パスワード変更時に、入力されたパスワードの強度を画面上で分かりやすく表示する。

ただし、開発中・個人利用・カジュアル利用の邪魔にならないよう、弱いパスワードでも原則として登録や変更を完全ブロックしない。  
まずは「警告・おすすめ表示」に留める。

## 背景

Chrome / Google パスワードマネージャーから、弱いパスワードや漏洩済みの可能性があるパスワードに対して警告が出ることがある。

Webピクロス側でも、ユーザー登録・パスワード変更時に最低限の強度表示を行うことで、ユーザーに安全なパスワードを促す。

ただし、厳しすぎるルールにするとログインやテストが面倒になり、本末転倒になるため、強制ではなく案内を基本とする。

## 実装内容

- ユーザー登録画面のパスワード入力欄に強度メーターを追加する
- ユーザーデータ画面のパスワード変更欄にも強度メーターを追加する
- パスワード入力中にリアルタイムで強度を表示する
- 表示段階は最低限以下とする

```text
弱い
普通
強い
```

- 可能であれば以下のような補足メッセージを表示する

```text
このパスワードは推測されやすい可能性があります
12文字以上のパスワードをおすすめします
英数字や記号を組み合わせるとより安全です
```

- 弱いパスワードでも、原則として登録・変更を完全ブロックしない
- ただし、明らかに短すぎるものはSupabase Auth側の制限に従う
- 既存のSupabase Auth登録・ログイン・パスワード変更処理を壊さない
- Supabase未設定時のローカルログイン導線を壊さない

## 強度判定ルール

まずは自前の軽量判定でよい。

最低限、以下を判定する。

```text
8文字未満 → 弱い
12文字以上 → 加点
英字を含む → 加点
数字を含む → 加点
記号を含む → 加点
同じ文字の連続 → 減点
連番・単純語句 → 減点
ユーザー名やメールアドレスの一部を含む → 減点
```

弱いパスワード例:

```text
password
pass1234
test1234
12345678
qwerty
11111111
```

## UI仕様

- パスワード欄の下に小さく表示する
- メーターは横棒またはテキスト表示でよい
- 既存テーマを壊さない
- ダークテーマ上で見づらくならないようにする
- 派手すぎる警告表示にしない
- スマホ幅でも崩れないようにする

表示例:

```text
パスワード強度: 弱い
このパスワードは推測されやすい可能性があります
```

```text
パスワード強度: 普通
12文字以上にするとより安全です
```

```text
パスワード強度: 強い
安全性の高いパスワードです
```

## ライブラリ利用について

今回はまず自前の軽量判定で実装する。

将来的に精度を上げる場合は、`zxcvbn` 系のパスワード強度推定ライブラリ導入を別チケットで検討する。

今回のチケットでは、既存ライブラリ構成を大きく変えないことを優先する。

## 受け入れ条件

- ユーザー登録画面でパスワード強度が表示される
- パスワード変更画面でパスワード強度が表示される
- 入力中に強度表示が更新される
- 弱いパスワードでも原則として登録・変更を完全ブロックしない
- 明らかに弱いパスワードには警告が表示される
- 12文字以上かつ英数字・記号を含む場合は強い表示になる
- ユーザー名やメールアドレスを含むパスワードは弱めに判定される
- 既存のログイン・登録・パスワード変更処理が壊れていない
- Supabase未設定時のローカル導線が壊れていない
- 既存テーマ・レイアウトが崩れていない
- `node --check` が通る
- ビルド番号を +1 する
