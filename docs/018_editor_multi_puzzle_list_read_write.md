# チケット18: エディタのリスト領域拡張と複数パズルデータの読み書き対応

## 目的

エディタモード左側のリスト部を現在より長めに確保し、読み込んだパズルデータ一覧を扱いやすくする。

また、1つのJSONデータ内に複数のパズルデータを格納できるようにし、一覧から1問ずつ読み込み・書き込みできるボタンを設置する。

現在の「一時保存」は、あくまでブラウザ内の作業用一時保存データとして扱う。  
JSONファイルから読み込んだ複数問データとは役割を分け、UI上でも混同しないようにする。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 実装内容

### 1. 左カラムのリスト部を長めに取る

エディタ画面左側のリスト表示領域を、現在より縦方向に長く確保する。

対象候補:

```text
- 読み込み済みパズル一覧
- 一時保存一覧
```

期待動作:

```text
- 複数件のパズルが見やすく表示される
- 一覧が短すぎてすぐスクロールになる状態を改善する
- 中央盤面や上部操作UIに被らない
```

### 2. 1つのJSON内に複数パズルを格納する形式へ対応する

読み込み・書き出し対象のJSONは、複数問を持つ配列形式に対応する。

基本形:

```json
[
  {
    "id": "beginner_mono_id00000001",
    "stageNo": 1,
    "title": "クロス",
    "difficulty": "beginner",
    "mode": "mono",
    "colorMode": "mono",
    "w": 5,
    "h": 5,
    "grid": []
  },
  {
    "id": "beginner_mono_id00000002",
    "stageNo": 2,
    "title": "ちいさいクロス",
    "difficulty": "beginner",
    "mode": "mono",
    "colorMode": "mono",
    "w": 5,
    "h": 5,
    "grid": []
  }
]
```

注意:

- 既存の配列形式を優先する
- 単体オブジェクト形式が読み込まれた場合は、配列1件として扱う
- チケット12の正規化処理を活用する
- 既存の `data/*.json` 形式を壊さない

### 3. 読み込んだJSON内のパズル一覧を左カラムに表示する

JSONファイルを読み込んだら、そのJSONに含まれるパズル一覧を左カラムに表示する。

表示項目候補:

```text
- #stageNo
- title / name
- difficulty
- mode / colorMode
- w x h
```

表示例:

```text
読み込み済みパズル

#1 クロス
ビギナー / モノクロ / 5x5

#2 ちいさいクロス
ビギナー / モノクロ / 5x5
```

注意:

- 選択中のパズルが分かるようにする
- 一覧が空の場合は「JSON未読込」または「パズルなし」と表示する
- stageNo がない場合は配列順や id から安全に表示する

### 4. 「1問読込」ボタンを追加する

左カラムの一覧で選択した1問を、中央のエディタ盤面へ読み込むボタンを追加する。

ボタン名候補:

```text
読込
1問読込
選択読込
```

期待動作:

```text
左カラムでパズルを選択
→ 読込ボタン
→ 中央盤面にそのパズルを反映
```

反映対象:

```text
- パズル名
- 難易度
- 面数 / stageNo
- 盤面サイズ
- モノクロ / カラー
- grid / grid_strings / cells / solution
- 選択色やパレット状態
```

### 5. 「1問書込」ボタンを追加する

中央のエディタ盤面の現在内容を、左カラムで選択中の1問へ書き戻すボタンを追加する。

ボタン名候補:

```text
書込
1問書込
選択へ書込
```

期待動作:

```text
中央盤面を編集
→ 左カラムで対象パズルを選択
→ 書込ボタン
→ JSON内の該当パズルデータを更新
```

書き込む項目:

```text
- id
- stageNo
- title / name
- difficulty
- mode / colorMode
- w / h
- grid
- grid_strings
- updatedAt
```

注意:

- stageNo はUI上の面数と同期する
- id がない場合は安全に生成する
- 既存idがある場合は不用意に変えない
- 書込後、左カラムの表示も更新する
- 書込はメモリ上の読み込み済みJSONデータに対して行う
- 書込しただけではファイルへ自動保存されないことをUI上で分かるようにする

### 6. 新規追加ボタンを用意する

可能であれば、現在のエディタ盤面を新しい1問として、読み込み済みJSON配列へ追加できるようにする。

ボタン名候補:

```text
新規追加
現在の盤面を追加
```

最小実装では、この機能は後回しでもよい。  
後回しにする場合は未対応事項として報告する。

### 7. JSONダウンロードは複数問データ全体を書き出す

JSONダウンロードボタンは、読み込み済みパズル一覧の全体を出力できるようにする。

期待動作:

```text
複数問JSONを読み込み
→ #2を書込
→ JSONダウンロード
→ #1〜#nを含むJSONファイルとして保存
```

注意:

- 現在編集中の1問だけを書き出すボタンが必要な場合は、別名にする
- 「全体JSONダウンロード」と「現在の1問だけ出力」の役割を混同しない
- 既存のJSONダウンロード機能を壊さず、名称や動作を整理する

### 8. 一時保存データとの役割を明確にする

「一時保存」はブラウザ内localStorageなどに保存された作業用データとして扱う。

整理方針:

```text
読み込み済みパズル:
- JSONファイルから読み込んだ複数問データ
- 1問読込 / 1問書込 / JSONダウンロードの対象

一時保存:
- ブラウザ内localStorageなどに保存された作業用データ
- 一時保存読込 / 一時保存削除の対象
```

UI上も、見出しやボタン名で区別する。

### 9. 正しく読み書きできるように検証する

以下を必ず確認する。

```text
- 複数問JSONを読み込める
- #1を中央盤面に読み込める
- #2を中央盤面に読み込める
- #2を編集して書込できる
- 書込後、JSONダウンロードできる
- ダウンロードしたJSONを再読込できる
- 再読込後、編集内容が残っている
```
