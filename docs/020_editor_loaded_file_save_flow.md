# チケット20: エディタの読込ファイル操作とパズルデータ保存方法の整理

## 目的

エディットモードで、現在読み込んでいるパズルデータファイルに対して、分かりやすく読み込み・保存できるUIを整備する。

現在は、ファイル選択・JSON読込・JSON全体ダウンロード・スロット管理が画面内に分散しているため、以下のように整理する。

```text
左カラム上部:
- ファイル選択
- JSON読込

左カラム:
- 読み込み済みJSONスロット一覧

中央または上部:
- 現在選択中スロットの面数設定
- パズル名
- 難易度
- モード
- 盤面サイズ

保存:
- 読み込んでいるパズルデータへ上書き保存する操作
- 別名のエディットパズルデータファイルとして出力する操作
```

Webブラウザ上では、元ファイルへ直接上書き保存できない場合があるため、その制約も踏まえて、ユーザーに分かりやすい保存方法へ整理する。

## 実装内容

### 1. ファイル選択・JSON読込を読込スロット上部へ移動する

エディタ左カラムの「読み込み済みJSONスロット」上部に、ファイル選択とJSON読込ボタンを設置する。

期待配置:

```text
左カラム上部:
[ファイルを選択]
[JSON読込]

読み込み済みJSONスロット
#1 ...
#2 ...
#3 ...
```

注意:

- 現在中央付近にあるファイル選択・JSON読込UIは、左カラム側へ整理する
- 既存のJSON読込機能は壊さない
- ファイル未選択時は、分かりやすいメッセージを表示する

### 2. 読み込んでいるファイル名を表示する

JSONを読み込んだら、現在読み込んでいるファイル名を表示する。

表示例:

```text
読込中: beginner.json
```

注意:

- ブラウザの仕様上、フルパスは取得できない前提でよい
- ファイル名だけ表示できればよい
- 未読込時は `未読込` と表示する

### 3. 面数設定場所をスロットの横に並べる

現在の面数入力欄を、スロット選択・スロット番号と関連が分かる位置へ移動または追加する。

期待配置例:

```text
選択スロット: #2
面数: [ 2 ]
```

または、各スロット表示内に面数が分かるようにする。

```text
#2 / 面数 2 / やじるし
```

注意:

- 面数は `stageNo` と同期する
- スロット番号と面数が矛盾しないようにする
- 既存スロットを選択したら、面数入力欄もその値へ更新する
- 面数を変更した場合、保存時にどのスロットへ反映するか明確にする

### 4. 読み込み済みパズルデータへの上書き保存を整理する

現在読み込んでいるJSONデータに対して、選択中スロットの編集内容を書き込む操作を明確にする。

候補ボタン:

```text
スロットへ保存
読み込み中データへ反映
```

期待動作:

```text
中央エディタ盤面を編集
→ 選択中スロットを確認
→ スロットへ保存
→ 読み込み済みJSONデータ上の該当スロットを更新
```

注意:

- ブラウザ上では元ファイルへ直接上書きできない場合がある
- 「読み込み済みデータへ反映」と「PC上のファイルへ保存」は別であることをUI上で分かるようにする
- スロットへ保存後、JSONファイルとして出力しない限り、PC上の元ファイルは更新されないことを表示する

### 5. 上書き保存相当のJSON出力を実装する

読み込んでいるファイル名と同じ名前でJSONをダウンロードできるようにする。

候補ボタン:

```text
読込ファイル名で保存
上書き用JSON出力
```

期待動作:

```text
beginner.json を読み込む
→ スロットを編集・保存
→ 読込ファイル名で保存
→ beginner.json としてダウンロード
→ ユーザーが既存ファイルへ上書き保存できる
```

注意:

- ブラウザが自動で元ファイルを直接上書きできるとは限らない
- そのため「上書き用JSON出力」という扱いにしてよい
- ファイル名は読み込んだ元ファイル名を使う
- ファイル未読込の場合は安全な初期ファイル名を使う

### 6. 別名のエディットパズルデータファイルとして出力する

読み込んでいるデータまたは現在のスロット群を、別名のエディットパズルデータファイルとして出力するボタンを追加する。

候補ボタン:

```text
別名でJSON出力
エディットデータ出力
```

ファイル名候補:

```text
edit_puzzles.json
edit_puzzles_YYYYMMDD_HHMMSS.json
```

期待動作:

```text
スロットデータを編集
→ 別名でJSON出力
→ edit_puzzles_YYYYMMDD_HHMMSS.json として保存
```

注意:

- 既存ファイル名での保存と別名保存の違いが分かる表示にする
- ファイル名入力欄が既にある場合は、それを利用してよい
- 既存のJSON全体ダウンロード機能と役割が重複する場合は、名称を整理する

### 7. 保存方法の説明文を画面に出す

Webアプリでは、ローカルファイルへの直接上書きができない/制限される場合があるため、短い説明文を表示する。

表示例:

```text
スロット保存は画面内データへの反映です。
PC上のJSONファイルを更新するには、JSON出力したファイルを保存してください。
```

注意:

- 長すぎる説明文は避ける
- ユーザーが「保存したのにファイルが変わっていない」と誤解しないようにする

### 8. JSON出力内容は最大100スロット管理と整合させる

チケット19で実装した最大100スロット管理と整合するように、JSON出力は読み込み済みスロット全体を対象にする。

期待動作:

```text
#1, #2, #5 にデータがある
→ JSON出力には stageNo 1, 2, 5 のデータが含まれる
```

注意:

- 空スロットは原則として出力しない
- stageNo順に並べて出力する
- サムネイルは原則としてgridから再生成できるため、base64画像をJSONへ保存しない
- 既存データのidは維持する
- 新規スロットには安全なidを生成する

### 9. 既存の一時保存機能と混同しない

このチケットの保存は「読み込み済みJSONデータへの反映」と「JSONファイル出力」を対象とする。

一時保存は引き続き、ブラウザ内作業データとして扱う。

```text
一時保存:
- localStorage等
- 作業中のバックアップ
- JSONファイルとは別管理

スロット保存:
- 読み込み済みJSONスロットへの反映
- JSON出力対象
```

### 10. 既存機能を壊さない

以下を維持する。

```text
- エディタ盤面編集
- 最大100スロット管理
- スロット読込
- スロット保存
- サムネイル表示
- モノクロ / カラー切り替え
- 16色パレット
- 一時保存
- 一時保存読込
- 一時保存削除
- エディットプレイ
- 通常ゲームセレクト
- 通常プレイ
```
