# チケット106fix3：旧パスワード再設定メール送信ボタンの削除

## 背景

チケット106fix1 / 106fix2により、管理者によるパスワード再設定はサーバーAPI経由の「管理者再設定メール送信」導線に整理された。

現在の管理者ページには、以下の2つのボタンが並んでいる。

- パスワード再設定メール送信
- 管理者再設定メール送信

このうち「管理者再設定メール送信」は、実際に確認済みの正しい導線であり、以下の仕様に対応している。

- `/api/admin-reset-auth-user` 経由
- `APP_BASE_URL` を使った本番URLへの `redirectTo`
- 同一ユーザーへの1時間5回制限
- `password_reset_request_logs` への送信ログ保存
- ログイン後の追加パスワード変更画面を出さない

一方、「パスワード再設定メール送信」ボタンは、テスト時に送信失敗し、現在の仕様上も役割が重複しているため不要。

## 目的

管理者ページのパスワード再設定メール送信導線を1つに統一し、管理者が迷わず正しいサーバーAPI経由の導線だけを使えるようにする。

## 対象ファイル（推定）

- `js/admin.js`
- `js/actions.js`
- `js/render.js`
- `styles.css`
- `README.md`
- `docs/vercel_supabase_production_checklist.md`
- `docs/ticket_status.json`
- 必要に応じて関連する管理者UI / モーダル生成処理ファイル

## 実装内容

### 1. 旧ボタンの削除

管理者ページのユーザー詳細エリアから、旧導線と思われる以下のボタンを削除する。

```text
パスワード再設定メール送信
```

削除対象は、表示ボタンだけでなく、以下も含める。

- 旧ボタン用のDOM生成処理
- 旧ボタン用のイベントハンドラ
- 旧ボタン用の確認モーダル
- 旧ボタン用の送信処理
- Supabaseクライアントから直接パスワード再設定メールを送る旧処理が残っている場合は削除

### 2. 残す導線

以下の導線だけを残す。

```text
管理者再設定メール送信
```

このボタンは、既存の正しいサーバーAPI経由の処理を使うこと。

```text
/api/admin-reset-auth-user
```

この導線では、既存の106fix1 / 106fix2仕様を維持する。

- 送信前に確認モーダルを表示する
- 対象ユーザー名、表示名、メールアドレス、ユーザーIDを確認できる
- メール送信成功時のみ送信回数・送信日時・送信ログを更新する
- `password_clear_required = true` を新規設定しない
- ログイン後に追加のパスワード変更画面を出さない
- 1時間5回制限を維持する

### 3. 表示文言の整理

管理者ページ内のボタン文言は、以下のどちらかに統一する。

推奨：

```text
パスワード再設定メールを送信
```

ただし、既存実装上「管理者再設定メール送信」のままの方が差分が少ない場合は、そのままでも可。

重要なのは、管理者ページ内でパスワード再設定メール送信系のボタンが2つ表示されないこと。

### 4. 失敗する旧モーダルの削除

テスト時に以下のような失敗メッセージが表示された旧導線は削除する。

```text
パスワード再設定メールの送信に失敗しました。
時間をおいて再度お試しください。
```

ただし、正しいサーバーAPI経由の導線でエラーが発生した場合のエラー表示は残すこと。

### 5. ドキュメント更新

README、本番チェックリスト、チケット管理JSONに、106fix3として以下を反映する。

- 管理者ページの再設定メール送信ボタンは1つに統一
- 旧パスワード再設定メール送信ボタンは削除
- 使用する導線はサーバーAPI経由のみ
- Build番号を更新する

## 受け入れ条件（目視確認基準）

### 管理者ページ表示

1. `AdminQtaro` でログインする
2. 管理者ページを開く
3. 任意のユーザーを選択する
4. ユーザー詳細エリアを見る

OK：

```text
パスワード再設定メール送信系のボタンが1つだけ表示される
```

NG：

```text
「パスワード再設定メール送信」と「管理者再設定メール送信」が両方表示される
```

### 再設定メール送信

1. 残っている再設定メール送信ボタンを押す
2. 確認モーダルを確認する
3. 実行する

OK：

```text
確認モーダルが表示される
対象ユーザーのメールアドレスが確認できる
送信成功メッセージが表示される
Gmailに再設定メールが届く
```

NG：

```text
旧導線の失敗モーダルが出る
どちらのボタンを押すべきか分からない
メールが送信されない
```

### 再設定後ログイン

1. 新しく届いたメールのリンクを開く
2. 新しいパスワードを設定する
3. ログイン画面へ戻る
4. 対象ユーザーでログインする

OK：

```text
通常メニューへ進む
追加のパスワード変更画面は表示されない
```

NG：

```text
ログイン後に再度「新しいパスワードの設定」画面が表示される
```

### 回数制限

同一ユーザーに対して短時間で複数回送信する。

OK：

```text
1時間5回制限が維持される
6回目以降は適切なエラーになる
```

NG：

```text
旧ボタン経由で制限を回避できる
旧ボタン経由で送信ログが残らない
```

## 備考

このチケットでは、再設定メール本文やSupabase URL Configurationの再調整は行わない。

それらは106fix1 / 106fix2の範囲で対応済みとし、本チケットでは管理者ページ上の重複ボタン削除と導線統一に集中する。
