# チケット72: ユーザー名・メールアドレス・パスワードの入力制限とエラー表示改善

## 目的

ユーザー登録・ログイン・パスワード変更で使用する入力欄に、明確な文字数制限・入力ルール・分かりやすいエラー表示を追加する。

入力値のルールを画面側とJS側の両方で統一し、不正な値が保存・送信されないようにする。

## 背景

現在、ユーザー名・メールアドレス・パスワードの入力ルールが明確ではない。

今後Supabase Auth / profiles / user_progress / ranking_recordsなどにユーザー情報を連携していくため、以下のようなルールをアプリ側で明示する必要がある。

```text
ユーザー名は日本語OKなのか
ユーザー名の最大文字数はいくつか
メールアドレス欄は最大何文字か
パスワードは何文字以上・何文字以下か
エラー時に何が悪いのか分かるか
```

## 対象ファイル（推定）

```text
js/render.js
js/actions.js
js/supabaseAuth.js
js/config.js
styles.css
README.md
```

## 入力制限ルール

### ユーザー名

```text
最小: 1文字
最大: 10文字
日本語: 許可
英数字: 許可
記号: _ と - のみ許可
空白のみ: 禁止
前後の空白: trimする
```

許可例:

```text
testuser
えり
えりちゃん
user_01
user-01
```

禁止例:

```text
空文字
空白だけ
11文字以上
user name
user@example
user!
```

### メールアドレス

```text
最大: 50文字
形式: メールアドレス形式のみ許可
前後の空白: trimする
```

禁止例:

```text
空文字
50文字超過
test
test@
@test.com
```

### パスワード

```text
最小: 8文字
最大: 72文字
前後の空白: 原則として禁止または警告
日本語など全角文字: いったん許可しない方針
```

禁止例:

```text
7文字以下
73文字以上
空白だけ
前後に空白がある値
```

補足:

- パスワード強度メーターは別チケットで実装する
- このチケットでは、最低文字数・最大文字数・不正文字の制限を担当する
- 弱いパスワードを完全ブロックするかどうかは、強度メーターチケット側の方針に従う

## 実装内容

- ユーザー登録画面の入力欄に `maxlength` などのHTML属性を追加する
- ユーザーデータ画面のパスワード変更欄にも `maxlength` などのHTML属性を追加する
- HTML属性だけに頼らず、JS側でも同じルールで検証する
- 登録処理前に入力値を検証する
- ログイン処理前に入力値を検証する
- パスワード変更処理前に入力値を検証する
- エラーは英語ではなく日本語で表示する
- 何が悪いのか分かる具体的な文言にする
- エラー表示は目立つようにする
  - 赤字
  - 太字
  - 既存テーマに合う警告枠
- 複数エラーがある場合は、可能であればまとめて表示する
- エラー解消後はエラー表示を消す、または更新する
- 既存のSupabase Auth登録・ログイン・パスワード変更処理を壊さない
- Supabase未設定時のローカルログイン導線を壊さない
- ビルド番号を +1 する

## エラー表示仕様

エラーは分かりやすく、ユーザーが次に何を直せばよいか分かる文言にする。

表示例:

```text
ユーザー名は1〜10文字で入力してください
ユーザー名に使える記号は _ と - のみです
メールアドレスは50文字以内で入力してください
メールアドレスの形式が正しくありません
パスワードは8〜72文字で入力してください
パスワードの前後に空白は使えません
```

見た目:

```text
赤字
太字
小さすぎない文字サイズ
入力フォーム付近に表示
```

可能であれば、対象欄の近くに表示する。  
難しい場合は、フォーム下部のメッセージエリアにまとめて表示してよい。

## UI仕様

- 既存テーマを壊さない
- ダークテーマ上でエラーが見やすい
- スマホ幅でも崩れない
- 警告色は強すぎず、ただし見落とさない
- 入力欄の近くに補足ルールを表示してもよい

補足表示例:

```text
ユーザー名: 10文字まで / 日本語OK / 記号は _ - のみ
メールアドレス: 50文字まで
パスワード: 8〜72文字
```

## バリデーション関数

可能であれば、入力検証処理は共通関数化する。

例:

```text
validateUsername()
validateEmail()
validatePassword()
validateAuthForm()
```

同じルールを複数箇所にコピペしない。

## 受け入れ条件

- ユーザー名が空の場合、登録できず日本語エラーが出る
- ユーザー名が10文字を超える場合、登録できず日本語エラーが出る
- ユーザー名に許可外の記号がある場合、登録できず日本語エラーが出る
- 日本語ユーザー名で登録できる
- メールアドレスが50文字を超える場合、登録できず日本語エラーが出る
- メール形式が不正な場合、登録・ログイン前に日本語エラーが出る
- パスワードが8文字未満の場合、登録・変更できず日本語エラーが出る
- パスワードが72文字を超える場合、登録・変更できず日本語エラーが出る
- エラー表示が赤字・太字などで分かりやすい
- 入力を修正するとエラー表示が消える、または正しい内容に更新される
- HTMLの `maxlength` だけでなくJS側でも検証している
- 既存のログイン・登録・パスワード変更処理が壊れていない
- Supabase未設定時のローカル導線が壊れていない
- `node --check` が通る
- ビルド番号を +1 する
