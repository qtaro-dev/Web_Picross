# チケット28: ユーザー登録・ログイン画面追加とサーバ側ユーザーファイル保存

## 目的

タイトル画面の次に、ユーザー登録・ログイン画面を設置する。

ユーザー登録した情報は、サーバ側のユーザーファイルへ格納する。  
まずは固定ユーザーとして、以下のログイン情報を用意する。

```text
ユーザー名: admin
パスワード: admin
```

## 重要な前提

現在のWebピクロスは静的Webアプリ構成であり、HTML / CSS / JavaScriptのみで動作している。  
静的Webアプリのままでは、ブラウザからサーバ上のユーザーファイルへ直接書き込むことはできない。

そのため、このチケットでは以下のどちらかを選ぶ必要がある。

```text
A. ローカル開発用の簡易サーバAPIを追加する
B. まずはフロント側だけ仮実装し、サーバ保存は後続チケットに分離する
```

ユーザー要望は「サーバのユーザファイルに格納」なので、可能であればAを採用する。  
ただし、既存の静的Web版・Vercel公開用MVPを壊さないことを優先する。

## 実装内容

### 1. タイトル画面の次にログイン画面を追加する

現在の導線を以下へ変更する。

変更前:

```text
タイトル
→ メニュー
```

変更後:

```text
タイトル
→ ログイン / ユーザー登録
→ メニュー
```

注意:

- タイトル画面は維持する
- ログイン成功後にメニューへ遷移する

### 2. ログイン画面UIを作る

ログイン画面に以下を表示する。

```text
ユーザー名入力欄
パスワード入力欄
ログインボタン
ユーザー登録ボタン
メッセージ表示欄
```

既存テーマに合わせて、黒背景・白文字・枠線ボタンのデザインを維持する。

### 3. 固定ユーザー admin/admin を用意する

まずは固定ユーザーとして以下を用意する。

```text
ユーザー名: admin
パスワード: admin
```

期待動作:

```text
admin / admin でログイン
→ メニューへ遷移
```

注意:

- 開発用の固定ユーザーであることをコメントやREADMEに明記する
- 本番向けの安全な認証ではない
- 将来的にパスワードハッシュ化等を検討する

### 4. ユーザー登録機能を追加する

ログイン画面からユーザー登録できるようにする。

登録項目:

```text
ユーザー名
パスワード
```

入力チェック:

```text
- ユーザー名が空でない
- パスワードが空でない
- 同じユーザー名が既に存在しない
```

### 5. ユーザー情報をサーバ側ユーザーファイルに保存する

可能であれば、サーバ側にユーザーファイルを用意し、登録ユーザーを保存する。

ファイル候補:

```text
users.json
```

保存形式候補:

```json
[
  {
    "username": "admin",
    "password": "admin",
    "createdAt": "2026-05-17T00:00:00.000Z"
  }
]
```

注意:

- まずは開発用なので平文パスワードでもよいが、本番用途では危険であることをコメントに残す
- `users.json` を公開リポジトリに含める場合、個人情報を入れないこと
- Vercel等の静的ホスティングではファイル書き込みができない可能性があるため、その場合は後続でDBや外部ストレージを検討する

### 6. 簡易サーバAPIを追加する場合

静的ファイルだけではユーザーファイル保存ができないため、ローカル用の簡易サーバAPIを追加する場合は以下を用意する。

候補API:

```text
POST /api/register
POST /api/login
GET /api/session
POST /api/logout
```

最小必須:

```text
POST /api/register
POST /api/login
```

注意:

- 既存の `python -m http.server` 起動ではAPIは動かない
- サーバAPIを追加する場合はREADMEに起動方法を追記する
- Web版の静的公開とローカルサーバ版の差分を明記する

### 7. 静的版フォールバックを用意する

サーバAPIが使えない環境でも、最低限admin/adminでログインできるようにする。

フォールバック候補:

```text
- API通信失敗時は admin/admin のみログイン可能
- ユーザー登録は「サーバ未接続のため登録不可」と表示
```

注意:

- Vercel静的公開時に完全に壊れないようにする
- 将来DB連携に置き換えやすい構造にする

### 8. ログイン状態を管理する

ログイン成功後、ユーザー名をstateに保持する。

保持候補:

```text
state.currentUser
sessionStorage
```

期待動作:

```text
ログイン成功
→ currentUser = { username: "admin" }
→ メニューへ遷移
```

注意:

- ページ更新時の扱いはチケット27との整合を取る
- F5/更新でタイトルに戻る場合でも、ログイン状態を維持するか破棄するかを実装時に決めて報告する

### 9. 既存導線を壊さない

ログイン後は既存のメニュー以降の導線を維持する。

維持する導線:

```text
メニュー
→ ゲームセレクト
→ 問題選択
→ ゲーム画面

メニュー
→ エディタ
```

- タイトル画面を開ける

- `node --check js/main.js` が通る
