# チケット42: ユーザー登録後ログイン補助とログイン情報記録チェックボックス追加

## 目的

新規ユーザー登録後、そのユーザーでログインする手間を減らす。

登録直後に「登録したユーザーでログインするか」を確認し、選択に応じてログインフォームへ反映する。

また、ログイン画面に「ユーザー名とパスワードを記録する」チェックボックスを追加し、チェック状態と入力情報をユーザー側ブラウザに保存できるようにする。

- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\main.js`

## 現状

Node.jsサーバ起動後、以下のURLで確認している。

```text
http://127.0.0.1:8000/
```

新規ユーザー `01` を作成し、そのユーザーでログインできることは確認済み。

ただし、ユーザー登録後にそのままログインする導線が弱く、手動でユーザー名とパスワードを再入力する必要がある。

## 実装内容

### 1. ユーザー登録成功後に確認モーダルを出す

ユーザー登録成功後、既存テーマに合わせた画面内モーダルを表示する。

表示文言:

```text
登録しました。
登録したユーザでログインしますか？
```

ボタン:

```text
[はい] [いいえ]
```

注意:

- ブラウザ標準の `alert()` / `confirm()` は使わない
- 既存のモーダルUIがある場合はそれを使う
- 登録失敗時はこのモーダルを出さない

### 2. 「はい」を押した場合の挙動

「はい」を押した場合、登録したユーザー情報をログインフォームへ転記する。

期待動作:

```text
ユーザー登録成功
→ モーダル表示
→ はい
→ ログイン画面/ログインフォームへ戻る
→ ユーザー名欄に登録ユーザー名を入力済みにする
→ パスワード欄に登録パスワードを入力済みにする
→ ログインボタンを活性化する
→ ユーザーがログインボタンをクリックするとログインできる
```

注意:

- 自動でログインボタンを押してログインまではしない
- ユーザーがログインボタンを押す導線にする
- パスワード欄は通常通り伏せ字表示でよい

### 3. 「いいえ」を押した場合の挙動

「いいえ」を押した場合、ログインフォームの入力情報を空にする。

期待動作:

```text
ユーザー登録成功
→ モーダル表示
→ いいえ
→ ログインフォームのユーザー名を空にする
→ ログインフォームのパスワードを空にする
→ 登録時に一時保持していたユーザー名・パスワードを破棄する
```

ユーザー要望では「クリップボードをクリア」とあるが、ブラウザからOSクリップボードを無条件で消すのは環境依存・権限制約があるため、実装可能な範囲では以下を行う。

```text
- アプリ内部で保持している登録直後のユーザー名・パスワードを破棄
- ログインフォームを空にする
- 記録チェックがOFFなら保存済みログイン情報も削除する
```

### 4. ログインボタンの活性/非活性を整理する

ログインフォームの入力状態に応じて、ログインボタンを活性化する。

期待動作:

```text
ユーザー名あり + パスワードあり
→ ログインボタン活性

ユーザー名なし または パスワードなし
→ ログインボタン非活性
```

既存が常時押せる仕様の場合は、無理に非活性化しなくてもよいが、登録後「はい」でログイン可能状態になることは必須。

### 5. 「ユーザー名とパスワードを記録する」チェックボックスを追加する

ログインフォーム下部にチェックボックスを追加する。

表示文言:

```text
□ ユーザー名とパスワードを記録する
```

配置:

```text
ユーザー名入力欄
パスワード入力欄
[ログイン] [ユーザー登録]
□ ユーザー名とパスワードを記録する
```

### 6. チェック状態をブラウザに保存する

「ユーザー名とパスワードを記録する」のチェック状態を、ユーザー側ブラウザに保存する。

ユーザー要望では「クッキー」とあるため、Cookie保存を基本とする。

保存候補:

```text
Cookie:
picross_remember_login=true/false
picross_saved_username=<username>
picross_saved_password=<password>
```

ただし、実装しやすさや既存設計によっては localStorage でもよい。  
localStorageを使う場合は、画面またはREADMEに「ブラウザ保存」として明記する。

注意:

- 今回はローカル開発用のため、平文保存でよい
- 本番運用ではパスワード平文保存は避けることをREADMEに記載する
- チェックOFF時は保存済みユーザー名・パスワードを削除する

### 7. ログイン画面表示時に保存済み情報を復元する

ログイン画面を開いたとき、記録チェックがONで保存済み情報がある場合は、自動で入力欄へ反映する。

期待動作:

```text
前回:
チェックON
ユーザー名: admin
パスワード: admin

次回ログイン画面:
チェックON
ユーザー名欄: admin
パスワード欄: admin
ログインボタン活性
```

チェックOFFの場合:

```text
ログイン画面:
チェックOFF
ユーザー名欄: 空
パスワード欄: 空
```

### 8. ログイン成功時にも保存設定を反映する

ログイン成功時、チェックボックスの状態に応じて保存・削除を行う。

チェックON:

```text
- ユーザー名を保存
- パスワードを保存
- チェック状態ONを保存
```

チェックOFF:

```text
- 保存済みユーザー名を削除
- 保存済みパスワードを削除
- チェック状態OFFを保存
```

### 9. 登録後「はい」と記録チェックの関係

登録後「はい」を押した場合、ログインフォームに登録ユーザー名とパスワードを転記する。

ただし、記録チェックがONでない限り、ブラウザ保存はしない。

期待仕様:

```text
登録後「はい」
→ フォームには転記する
→ 保存はまだしない

その後ログインボタン押下
→ チェックONなら保存
→ チェックOFFなら保存しない
```

### 10. READMEに注意を追記する

READMEに以下を追記する。

```text
ログイン情報記録機能はローカル開発・ポートフォリオ確認用です。
現在はユーザー名・パスワードをブラウザ側に保存します。
本番運用ではパスワードを平文保存せず、Supabase Auth等の認証基盤へ移行する想定です。
```
