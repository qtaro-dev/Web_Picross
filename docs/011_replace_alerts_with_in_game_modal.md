# チケット11: ゲーム中のalert / confirm表示を画面内モーダルへ置き換え

## 目的

現在、ゲーム中の「時間切れです」「クリア」などの通知が、ブラウザ標準の `alert()` で表示されている。

ブラウザ標準ダイアログはゲーム画面の雰囲気を壊し、ポートフォリオ用として仮実装感が強いため、ゲーム画面内のモーダル表示へ置き換える。

あわせて、確認系の `confirm()` も可能な範囲で画面内モーダルへ置き換える。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\engine.js`
- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 対象にする表示

最低限、以下の `alert()` / `confirm()` を画面内UIへ置き換える。

```text
- クリア通知
- 時間切れ通知
- ギブアップ確認
- ヒント使用確認
- JSON読込エラー
- 保存時の上書き確認
- その他、ゲーム中やエディタ中に出る主要な alert / confirm
```

ただし、すべてを一気に置き換えることで大規模化する場合は、まずゲーム画面中のものを優先する。

優先順位:

```text
1. 時間切れ
2. クリア
3. ギブアップ確認
4. ヒント確認
5. エディタ系エラー・保存確認
```

## 実装内容

### 1. 既存のalert / confirm使用箇所を洗い出す

まず、プロジェクト内で以下を検索する。

```text
alert(
confirm(
window.alert
window.confirm
```

洗い出した箇所を、役割ごとに分類する。

### 2. 共通モーダル表示の仕組みを作る

既存設計に合わせて、画面内モーダルを表示する仕組みを作る。

候補:

```text
state.modal
renderModal()
actions.openModal()
actions.closeModal()
```

状態例:

```js
modal: {
  open: true,
  type: "timeout",
  title: "時間切れ",
  message: "制限時間が終了しました。",
  buttons: [
    { label: "セレクトへ戻る", action: "backToSelect" },
    { label: "リトライ", action: "retry" }
  ]
}
```

注意:

- 既存構造に合わない場合は、無理にこの形へ固定しない
- ただし、各所で独自モーダルを乱立させない
- なるべく共通部品として扱う

### 3. 見た目を既存テーマに合わせる

モーダルはWebピクロスの既存テーマに合わせる。

見た目の方針:

```text
- 背景を半透明の黒で覆う
- 中央にパネルを表示する
- パネルは黒・濃いグレー系
- 枠線は既存ボタンに近い白/グレー系
- 文字は白系
- ボタンは既存ボタンデザインに合わせる
```

### 4. 時間切れ通知をモーダル化する

現在の `alert("時間切れです")` のような処理を廃止し、ゲーム画面内モーダルで表示する。

表示例:

```text
時間切れ

制限時間が終了しました。

[セレクトへ戻る] [リトライ]
```

期待動作:

```text
- 時間切れ時にalertが出ない
- ゲーム画面内に時間切れモーダルが出る
- クリア扱いにはしない
- 入力は停止する、またはモーダル中は無視する
- セレクトへ戻れる
- 可能ならリトライできる
```

### 5. クリア通知をモーダル化する

現在の `alert("クリア")` のような処理を廃止し、ゲーム画面内モーダルで表示する。

表示例:

```text
クリア！

パズルを完成しました。

[OK] [セレクトへ戻る]
```

期待動作:

```text
- クリア時にalertが出ない
- ゲーム画面内にクリアモーダルが出る
- クリア済み処理は従来どおり行う
- タイマーは停止する
- セレクトへ戻れる
```

### 6. ギブアップ確認をモーダル化する

現在 `confirm()` を使っている場合、画面内モーダルへ置き換える。

表示例:

```text
ギブアップしますか？

この問題はクリア扱いになりません。

[キャンセル] [ギブアップ]
```

期待動作:

```text
- confirmが出ない
- キャンセルでゲームに戻る
- ギブアップでクリア扱いにせず終了する
- 必要ならセレクトへ戻る
```

### 7. ヒント確認をモーダル化する

ヒント使用時に確認を出している場合、画面内モーダルへ置き換える。

表示例:

```text
ヒントを使いますか？

未入力のマスを1つ正しく埋めます。

[キャンセル] [使う]
```

期待動作:

```text
- confirmが出ない
- キャンセルで何もしない
- 使うで既存のヒント処理を実行する
- カラー問題では正しい色を置く
- モノクロ問題では従来どおり動く
```

### 8. エディタ系のalert / confirmも可能な範囲で置き換える

以下の表示も、可能なら共通モーダルへ寄せる。

```text
- JSON読込エラー
- 保存成功
- 保存失敗
- 上書き確認
- 不正な難易度 / 面数 / カラーID
```

ただし、ゲーム画面側のモーダル化を優先し、エディタ側が大規模化する場合は後回しにしてよい。

後回しにした場合は、未対応箇所として報告する。

### 9. モーダル表示中の入力制御

モーダル表示中は、盤面操作が意図せず進まないようにする。

期待動作:

```text
- モーダル中に盤面クリックしても入力されない
- モーダル中に右クリックしても×が置かれない
- モーダル中にドラッグ状態が残らない
- モーダルを閉じた後、必要な状態に戻る
```

### 10. 既存機能を壊さない

以下を維持する。

```text
- 通常プレイ
- エディットプレイ
- カラー問題
- モノクロ問題
- 右クリック×
- 左クリック塗り
- 左ドラッグ塗り
- 右ドラッグ×
- 全消去
- 判定
- ヒント
- ギブアップ
- タイマー
- エディタ保存
- JSON読込
- JSONダウンロード
```

## 受け入れ条件

- ギブアップ確認でブラウザ標準confirmが出ない

- ヒント確認でブラウザ標準confirmが出ない

- ヒント処理が従来どおり動く
- モーダルの見た目が既存テーマに合っている
- モーダル中に盤面入力が進まない
- モーダルを閉じた後、必要な操作ができる
- 通常問題のプレイ導線が壊れない
- エディットプレイ導線が壊れない
- カラー問題の操作が壊れない
- モノクロ問題の操作が壊れない
- `node --check js/state.js` が通る
