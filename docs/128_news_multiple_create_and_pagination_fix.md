# チケット128：お知らせ管理で2件目以降の記事作成が反映されない問題の修正とページング対応

## 目的

チケット126・127で管理者用のお知らせ管理と画像アップロード機能を追加したが、管理者画面で2件目以降のお知らせ記事を作成した際に、保存成功のように見えても `news_posts` に追加されず、一般向けお知らせ画面にも表示されない場合がある。

新規作成・編集・画像アップロード付き投稿の保存処理を見直し、複数記事を正しく作成できるようにする。  
また、お知らせ記事が増えた場合に管理者画面の一覧が長くなりすぎないよう、管理者用お知らせ一覧に10件単位のページングを追加する。

## 対象ファイル（推定）

- `js/admin.js`
- `js/actions.js`
- `js/render.js`
- `js/state.js`
- `js/config.js`
- `styles.css`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. 2件目以降の記事作成が反映されない原因を調査・修正する

- 管理者画面のお知らせ管理で、2件目以降の記事作成が `news_posts` に追加されない問題を修正する。
- 以下の観点を確認する。
  - 新規作成時に、前回編集していた記事IDが state に残っていないか
  - 新規作成時に、`selectedNewsPostId` / `editingNewsId` 相当の状態が正しくクリアされているか
  - 保存処理が `insert` ではなく誤って `update` になっていないか
  - 画像アップロード後の保存処理で、記事IDや一時状態がズレていないか
  - 保存成功メッセージを、Supabase反映前に出していないか
  - Supabaseの `error` を握りつぶしていないか
- 新規作成と編集更新の分岐を明確にする。
- 新規作成時は必ず `insert` を実行する。
- 既存記事編集時は必ず対象記事IDを指定して `update` を実行する。

### 2. 保存結果の検証とエラー表示を強化する

- Supabaseの `insert` / `update` / `delete` の戻り値と `error` を必ず確認する。
- 保存成功メッセージは、DB反映が成功した場合だけ表示する。
- 保存失敗時は、成功表示を出さず、原因が分かるメッセージを表示する。
- コンソールにだけエラーが出て画面では成功扱いになる状態を避ける。
- エラー表示は既存UIのトーンに合わせる。
- service_roleキーをフロントエンドへ露出しない。
- RLSや管理者判定を迂回しない。

### 3. 画像アップロード付き記事作成の保存フローを修正する

- 画像アップロード付きで新規記事を作成した場合も、記事が `news_posts` に追加されるようにする。
- 画像アップロード成功後、取得した画像URLが新規記事の `image_url` に正しく入るようにする。
- 画像プレビューだけ成功して記事保存が失敗する場合は、画面上で失敗が分かるようにする。
- 画像URL手入力記事、画像なし記事、画像アップロード記事の3パターンをすべて保存できるようにする。
- Storageファイル削除・画像URL解除の既存機能を壊さない。

### 4. 保存後に記事一覧を再取得する

- 新規作成・編集・削除・公開/非公開切り替え後は、管理者のお知らせ一覧を再取得する。
- 保存後に画面上の一覧が古いまま残らないようにする。
- 一般向けお知らせ画面でも、公開済み記事が反映されることを確認する。
- 必要であれば、キャッシュやローカルstateの更新順を見直す。

### 5. 管理者用お知らせ一覧にページングを追加する

- 管理者画面のお知らせ管理一覧に、10件単位のページングを追加する。
- 1ページあたりの表示件数は `10件` とする。
- 一覧の下部または上部にページ操作UIを追加する。
- 表示例：
  - `前へ`
  - `次へ`
  - `1 / 3ページ`
  - `全25件`
- 記事数が10件以下の場合は、ページ操作が目立ちすぎないようにする。
- ページ移動しても、選択中・編集中の記事状態が不自然に壊れないようにする。
- 記事作成後は、必要に応じて1ページ目へ戻すか、作成した記事が見えるページに移動する。
- どちらの仕様にするかREADMEまたはコメントに明記する。

### 6. 一覧の並び順を維持する

- 管理者一覧の並び順は、一般向けお知らせ画面と整合するようにする。
- 推奨順：
  1. `published_at desc`
  2. `display_order asc`
  3. `created_at desc`
- 非公開記事も管理者一覧には表示する。
- 非公開記事は状態列で分かるようにする。

### 7. 既存仕様を壊さない

- チケット126のお知らせ管理機能を維持する。
- チケット127の画像アップロード機能を維持する。
- 一般向けお知らせ画面では公開済み記事のみ表示する。
- 非公開記事は一般向け画面に表示しない。
- `data/news.json` フォールバック仕様を維持する。
- ログイン、ゲーム選択、実プレイ、エディタ、既存管理者機能を壊さない。
- 既存テーマ・背景・ボタンデザインを維持する。
- 既存ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### 1件目の記事作成

- 管理者が管理者画面を開く。
- 管理者が「お知らせ管理」で新規記事を作成する。
- タイトル、本文、公開状態を入力して保存する。
- OK：`news_posts` に1件追加されること。
- OK：管理者一覧に表示されること。
- OK：公開済みなら一般向けお知らせ画面に表示されること。
- NG：保存成功表示だけ出てDBに追加されないこと。

### 2件目の記事作成

- 管理者が続けて2件目の記事を新規作成する。
- タイトル、本文、公開状態を入力して保存する。
- OK：`news_posts` に2件目として追加されること。
- OK：1件目が上書きされないこと。
- OK：管理者一覧に2件表示されること。
- OK：公開済みなら一般向けお知らせ画面にも2件表示されること。
- NG：2件目がDBに追加されないこと。
- NG：1件目が2件目の内容で上書きされること。

### 画像なし記事

- 管理者が画像なしの記事を新規作成する。
- OK：保存できること。
- OK：一般向けお知らせ画面で画像なし記事として自然に表示されること。
- NG：画像がないことで保存失敗すること。

### 画像URL手入力記事

- 管理者が画像URLを入力して記事を新規作成する。
- OK：保存できること。
- OK：一般向けお知らせ画面で画像が表示されること。
- OK：画像alt・キャプションが反映されること。
- NG：画像URL入力記事だけ保存できないこと。

### 画像アップロード付き記事

- 管理者が画像ファイルを選択する。
- 管理者が画像アップロードを行う。
- 管理者が記事を保存する。
- OK：画像URLが `image_url` に入った記事が新規作成されること。
- OK：一般向けお知らせ画面で画像が表示されること。
- OK：管理者一覧にも記事が表示されること。
- NG：画像プレビューは出るが記事がDBに追加されないこと。
- NG：保存成功表示だけ出て記事が存在しないこと。

### 編集更新

- 管理者が既存記事を選択する。
- 管理者がタイトル・本文・公開状態・画像URLを変更する。
- 管理者が保存する。
- OK：対象記事だけが更新されること。
- OK：別の記事が上書きされないこと。
- NG：編集保存が新規作成扱いになること。
- NG：別記事の内容が変わること。

### 削除

- 管理者が任意の記事を削除する。
- OK：確認ダイアログが表示されること。
- OK：確認後にDBから削除されること。
- OK：管理者一覧から消えること。
- OK：一般向け画面からも消えること。
- NG：削除後も一覧に残ること。

### 保存失敗時

- RLSエラー、通信エラー、必須項目不足など、保存失敗を想定する。
- OK：画面上に失敗メッセージが表示されること。
- OK：保存成功メッセージが出ないこと。
- NG：DB反映されていないのに成功表示が出ること。

### 10件ページング

- 管理者が11件以上の記事を用意する。
- OK：管理者一覧が10件で1ページに分かれること。
- OK：`前へ` / `次へ` でページ移動できること。
- OK：現在ページと総ページ数が分かること。
- OK：11件目以降も別ページで確認できること。
- NG：11件目以降が見えないこと。
- NG：ページ移動で画面が壊れること。

### ページング中の編集

- 管理者が2ページ目の記事を選択する。
- 管理者が記事を編集して保存する。
- OK：対象記事が更新されること。
- OK：保存後も一覧が再取得されること。
- NG：別ページの記事が上書きされること。

### 一般向けお知らせ画面

- 管理者が複数の公開記事を作成する。
- 一般ユーザーがお知らせ画面を開く。
- OK：公開済み記事が複数表示されること。
- OK：非公開記事は表示されないこと。
- OK：記事を選ぶと本文が切り替わること。
- NG：1件しか表示されないこと。
- NG：非公開記事が表示されること。

### 回帰確認

- ユーザーがログイン画面を開く。
- ユーザーがゲーム選択画面を開く。
- ユーザーが実プレイ画面を開く。
- ユーザーがエディタ画面を開く。
- 管理者が既存のユーザー管理・ランキング・パズル管理を開く。
- OK：既存機能が従来どおり動くこと。
- NG：お知らせ修正の影響で既存機能が壊れること。
