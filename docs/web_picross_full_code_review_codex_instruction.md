# 実装内容（具体的変更指示）

今回は実装・修正は行わないでください。

以下の観点でコードレビューを行い、問題点を報告してください。

## 1. セキュリティレビュー

以下を重点的に確認してください。

- Supabase `service_role` key や `SUPABASE_SECRET_KEY` がフロントエンドへ露出していないか
- `.env` 相当の秘密情報がコードやREADMEに含まれていないか
- 管理者専用処理が一般ユーザーから実行できないか
- 管理者判定がフロント側だけに依存していないか
- Supabase RLS が想定どおり機能する設計になっているか
- Storage のアップロード・削除権限が管理者限定になっているか
- 一般ユーザーが非公開のお知らせ記事を読めないか
- XSSにつながる `innerHTML` やHTML展開がないか
- お知らせ本文・タイトル・画像キャプションなどが安全に表示されているか
- 画像アップロードで危険な形式を許可していないか
- SVGアップロード禁止方針が守られているか
- ファイルサイズ制限がクライアントだけに偏りすぎていないか

## 2. Supabase / DB / Storageレビュー

以下を確認してください。

- `news_posts` テーブルのRLS設計
- `news-images` Storageバケットのポリシー設計
- `is_admin()` の使用箇所
- insert / update / delete の権限
- 公開済み記事のみ一般画面に出るか
- 非公開記事が一般画面に漏れないか
- SQLファイルの実行順や依存関係
- 既存SQLとの衝突
- `updated_at` 更新トリガーの整合性
- Storage公開URLの扱い
- 削除処理で他記事の画像を誤って消す可能性

## 3. 認証・ログインレビュー

以下を確認してください。

- ユーザー名ログイン時の `username -> email` 解決処理
- `resolve-login-email` APIの情報漏えいリスク
- パスワード再設定・確認メール再送処理
- 管理者ログイン後の権限反映
- ログイン状態の保持処理
- localStorageに保存している情報の妥当性
- エラー表示でユーザー存在有無を漏らしすぎていないか

## 4. お知らせ管理レビュー

以下を確認してください。

- 新規作成 / 編集 / 削除 / 公開 / 非公開の分岐
- `insert` と `update` の誤判定が再発しないか
- 保存成功表示がDB反映後にのみ出るか
- 保存失敗時に成功表示されないか
- 画像アップロード後の記事保存フロー
- 画像URL解除とStorage削除の挙動
- 画像URLコピー処理
- 本文なし・画像あり記事の保存条件
- タイトルのみ記事の拒否条件
- 管理者一覧の10件ページング
- ページング中の編集・削除で別記事を更新しないか

## 5. ピクロスゲーム本体レビュー

以下を確認してください。

- 盤面描画のパフォーマンス
- Endless大盤面での重さ
- セル差分更新の整合性
- スクロール位置保持
- ミニマップ更新処理
- stickyヒントと5マス補助線の副作用
- 判定ボタンのXマーク処理
- 判定メッセージの分岐
- クリア後編集不可の維持
- ヒント・ギブアップ・やりなおし処理
- カラー問題の色判定

## 6. 保守性レビュー

以下を確認してください。

- 1ファイルに処理が集中しすぎていないか
- 重複処理が多くないか
- state更新が複雑化していないか
- renderとactionsの責務が崩れていないか
- 命名が分かりにくい箇所
- 今後チケット化した方がよいリファクタ候補
- READMEと実装の説明ズレ
- `ticket_status.json` の整合性

## 7. 出力形式

レビュー結果は、以下の形式で報告してください。

各指摘は、重大度順に並べてください。

- `High`: セキュリティ事故、権限漏れ、データ破壊、ログイン不能、重大な保存不具合につながるもの
- `Medium`: 実用上の不具合、保守性低下、特定条件での破綻につながるもの
- `Low`: 軽微な改善、読みやすさ、将来的な整理候補

各項目は以下の形式で記載してください。

```text
## 指摘番号
重大度: High / Medium / Low
対象ファイル:
対象箇所:
問題内容:
なぜ問題か:
推奨修正方針:
修正チケット化:
```

最後に、以下もまとめてください。

```text
# 総評
# すぐ直すべき項目
# 後回しでよい項目
# チケット化候補一覧
# 修正不要だが注意しておく点
```
