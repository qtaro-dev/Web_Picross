# チケット135：localStorageへのパスワード保存廃止

## 目的

コードレビューで、`remember` 有効時にパスワードを `localStorage` に保存している可能性が指摘された。

`localStorage` に平文パスワードを保存すると、XSSや端末共有時に漏えいリスクが高いため、パスワード保存を廃止し、保存対象はユーザー名など安全性の高い情報に限定する。

## 対象ファイル（推定）

- `js/actions.js`
- `js/supabaseAuth.js`
- `js/render.js`
- `js/state.js`
- `js/config.js`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. パスワード保存処理を削除する

- `localStorage` にパスワードを保存している箇所を確認する。
- `remember` 有効時でも、パスワードを保存しないようにする。
- 既存の保存済みパスワードがある場合は、読み込み時またはログイン時に削除する。
- `localStorage.removeItem()` などで旧キーを掃除する。

### 2. 保存対象をユーザー名のみにする

- ログイン補助として保存する場合は、ユーザー名のみ保存する。
- メールアドレスやパスワードは保存しない。
- UI文言を修正する。
  - 例：`ユーザー名を記憶する`
- 旧文言が `メールアドレスとパスワードを記録する` のようになっている場合は修正する。

### 3. Supabaseセッション保持を利用する

- ログイン状態の維持はSupabase Authのセッション保持に任せる。
- アプリ独自にパスワードを保持しない。
- ログアウト時は必要なセッション情報だけ削除し、保存ユーザー名の扱いを仕様として決める。

### 4. 既存ログイン体験を大きく損なわない

- ユーザー名が保存されていれば、ログイン画面でユーザー名だけ自動入力されるようにしてよい。
- パスワードは毎回入力する。
- セッションが有効な場合は従来どおりログイン状態を維持する。

## 受け入れ条件（目視確認基準）

### パスワードが保存されない

- ユーザーがログイン画面で記憶チェックをONにする。
- ユーザー名とパスワードでログインする。
- ブラウザのlocalStorageを確認する。
- OK：パスワードが保存されていないこと。
- NG：平文パスワードがlocalStorageに残ること。

### 旧保存パスワード削除

- 旧バージョンで保存済みのパスワードがある状態を想定する。
- 新バージョンを開く。
- OK：旧パスワード保存キーが削除されること。
- NG：過去のパスワードが残り続けること。

### ユーザー名記憶

- 記憶チェックONでログインする。
- ログアウトまたは再訪問する。
- OK：ユーザー名のみ復元されること。
- NG：パスワードまで復元されること。

### ログイン回帰

- 一般ユーザーと管理者でログインする。
- OK：従来どおりログインできること。
- NG：記憶機能変更によりログイン不能になること。
