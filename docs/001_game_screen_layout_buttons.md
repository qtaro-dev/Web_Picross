- AGENT.md が存在する場合、その内容を最優先で遵守する
- ユーザーはコードを直接編集しない前提
- 実装・修正はすべて AIエージェント が行う
- 既存設計を破壊しない
- 既存テーマ・ライブラリ構成を維持する
- 既存の動作確認済み導線を壊さない
- ハードコード文字列は避け、既存の定数・状態管理・描画構造に合わせる
- 変更後は対象JSファイルに対して `node --check` を実行する

# チケット1: ゲーム中画面のレイアウト変更と操作ボタン追加

## 目的

ゲーム中画面の操作UIを整理し、スクリーンショットの赤枠イメージに近いレイアウトへ変更する。  
現在中央上部に縦並び気味で配置されている操作ボタンを、盤面左側または盤面横の操作エリアへ移動し、プレイ画面として見やすくする。

あわせて、以下のボタンを新設する。

- メニューへ戻る
- ギブアップ
- ヒント

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 実装内容

### 1. ゲーム画面の基本レイアウトを調整する

スクリーンショットの意図に合わせて、ゲーム中画面を以下のような構成に整理する。

```text
左側:
- 残り時間表示欄
- 操作ボタン群
  - 全消去
  - 判定
  - メニューへ戻る
  - ギブアップ
  - ヒント

中央:
- パズル名 / サイズ表示
- パズル盤面
- 操作説明
```

既存の黒背景・白文字・枠線ボタンの雰囲気は維持する。

### 2. 既存ボタンを移動する

現在の以下のボタンを、スクリーンショットの赤枠イメージに近い操作エリアへ移動する。

- 全消去
- 判定

機能は変更しない。

### 3. 「メニューへ戻る」ボタンを追加する

ゲーム中画面からメニュー画面へ戻るボタンを追加する。

期待動作:

```text
ゲーム画面 → メニュー画面
```

注意:

- 既存の「セレクトに戻る」と競合しないようにする
- 必要なら「セレクトに戻る」は残してよい
- ただし、画面上でボタンが散らばりすぎないよう整理する

### 4. 「ギブアップ」ボタンを追加する

ゲームを途中終了するためのボタンを追加する。

期待動作:

- 押下時に確認ダイアログを出す
- OKの場合、現在の問題を終了扱いにする
- クリア扱いにはしない
- 可能であれば正解盤面を表示する、またはセレクト画面へ戻る

最小実装でよいが、クリア済み扱いにしてはいけない。

### 5. 「ヒント」ボタンを追加する

ヒントボタンを追加する。

初期実装は最小でよい。

候補:

- 未入力セルのうち、正解で塗るべきセルを1つだけ塗る
- または、未入力セルのうち、塗らないセルを1つだけ×にする
- ヒント使用時は確認ダイアログを出してもよい

注意:

- ヒントで埋めたセルも、塗りと×の排他制御を守る
- 既存の判定ロジックを壊さない
- ヒント回数制限は今回必須ではない

### 6. 画面崩れを避ける

盤面と操作ボタンが重ならないようにする。

特に以下を確認する。

- 10x10盤面で崩れない
- 5x5盤面で不自然に間延びしない
- ボタンが盤面やヒント数字に被らない
- ブラウザ幅が広い状態で中央に寄りすぎない

## 受け入れ条件

- ローカルサーバーで起動できる
- タイトル → メニュー → ゲームセレクト → 問題選択 → ゲーム画面まで遷移できる
- ゲーム中画面に操作エリアが表示される
- 「全消去」ボタンが従来どおり動作する
- 「判定」ボタンが従来どおり動作する
- 「メニューへ戻る」ボタンでメニュー画面へ戻れる
- 「ギブアップ」ボタンが表示される
- 「ギブアップ」してもクリア済み扱いにならない
- 「ヒント」ボタンが表示される
- ヒント使用時に塗りと×が重ならない
- 盤面とボタンが重ならない
- `node --check js/render.js` が通る
- 変更したJSファイルすべてで `node --check` が通る
