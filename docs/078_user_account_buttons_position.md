# チケット78: ユーザーデータ画面のアカウント操作ボタンを下部へ移動する

## 目的

ユーザーデータ画面の「アカウント管理」セクションで、`パスワード変更` と `アカウント削除申請` ボタンの位置を下げ、入力欄・強度表示・確認欄と自然に分離する。

## 背景

現在のユーザーデータ画面では、以下の2つのボタンがパスワード確認欄の直下に近すぎる位置へ表示されている。

```text
パスワード変更
アカウント削除申請
```

スクリーンショット上では、ボタン群が入力欄と近く、フォーム全体の視線誘導が少し窮屈に見える。

特に `アカウント削除申請` は危険操作に近いボタンなので、パスワード変更操作と横並びにしつつも、入力欄から少し下げて分離した方が分かりやすい。

## 対象ファイル（推定）

```text
js/render.js
js/actions.js
styles.css
README.md
docs/ticket_status.json
```

## 実装内容

### 1. アカウント管理ボタン群を下に移動する

ユーザーデータ画面の「アカウント管理」内にある以下のボタン群を、現在より下へ移動する。

```text
パスワード変更
アカウント削除申請
```

修正方針:

```text
新しいパスワード入力欄
新しいパスワード確認欄
パスワード強度表示
補足文
↓
適度な余白
↓
パスワード変更 / アカウント削除申請 ボタン
```

### 2. 入力欄との余白を確保する

ボタン群の上に適度な余白を追加する。

目安:

```text
margin-top: 16px 〜 24px 程度
```

既存レイアウトに合わせて自然な値にする。

### 3. ボタン群のレイアウトを整える

現在の横並びレイアウトは維持してよいが、以下を確認する。

```text
2つのボタンの高さが揃っている
ボタン同士の間隔が自然
入力欄と重ならない
スマホ幅で崩れない
```

スマホ幅では必要に応じて縦並びにする。

### 4. 危険操作の見た目を検討する

`アカウント削除申請` は通常ボタンより危険操作寄りなので、可能であれば軽く区別する。

例:

```text
赤系の枠線
警告色の薄い背景
hover時の警告色
```

ただし、派手すぎないよう既存テーマに合わせる。

### 5. 既存処理を壊さない

見た目と配置の調整を目的とするため、以下の処理は壊さない。

```text
パスワード変更処理
アカウント削除申請処理
パスワード表示 / 非表示切り替え
パスワード強度メーター
入力制限
エラー表示
```

## UI仕様

- ボタン群が入力欄に近すぎない
- フォームとして自然な縦の流れになっている
- `パスワード変更` と `アカウント削除申請` が見やすい
- `アカウント削除申請` は危険操作であることが少し分かる
- 既存テーマを壊さない
- ダークテーマ上で見やすい
- スマホ幅でも崩れない

## 受け入れ条件

- ユーザーデータ画面の `パスワード変更` ボタンが現在より下に配置されている
- `アカウント削除申請` ボタンも同じボタン群として下に配置されている
- 新しいパスワード確認欄とボタン群の間に適度な余白がある
- ボタン群が入力欄やパスワード強度メーターと重ならない
- ボタンの高さ・横幅・間隔が不自然ではない
- スマホ幅でも崩れない
- パスワード変更処理が壊れていない
- アカウント削除申請処理が壊れていない
- パスワード表示 / 非表示ボタンが壊れていない
- パスワード強度メーターが壊れていない
- `node --check` が通る
- ビルド番号を +1 する
- `docs/ticket_status.json` にこのチケットを追加し、初期状態を `未修整` にする
