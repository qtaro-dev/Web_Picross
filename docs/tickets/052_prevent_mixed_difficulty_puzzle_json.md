# チケット52: エディットモードで難易度混在JSONを作成・保存・読込できないようにする

## 目的

エディットモードで、1つのパズルデータJSON内に複数の難易度が混在しないようにする。

例:

```text
スロット1: イージー
スロット2: ノーマル
スロット3: エンドレス
```

このような難易度混在データは、作成・保存・読込できないようにする。

理由:

```text
イージー用JSONの中にノーマル難易度やエンドレス難易度のデータが入り込むと、
ゲームセレクト、クリア管理、ランキング集計などに影響を及ぼす可能性があるため。
```

## 対象ファイル（推定）

```text
E:\Dev\web_picross_Ver2\js\editor.js
E:\Dev\web_picross_Ver2\js\actions.js
E:\Dev\web_picross_Ver2\js\render.js
E:\Dev\web_picross_Ver2\js\state.js
E:\Dev\web_picross_Ver2\js\config.js
E:\Dev\web_picross_Ver2\server.js
E:\Dev\web_picross_Ver2\styles.css
E:\Dev\web_picross_Ver2\README.md
```

## 実装内容

### 1. 1ファイル1難易度ルールを明確化する

パズルデータJSONは、1ファイルにつき1難易度のみ許可する。

許可例:

```text
beginner.json
→ 全スロット beginner のみ

easy.json
→ 全スロット easy のみ

normal.json
→ 全スロット normal のみ

hard.json
→ 全スロット hard のみ

endless.json
→ 全スロット endless のみ
```

禁止例:

```text
easy.json の中に normal のパズルが入っている
beginner.json の中に hard のパズルが入っている
1つのJSON内に beginner / easy / normal が混在している
```

### 2. JSON読込時に難易度混在チェックを行う

エディットモードでJSONを読み込んだ時、全スロットの難易度を検査する。

検査対象:

```text
- puzzle.difficulty
- puzzle.level
- puzzle.meta.difficulty
- 既存データ構造で難易度を保持しているフィールド
```

既存仕様で難易度フィールドがない場合は、以下の順で判定する。

```text
1. 読み込んだファイル名から推定した難易度
2. 画面上の現在選択難易度
3. JSON内の各パズルが持つ difficulty
```

ただし、難易度フィールドが存在する場合は、ファイル内で混在していないことを必ず確認する。

### 3. 固定ファイル名と中身の難易度一致を確認する

固定ファイル名で読み込んだ場合は、ファイル名と中身の難易度が一致することを確認する。

対象ファイル:

```text
beginner.json
easy.json
normal.json
hard.json
endless.json
```

判定:

```text
beginner.json → 全スロット beginner であること
easy.json     → 全スロット easy であること
normal.json   → 全スロット normal であること
hard.json     → 全スロット hard であること
endless.json  → 全スロット endless であること
```

不一致がある場合は読み込みを中断する。

### 4. 混在JSONは読み込みできないようにする

難易度混在を検出した場合、エディタに反映しない。

表示するアラート例:

```text
このJSONには複数の難易度が混在しているため読み込みできません。
1つのJSONファイルには1つの難易度のみ含めてください。
```

ファイル名と中身が不一致の場合:

```text
読み込んだファイル名とパズル難易度が一致しないため読み込みできません。
例: easy.json には easy のパズルのみ保存できます。
```

### 5. スロット保存時に現在ファイルの難易度と一致させる

エディットモードでスロット保存する時、保存対象スロットの難易度が現在のJSON難易度と一致するようにする。

仕様:

```text
- 現在読み込んでいるファイルが beginner.json の場合、保存されるスロットの difficulty は beginner にする
- 現在読み込んでいるファイルが easy.json の場合、保存されるスロットの difficulty は easy にする
- ファイル名から難易度が確定できる場合、スロットごとの個別難易度変更は許可しない
```

### 6. 個別スロットに難易度を混在設定できないUIにする

スロットごとに個別難易度を持たせる操作ができる場合は、混在を作れないようにする。

方針:

```text
- 難易度はファイル単位で管理する
- スロット単位の難易度編集は廃止または無効化する
- 画面上の難易度ドロップダウンは「現在編集中のJSON全体の難易度」として扱う
```

### 7. JSON出力前に難易度混在チェックを行う

以下の出力前に、必ず難易度混在チェックを実行する。

```text
- 読込ファイル名でJSON出力
- 別名でJSON出力
- スロット保存後の出力
```

混在を検出した場合は出力を中断する。

表示する警告例:

```text
このファイルには複数の難易度が混在しています。
このまま保存すると読み込みできない可能性があります。
難易度を統一してから保存してください。
```

より厳密にする場合:

```text
このファイルには複数の難易度が混在しているため保存できません。
1つのJSONファイルには1つの難易度のみ含めてください。
```

基本方針は「保存できない」にする。ただし、既存データ保護のため一時的に警告のみとする場合は、最終報告で明記する。

### 8. 読み込みできない可能性があるデータを作らせない

ユーザーが難易度混在データを作りそうな操作をした時点で警告する。

例:

```text
現在のJSONは easy として編集中です。
normal の難易度データをこのファイルに保存することはできません。
```

または:

```text
この操作を行うと、1つのJSON内に複数難易度が混在します。
ランキングやクリア管理に影響する可能性があるため保存できません。
```

### 9. ランキング・クリア管理への影響を防ぐ

ランキングやクリア管理で使用する難易度は、ファイル単位・画面選択難易度・ユーザーデータ保存時の難易度と一致させる。

確認対象:

```text
- ゲームセレクトの難易度
- パズルID
- ユーザーデータのprogress
- ランキングAPI
- クリア記録
- ギブアップ記録
```

難易度混在JSONがランキング集計対象に入らないようにする。

## 受け入れ条件

```text
- http://127.0.0.1:8000/ で確認できる
- beginner.json に beginner 以外の難易度が含まれる場合、読み込みできない
- easy.json に easy 以外の難易度が含まれる場合、読み込みできない
- normal.json に normal 以外の難易度が含まれる場合、読み込みできない
- hard.json に hard 以外の難易度が含まれる場合、読み込みできない
- endless.json に endless 以外の難易度が含まれる場合、読み込みできない
- 1つのJSON内に複数難易度が混在する場合、読み込みできない
- 難易度混在JSONを保存しようとした場合、保存を中断するか警告を表示する
- スロット単位で個別難易度を混在設定できない
- JSON出力前に難易度混在チェックが行われる
- 正常な単一難易度JSONは従来通り読み込める
- 正常な単一難易度JSONは従来通り出力できる
- ゲームセレクト、クリア管理、ランキングが壊れない
- node --check が変更したJSファイルすべてで通る
```

