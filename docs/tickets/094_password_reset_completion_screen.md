# チケット94：パスワード再設定リンク後の新パスワード設定画面

## 背景

チケット92・93で、Supabase Auth の `resetPasswordForEmail()` を使ったパスワード再設定メール送信までは実装済み。

実メールの到着は確認できた。

ただし、メール内の再設定リンクを開くと、現在は以下のようなURLでアプリへ戻るだけになっている。

```text
http://127.0.0.1:8000/#access_token=...&type=recovery...
```

この後に、新しいパスワードを入力して確定する画面がまだ存在しない。

## 目的

パスワード再設定メールのリンクから戻ってきたユーザーに対して、新しいパスワードを入力・確定できる専用画面を表示する。

## 対象ファイル（推定）

```text
js/supabaseAuth.js
js/actions.js
js/render.js
js/config.js
styles.css
README.md
docs/ticket_status.json
```

## 実装内容

### 1. パスワード再設定リンクからの復帰を検出する

URLフラグメントまたはSupabase Authイベントから、パスワード再設定モードを検出する。

検出対象例:

```text
#access_token=...
#refresh_token=...
type=recovery
PASSWORD_RECOVERY
```

Supabase JSの既存処理に合わせ、`onAuthStateChange` などで `PASSWORD_RECOVERY` を検出できる場合はそれを優先する。

### 2. 新パスワード設定画面を表示する

パスワード再設定モードの場合、通常のログイン画面ではなく、専用の新パスワード設定画面を表示する。

画面要素:

```text
新しいパスワード
新しいパスワード（確認）
パスワード強度表示
パスワードを更新するボタン
キャンセル / ログイン画面へ戻るボタン
```

### 3. 入力チェックを行う

以下をチェックする。

```text
新パスワードが未入力ではない
既存のパスワードルールを満たす
確認用パスワードと一致する
```

既存のパスワード強度判定や入力チェックがある場合は流用する。

### 4. Supabase Authへ新パスワードを反映する

入力チェック後、Supabase Auth のユーザー更新処理でパスワードを変更する。

想定処理:

```text
supabase.auth.updateUser({ password: newPassword })
```

既存のSupabaseクライアント構造に合わせて実装する。

### 5. 更新完了後はセッションを終了し、ログイン画面へ戻す

パスワード更新完了後は、明示的にログアウトまたはセッション整理を行い、ログイン画面へ戻す。

表示メッセージ:

```text
パスワードを更新しました。新しいパスワードでログインしてください。
```

### 6. アクセストークンを画面に表示しない

URLに含まれる `access_token` や `refresh_token` は画面上に表示しない。

ログ出力にも残さない。

### 7. 不正・期限切れリンクの場合のメッセージを用意する

リンクが無効、期限切れ、セッション取得失敗などの場合は、ログイン画面へ戻してエラーを表示する。

表示メッセージ例:

```text
パスワード再設定リンクが無効、または期限切れです。再度メールを送信してください。
```

## 受け入れ条件

### 正常系

```text
1. ログイン画面からパスワード再設定メールを送信する
2. メール内リンクを開く
3. 新パスワード設定画面が表示される
4. 新パスワードと確認用パスワードを入力する
5. パスワード更新が成功する
6. ログイン画面へ戻る
7. 新しいパスワードでログインできる
```

### 入力エラー

```text
未入力ならエラー表示
パスワードルール違反ならエラー表示
確認用パスワード不一致ならエラー表示
```

### 無効リンク

```text
期限切れまたは不正リンクでは更新画面に進めない
ログイン画面へ戻る
エラーメッセージが表示される
```

### セキュリティ

```text
access_token / refresh_token を画面表示しない
access_token / refresh_token をログ出力しない
更新完了後に不要なセッションを残さない
```

## メモ

本番公開時は、Supabase側のRedirect URL設定に本番URLを追加する必要がある。

ローカル開発では `http://127.0.0.1:8000/` などのローカルURLで動作確認する。
