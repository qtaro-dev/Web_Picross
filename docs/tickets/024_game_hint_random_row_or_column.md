# チケット24: ゲーム中ヒントをランダム行・列の正解表示に変更

## 目的

ゲーム中のヒント機能を、現在の「未入力マスを1つ正しく埋める」方式から、ランダムに選ばれた1行または1列の正解部分を表示する方式へ変更する。

ヒント使用時に、対象となった行または列のうち、正解として塗るべきマスをまとめて表示する。  
カラー問題の場合は、正しい色も反映する。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\engine.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 実装内容

### 1. ヒント対象をランダムに行または列から選ぶ

ヒントを使ったとき、以下のどちらかをランダムに選ぶ。

```text
- 1行
- 1列
```

さらに、選ばれた方向の中からランダムに対象番号を選ぶ。

例:

```text
行ヒント:
- 3行目を対象にする

列ヒント:
- 5列目を対象にする
```

### 2. 対象行・列の正解部分を表示する

対象となった行または列について、正解として塗るべきマスをプレイヤー入力へ反映する。

モノクロ問題:

```text
正解が塗りのマス → 塗り状態にする
正解が空白のマス → 原則そのまま
```

カラー問題:

```text
正解がカラーID付きマス → 正しいカラーIDで塗る
正解が空白のマス → 原則そのまま
```

注意:

- 空白マスに自動で×を置くかどうかは、既存仕様との整合性を見て判断する
- 要望は「正解部分を表示」なので、塗るべき部分の反映を優先する
- 既に間違った塗りや色がある場合、正解部分は正しい状態へ上書きする
- 既に×が置かれている正解マスは、×を消して正しい塗りへ変更する

### 3. すでに完成済みの行・列は避ける

可能であれば、すでにすべて正しく入力済みの行・列はヒント対象から除外する。

候補ロジック:

```text
- 未完成の行・列一覧を作る
- その中からランダム選択する
- 全行・全列が完成済みなら、ヒント不要メッセージを出す
```

最小実装では、ランダム選択後に未変更だった場合、別候補を探す処理でもよい。

### 4. ヒント使用後に対象行・列を短く強調表示する

可能であれば、ヒントで反映した行または列が分かるように、短時間だけハイライトする。

例:

```text
- 対象行を薄く光らせる
- 対象列を薄く光らせる
- 「3行目を表示しました」などのメッセージを出す
```

最小実装ではメッセージのみでもよい。

### 5. ヒント確認モーダルと連携する

チケット11で実装した画面内モーダルのヒント確認がある場合、それと連携する。

期待動作:

```text
ヒントボタン
→ ヒントを使いますか？モーダル
→ 使う
→ ランダム行/列ヒントを実行
```

ブラウザ標準 `confirm()` へ戻さないこと。

### 6. 既存操作を壊さない

以下の既存機能を維持する。

```text
- 左クリック塗り
- 右クリック×
- 左ドラッグ塗り
- 右ドラッグ×
- カラー選択
- 全消去
- 判定
- ギブアップ
- タイマー
- エディットプレイ
```

## 受け入れ条件

- ヒントボタンを押せる
- ヒント確認モーダルがある場合、それ経由で実行できる
- ヒント使用時、ランダムに1行または1列が選ばれる
- 対象行または列の正解として塗るべきマスが反映される
- モノクロ問題で正しい塗りが反映される
- カラー問題で正しい色が反映される
- 正解マスに×がある場合、ヒントで×が消えて正しい塗りになる
- すでに正しいマスは壊れない
- 可能な範囲で完成済み行・列は避けられる
- ヒント使用後に対象行・列、または実行内容が分かる
- 判定が壊れない
- エディットプレイでもヒントが動く
- `node --check js/actions.js` が通る
- `node --check js/engine.js` が通る
- `node --check js/render.js` が通る
- 変更したJSファイルすべてで `node --check` が通る
