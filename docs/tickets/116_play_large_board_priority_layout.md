# チケット116：大盤面時の盤面優先レイアウト調整

## 目的

20×20以上やEndlessなどの大きい盤面で、横スクロールや周辺UIの圧迫によりゲームがしづらくなる問題を改善する。

大盤面では、周辺UIよりも盤面の見やすさと操作しやすさを優先する。

## 対象ファイル（推定）

- `index.html`
- `styles.css`
- `js/render.js`
- `js/actions.js`
- `js/config.js`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

- 大盤面表示時に、盤面表示領域を優先するレイアウトへ調整する。
- 盤面がブラウザ幅を超えやすい場合、以下を検討して実装する。
  - 左操作パネルを閉じた状態で盤面を広く表示する。
  - 右側に不要な余白やパレット領域を残さない。
  - 盤面コンテナの最大幅、最小幅、overflow設定を見直す。
  - 盤面の拡大縮小ボタンと組み合わせて遊びやすくする。
- 横スクロールが完全に不要にできない場合でも、操作不能になるほどの横スクロール依存を避ける。
- 縦方向についても、1024×768や1366×768で主要操作が極端に切れないようにする。
- 既存の盤面データ、セルクリック処理、正誤判定処理は変更しない。
- 既存の拡大縮小機能がある場合は、その挙動を壊さない。
- 判定ボタンの内部挙動調整は別チケット扱いとし、本チケットでは行わない。

## 受け入れ条件（目視確認基準）

### 大盤面表示

- 20×20以上の盤面を開く。
- 盤面が画面中央付近に表示されること。
- 周辺UIによって盤面が過度に押し出されないこと。

### 1024×768

- 大盤面を開く。
- 左操作パネルを閉じた状態で、盤面を可能な限り広く表示できること。
- 重要UIが完全に操作不能な位置に隠れないこと。
- 横スクロールが必要な場合でも、ゲーム継続が困難なほどではないこと。

### 1366×768

- 大盤面を開く。
- 左操作パネルやパレットを調整することで、盤面を実用的に操作できること。
- セルクリック位置がズレないこと。
- 盤面の上端・左端のヒント数字が確認できること。

### 1600×900

- 大盤面を開く。
- 通常表示またはコンパクト表示で、横スクロールの負担が軽いこと。
- 拡大縮小ボタンと併用して遊べること。

### 1920×1080

- 大盤面を開く。
- 通常表示でも盤面が自然に表示されること。
- 左操作パネル、パレット、盤面のバランスが崩れていないこと。

### 操作確認

- 大盤面でセルを塗る。
- 大盤面でセルを消す。
- カラー問題で色を変えて塗る。
- 拡大縮小ボタンを押す。
- いずれもクリック位置がズレず、ゲームデータが壊れないこと。
