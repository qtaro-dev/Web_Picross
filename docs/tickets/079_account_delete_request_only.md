# チケット79: アカウント削除申請を直接削除ではなく申請受付に変更する

## 目的

ユーザーデータ画面の「アカウント削除申請」について、アカウントを直接削除せず、削除申請を受け付けるだけの安全な挙動に変更する。

## 背景

現在の確認ダイアログでは、ユーザーから見るとアカウント削除がその場で実行されるように見える。

しかし、Supabase Authユーザーの削除には service role key が必要になる可能性が高く、フロント画面から直接削除処理を行うのは危険。

そのため、このチケットでは実削除を行わず、削除申請として受け付けるだけにする。

## 前提

- service role key はフロントに出さない
- このチケットでは Auth ユーザーを直接削除しない
- profiles / user_progress / play_history / ranking_records も直接削除しない
- 管理者確認後に対応する前提の導線にする
- 実際の削除処理は後続チケットで管理者専用機能として検討する

## 実装内容

### 1. 確認ダイアログの文言を変更する

現在のアカウント削除申請ダイアログの文言を、直接削除ではなく「申請受付」であることが分かる内容に変更する。

変更後の文言例:

```text
この画面ではアカウントを直接削除しません。
削除申請として記録し、管理者確認後に対応します。
```

補足文例:

```text
アカウント削除はAuthユーザー、プロフィール、進行データ、ランキング記録に影響します。
安全のため、この画面では直接削除しません。
```

### 2. 確認ボタンの文言を変更する

現在のボタン文言が `確認` の場合、削除されるのか申請なのか分かりにくい。

以下のように変更する。

```text
キャンセル
削除申請する
```

### 3. 実削除処理を呼ばない

`削除申請する` を押しても、以下の削除処理は実行しない。

```text
Supabase Authユーザー削除
profiles削除
user_progress削除
play_history削除
ranking_records削除
localStorage削除
```

このチケットでは、データ削除を行わない。

### 4. 申請受付メッセージを表示する

削除申請ボタン押下後、ユーザーに分かりやすい完了メッセージを表示する。

表示例:

```text
アカウント削除申請を受け付けました。
管理者確認後に対応します。
```

### 5. 申請の保存方式

このチケットでは、削除申請のDB保存は必須ではない。

まずは画面上の受付表示だけでもよい。

ただし、可能であれば後続チケット用に以下の方針をREADMEまたはコメントへ残す。

```text
将来的には account_delete_requests テーブルを作成し、
削除申請日時、user_id、email、status、admin_note を保存する
```

### 6. 後続チケットへの分離

実際の削除申請DB保存や管理者対応は別チケットで行う。

後続候補:

```text
チケット80: account_delete_requests テーブル追加
チケット81: 管理者専用アカウント削除申請一覧
チケット82: 管理者専用アカウント削除処理
```

## UI仕様

- 削除申請であり、即削除ではないことが分かる
- ボタン文言が「確認」ではなく「削除申請する」になっている
- 危険操作であることが分かる見た目にする
- ただし不必要に強い警告にしすぎない
- 既存テーマに合わせる
- スマホ幅でも崩れない

## 受け入れ条件

- アカウント削除申請ダイアログに「直接削除しない」旨が表示される
- 実行ボタンが `削除申請する` になっている
- キャンセルボタンで何もせず閉じられる
- `削除申請する` を押しても Auth ユーザーは削除されない
- `削除申請する` を押しても profiles は削除されない
- `削除申請する` を押しても user_progress は削除されない
- `削除申請する` を押しても play_history は削除されない
- `削除申請する` を押しても ranking_records は削除されない
- 申請受付メッセージが日本語で表示される
- service role key をフロントに出していない
- 既存のパスワード変更処理が壊れていない
- 既存のログイン / ログアウト処理が壊れていない
- `node --check` が通る
- ビルド番号を +1 する
- `docs/ticket_status.json` にこのチケットを追加し、初期状態を `未修整` にする
