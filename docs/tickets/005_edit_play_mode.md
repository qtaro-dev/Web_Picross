# チケット5: エディットプレイモード新設

## 目的

エディタで作成したパズルを、通常問題とは別枠で遊べる「エディットプレイ」モードを新設する。  
エディタで作成中のパズル、またはローカルJSONから読み込んだ自作パズルを、通常のゲーム画面と同じ操作感でプレイできるようにする。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\styles.css`
- 必要に応じて `E:\Dev\web_picross_Ver2\index.html`

## 実装内容

### 1. 「エディットプレイ」モードを追加する

通常の問題選択とは別に、エディタ由来のパズルを遊ぶためのモードを追加する。

表示名:

```text
エディットプレイ
```

内部名の例:

```text
editPlay
editorPlay
customPlay
```

既存の命名規則がある場合は、それに合わせる。

### 2. エディタから現在のパズルをプレイできるようにする

エディタ画面に、現在編集中のパズルをプレイするためのボタンを追加する。

想定UI:

```text
エディットプレイ
```

期待動作:

```text
エディタ画面
→ 現在の盤面をプレイ用データに変換
→ ゲーム画面へ遷移
→ 通常のピクロス操作でプレイ
```

### 3. ローカルJSONから読み込んだ自作パズルも遊べるようにする

チケット4で読み込んだパズルデータを、エディットプレイ対象にできるようにする。

想定:

- エディタに読み込んだ単体パズルをプレイ
- 読み込んだパズルリストから1問選んでプレイ
- 最小実装では、現在エディタに表示されている1問をプレイできればよい

### 4. 通常問題と自作問題を分けて扱う

エディットプレイは通常の公式問題とは別枠にする。

注意:

- 通常の `beginner` / `easy` / `normal` / `hard` / `endless` の問題一覧を壊さない
- エディットプレイのクリアを通常問題のクリア済みに混ぜない
- ランキングや進捗管理がある場合、通常問題とは分離する
- 未実装の場合は無理に統合しない

### 5. ゲーム画面の既存操作を利用する

エディットプレイでも、通常ゲーム画面と同じ基本操作を使う。

維持する操作:

```text
左クリック単発: 塗りON/OFF
右クリック単発: ×ON/OFF
左ドラッグ: 連続塗り
右ドラッグ: 連続×
全消去
判定
ヒント
ギブアップ
戻る
```

塗りと×の排他制御も維持する。

### 6. 判定処理をエディットプレイ用データにも対応させる

エディタ由来のパズルでも、正解判定が動くようにする。

注意:

- 正解セルのデータ形式を通常問題と揃える
- 既存の判定ロジックを使えるなら再利用する
- 通常問題用のデータ読み込み処理に無理に混ぜ込まない
- 必要なら、エディットプレイ用の一時的な `currentPuzzle` をstateに持たせる

### 7. エディットプレイ終了後の戻り先を整理する

エディットプレイ中の戻る操作は、エディタへ戻ることを優先する。

期待動作:

```text
エディットプレイ → エディタへ戻る
```

ただし、既存のメニューへ戻る導線も必要に応じて残してよい。

### 8. 未保存データの扱いに注意する

エディタで作成中の未保存パズルをプレイする場合、元の編集データを破壊しないようにする。

注意:

- プレイ中の入力状態と、エディタの正解盤面を混同しない
- プレイ中に塗ったマスが、エディタの問題作成データを書き換えないこと
- エディタへ戻ったとき、作成中の盤面が保持されていること
