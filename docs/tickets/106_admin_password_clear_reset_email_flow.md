# チケット106：管理者パスワードクリア後の再設定メール送信導線を追加

## 背景

現在、管理者ページで対象ユーザーに対して「パスワードクリア」を実行すると、DB上では以下のような状態更新が行われる。

```text
profiles.password_clear_required = true
profiles.password_clear_requested_at = 現在日時
profiles.password_clear_requested_by = 管理者ユーザーID
profiles.password_clear_count = +1
```

管理者画面上でも、以下の表示が確認できている。

```text
パスワード再設定：必須
パスワードクリア日時：表示あり
パスワードクリア回数：1
```

しかし、対象ユーザーが現在のパスワードを忘れている場合、旧パスワードでログインできないため、ログイン後に表示される想定の新パスワード設定画面へ到達できない。

そのため、現状のままだと「管理者がパスワードクリアしたが、ユーザーはログインできず復旧できない」という状態になる。

大手サイトで一般的な復旧導線と同じく、管理者がパスワードクリアを実行した場合は、対象ユーザーの登録メールアドレスへパスワード再設定メールを送信し、メール内URLから新パスワード設定画面へ進めるようにする必要がある。

## 目的

管理者によるパスワードクリア後、対象ユーザーがログイン不能状態から復旧できる導線を作る。

管理者がパスワードクリアを実行したら、対象ユーザーの登録メールアドレスへSupabase Authのパスワード再設定メールを送信する。

対象ユーザーはメール内URLから新パスワード設定画面へ進み、新パスワード設定完了後に通常ログインできるようにする。

## 対象ファイル（推定）

```text
js/admin.js
js/actions.js
js/render.js
js/supabaseAuth.js
js/supabaseClient.js
js/state.js
styles.css
README.md
docs/vercel_supabase_production_checklist.md
docs/ticket_status.json
```

必要に応じて:

```text
api/admin-password-clear.js
api/admin-send-password-reset.js
```

ただし、Supabase Authの `resetPasswordForEmail()` を公開用クライアントで安全に使える場合は、Vercel Functions化は必須ではない。

既存実装に合わせて最小変更で対応すること。

## 実装内容

### 1. 現在のパスワードクリア処理を確認する

管理者ページの「パスワードクリア」ボタン押下時に実行される処理を確認する。

確認対象:

```text
対象ユーザーID
対象ユーザー名
対象メールアドレス
password_clear_required 更新処理
確認モーダル
完了メッセージ
```

既存のDB更新処理は維持する。

### 2. パスワードクリア時に再設定メールを送信する

管理者がパスワードクリアを確定した後、対象ユーザーのメールアドレスへパスワード再設定メールを送信する。

使用候補:

```text
Supabase Auth resetPasswordForEmail()
```

既にチケット92・94・95で実装済みの「パスワードを忘れた場合」および「再設定メール送信」処理がある場合は、それを再利用する。

処理順は原則として以下。

```text
1. 管理者が確認モーダルで対象ユーザーを確認する
2. password_clear_required を true に更新する
3. 対象メールアドレスへパスワード再設定メールを送信する
4. 成功/失敗を管理者画面に表示する
```

### 3. メールアドレスがないユーザーへの対処

対象ユーザーにメールアドレスがない場合は、パスワードクリア操作を実行できないようにする。

または、実行前に明確な警告を出す。

表示例:

```text
このユーザーにはメールアドレスが登録されていないため、パスワード再設定メールを送信できません。
先にメールアドレスを登録してください。
```

この場合、`password_clear_required` だけをtrueにしてユーザーを詰ませないこと。

### 4. 確認モーダルにメール送信の説明を追加する

パスワードクリア確認モーダルに、以下の説明を追加する。

```text
この操作を実行すると、対象ユーザーは次回ログイン前に新しいパスワード設定が必要になります。
登録メールアドレスへパスワード再設定メールを送信します。
```

表示する対象情報:

```text
ユーザー名
表示名
メールアドレス
ユーザーID
現在のアカウント状態
```

### 5. 管理者画面の完了メッセージを分かりやすくする

成功時の表示例:

```text
パスワードクリアを実行し、再設定メールを送信しました。
対象ユーザーはメール内リンクから新しいパスワードを設定してください。
```

メール送信に失敗した場合の表示例:

```text
パスワードクリアは実行されましたが、再設定メールの送信に失敗しました。
メールアドレスまたはSupabase Redirect URL設定を確認してください。
```

この場合、DB状態がtrueになってユーザーが詰まる可能性があるため、必要なら以下のどちらかを採用する。

推奨:

```text
メール送信に失敗した場合は password_clear_required を true にしない
```

代替:

```text
DB更新後にメール送信失敗した場合は、password_clear_required を false に戻すロールバック処理を行う
```

安全性を優先し、対象ユーザーがログイン不能のまま放置されないようにする。

### 6. 再設定URL後の新パスワード設定画面と連動する

チケット94で実装済みの再設定URL検出・新パスワード設定画面を再利用する。

期待する流れ:

```text
ユーザーが再設定メールのURLを開く
↓
Vercel版Webピクロスが開く
↓
新パスワード設定画面が表示される
↓
新パスワードを入力する
↓
Supabase Authのパスワードが更新される
↓
profiles.password_clear_required が false に戻る
↓
ログアウトまたはログイン画面へ戻る
↓
新パスワードでログインできる
```

### 7. password_clear_required の解除条件を確認する

新パスワード設定成功後、以下が更新されること。

```text
profiles.password_clear_required = false
profiles.last_password_changed_at = 現在日時
```

必要に応じて以下も更新する。

```text
profiles.password_clear_requested_at は残してよい
profiles.password_clear_requested_by は残してよい
password_clear_count は減らさない
```

### 8. Supabase Redirect URLの確認手順をREADMEへ追記する

READMEまたは本番確認チェックリストに以下を追記する。

Supabase Dashboardで確認する場所:

```text
Authentication
→ URL Configuration
→ Redirect URLs
```

追加が必要なURL例:

```text
https://web-picross.vercel.app/
http://127.0.0.1:8000/
```

パスワード再設定メールのリンク先がVercel版になることを確認する。

### 9. 管理者ページの表示を更新する

パスワードクリア済みユーザーの詳細欄に、次の情報が分かるようにする。

```text
パスワード再設定：必須 / 不要
パスワードクリア日時
パスワードクリア回数
最終パスワード変更日時
再設定メール送信済みかどうか
```

既に表示済みの項目は維持する。

メール送信結果をDBに保存しない場合は、画面メッセージだけでもよい。

## 受け入れ条件

### 管理者によるパスワードクリア

1. AdminQtaroでVercel版Webピクロスへログインする。
2. 管理者ページを開く。
3. ユーザー管理で対象ユーザーを選択する。
4. 「パスワードクリア」ボタンを押す。
5. 確認モーダルで対象ユーザー名・メールアドレスを確認する。
6. 実行する。

期待結果:

```text
password_clear_required が true になる
パスワードクリア日時が更新される
パスワードクリア回数が増える
対象メールアドレスへ再設定メールが送信される
```

### 対象ユーザーのメール確認

1. 対象ユーザーのメール受信箱を開く。
2. Supabaseからのパスワード再設定メールを確認する。
3. メール内URLをクリックする。

期待結果:

```text
Vercel版Webピクロスが開く
新パスワード設定画面が表示される
URL内のaccess_token等が画面に出続けない
```

### 新パスワード設定

1. 新パスワード入力欄へ新しいパスワードを入力する。
2. 確認入力欄へ同じパスワードを入力する。
3. 更新ボタンを押す。

期待結果:

```text
パスワード更新が成功する
password_clear_required が false になる
last_password_changed_at が更新される
ログイン画面へ戻る、または再ログイン案内が出る
```

### 新パスワードログイン

1. ログイン画面で対象ユーザー名、メールアドレス、新パスワードを入力する。
2. ログインする。

期待結果:

```text
ログインできる
通常メニューへ進める
パスワード再設定必須画面に戻されない
```

### 失敗時確認

メール送信に失敗する条件でテストする。

期待結果:

```text
対象ユーザーがログイン不能のまま放置されない
管理者画面に原因が分かるメッセージが表示される
```

## NG条件

```text
管理者がパスワードクリアしても再設定メールが送信されない
メールアドレス未登録ユーザーにpassword_clear_requiredだけtrueになる
再設定メールのリンク先がlocalhostになる
新パスワード設定後もpassword_clear_requiredがtrueのまま
新パスワードでログインできない
SUPABASE_SECRET_KEYをブラウザに出す
```

## メモ

このチケットは、現在の「管理者パスワードクリア」の不足導線を修正するもの。

Authユーザー本体を管理者が直接削除・変更するSecret key利用APIはチケット104で扱う。

このチケットでは、まず既存のSupabaseパスワード再設定メール導線を管理者操作と連動させる。
