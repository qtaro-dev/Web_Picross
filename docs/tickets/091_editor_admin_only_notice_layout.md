# チケット91：エディタの管理者専用化とお知らせ枠への置き換え

## 背景

現在のメニュー画面では、一般ユーザーにも「エディタ」ボタンが表示されている。

エディタはパズル編集機能であり、通常ユーザーが利用できる必要はないため、Adminユーザー専用にしたい。

また、エディタボタンを単純に非表示にするとメニュー内に空きが出るため、その位置には「お知らせ」を表示する。

管理者ユーザーの場合は、従来の「エディタ」と「管理者ページ」への導線は残すが、通常メニュー列からは外し、右側に管理者用ショートカットとして配置する。

## 現在の問題

一般ユーザーのメニュー画面に「エディタ」が表示されている。

```text
ゲームセレクト
ランキング
オプション
ヘルプ
クレジット
エディタ
ログアウト
```

管理者ユーザーのメニュー画面では、通常メニュー内に「エディタ」と「管理者ページ」が並んでいる。

```text
ゲームセレクト
ランキング
オプション
ヘルプ
クレジット
エディタ
管理者ページ
ログアウト
```

この状態だと、一般ユーザーに不要な編集機能が見えてしまう。

## 目的

一般ユーザーにはエディタを表示しない。

空いたエディタ位置には「お知らせ」を表示する。

管理者ユーザーには、右側に「エディタ」と「管理者ページ」の導線を表示する。

## 対象ファイル

推定対象:

```text
js/render.js
js/actions.js
js/state.js
js/config.js
styles.css
README.md
docs/ticket_status.json
```

主に確認する箇所:

```text
メニュー画面描画処理
エディタボタン描画処理
管理者ページボタン描画処理
ユーザー権限判定処理
エディタ画面への遷移処理
メニュー画面CSS
```

## 実装内容

### 1. 一般ユーザーのエディタボタンをお知らせに置き換える

一般ユーザーの場合、メニュー内の従来の「エディタ」位置には「お知らせ」を表示する。

一般ユーザーのメニュー構成:

```text
ゲームセレクト
ランキング
オプション
ヘルプ
クレジット
お知らせ
ログアウト
```

「お知らせ」は、現時点では画面遷移なし、または未実装メッセージ表示でよい。

例:

```text
お知らせ機能は準備中です。
```

既存の未実装機能メッセージの仕組みがある場合は、それに合わせる。

### 2. 管理者ユーザーの通常メニュー内もエディタ位置をお知らせにする

管理者ユーザーでも、中央の通常メニュー列では「エディタ」の位置を「お知らせ」に置き換える。

管理者ユーザーの中央メニュー構成:

```text
ゲームセレクト
ランキング
オプション
ヘルプ
クレジット
お知らせ
ログアウト
```

中央メニュー列には「エディタ」「管理者ページ」を置かない。

### 3. 管理者ユーザー専用の右側ショートカットを追加する

管理者ユーザーの場合のみ、メニュー画面右側に管理者用ショートカットを表示する。

表示するボタン:

```text
エディタ
管理者ページ
```

配置イメージ:

```text
中央メニュー列の右側
背景の右側パズル画像付近
縦並びで配置
```

右側ショートカットの「エディタ」は、従来のエディタボタンと同じ画面へ遷移する。

右側ショートカットの「管理者ページ」は、従来の管理者ページボタンと同じ画面へ遷移する。

### 4. Admin以外は右側ショートカットを表示しない

一般ユーザーには、右側の「エディタ」「管理者ページ」ショートカットを一切表示しない。

未ログインユーザーにも表示しない。

### 5. Admin以外のエディタ遷移を防御する

表示上ボタンを消すだけでなく、内部的にもAdmin以外はエディタ画面へ入れないようにする。

Admin以外が何らかの方法でエディタ表示処理を呼んだ場合は、メニュー画面へ戻す。

可能なら以下のようなメッセージを表示する。

```text
エディタは管理者専用です。
```

### 6. Admin以外の管理者ページ遷移も維持確認する

既存の管理者ページ制限を壊さないこと。

Admin以外が管理者ページへ入れない既存仕様は維持する。

### 7. 既存テーマ・レイアウトを崩さない

右側ショートカットは、既存の黒ボタン系デザインに合わせる。

中央メニュー列の幅・高さ・余白は大きく変更しない。

背景画像・全体の雰囲気を維持する。

画面幅が狭い場合に大きく崩れるようなら、右側ショートカットは中央メニュー下部または通常メニュー付近へ折り返すなど、最低限破綻しないようにする。

### 8. 文言は既存の管理方式に合わせる

「お知らせ」「エディタは管理者専用です。」「お知らせ機能は準備中です。」などの文言は、既存の定数・メッセージ管理がある場合はそこへ追加する。

ハードコード文字列を増やさない。

## 受け入れ条件

### 一般ユーザー

一般ユーザーでログインしてメニュー画面を表示する。

期待結果:

```text
中央メニューに「エディタ」が表示されない
中央メニューの従来エディタ位置に「お知らせ」が表示される
右側に「エディタ」「管理者ページ」が表示されない
ゲームセレクト、ランキング、オプション、ヘルプ、クレジット、ログアウトは従来通り利用できる
```

### 管理者ユーザー

AdminQtaro など、`profiles.role = admin` のユーザーでログインしてメニュー画面を表示する。

期待結果:

```text
中央メニューの従来エディタ位置に「お知らせ」が表示される
中央メニューに「エディタ」は表示されない
中央メニューに「管理者ページ」は表示されない
右側ショートカットに「エディタ」が表示される
右側ショートカットに「管理者ページ」が表示される
右側の「エディタ」から従来通りエディタ画面へ遷移できる
右側の「管理者ページ」から従来通り管理者ページへ遷移できる
```

### 未ログイン状態

未ログイン状態では、管理者用ショートカットが表示されないこと。

期待結果:

```text
右側に「エディタ」「管理者ページ」が表示されない
```

### 直接遷移・内部呼び出し防御

一般ユーザーでエディタ画面表示処理が呼ばれた場合。

期待結果:

```text
エディタ画面へ入れない
メニュー画面へ戻る
可能なら「エディタは管理者専用です。」と表示される
```

### 既存機能

期待結果:

```text
Adminの管理者ページ利用は従来通り可能
Adminのエディタ利用は従来通り可能
一般ユーザーのゲームプレイ・ランキング利用に影響がない
停止済みアカウント制御に影響がない
```

## メモ

このチケット91では、お知らせ機能の本実装までは行わない。

「お知らせ」は、まずはメニュー上の導線・枠として表示できればよい。

お知らせ内容の管理、DB連携、管理者ページからのお知らせ編集などは、必要になったら別チケットで扱う。
