# チケット127：お知らせ画像アップロード機能

## 目的

チケット126では、お知らせ記事に画像URLを指定できるようにする。  
次の段階として、管理者がお知らせ編集画面から画像ファイルをアップロードし、その画像を記事に紐付けられるようにする。

画像管理を管理者画面内で完結させ、毎回リポジトリへ画像ファイルを追加しなくてもお知らせ画像を更新できるようにする。

## 実装内容

### 1. お知らせ画像の保存先を用意する

- Supabase Storageを使って、お知らせ画像用の保存先を用意する。
- バケット名候補：`news-images`
- 画像は管理者のみアップロード・削除できるようにする。
- 一般ユーザーは公開済み記事の画像を読み取れるようにする。
- Storageのポリシーを追加する。
- SQLまたはREADMEに、バケット作成とポリシー設定手順を記載する。
- service_roleキーをフロントエンドへ露出しない。

### 2. 管理者画面に画像アップロードUIを追加する

- チケット126のお知らせ編集フォームに画像アップロードUIを追加する。
- 管理者が画像ファイルを選択できるようにする。
- 対応形式候補：
  - PNG
  - JPG / JPEG
  - WebP
  - SVGは許可する場合のみ慎重に扱い、仕様に明記する
- ファイルサイズ上限を設ける。
  - 例：2MBまたは5MB
- アップロード前にファイル形式とサイズを検証する。
- アップロード成功後、記事の `image_url` に公開URLまたは取得可能URLを保存する。
- altとキャプションは既存フォームで入力できるようにする。

### 3. アップロード済み画像のプレビューを表示する

- 管理者が画像を選択した時点で、保存前プレビューを表示する。
- 既存記事に画像がある場合は、現在の画像プレビューを表示する。
- 画像を差し替えた場合は、新しい画像プレビューへ更新する。
- 画像読み込み失敗時は代替表示を出す。
- 画像が大きすぎても編集フォームのレイアウトが崩れないようにする。

### 4. 画像削除・画像解除に対応する

- 管理者が記事から画像を外せるようにする。
- 操作例：
  - `画像を解除`
  - `画像を削除`
- 「記事から外すだけ」と「Storageから削除する」を分けるかどうかを検討する。
- 初期実装では、誤削除防止のため以下を推奨する。
  - 記事から画像URLを外す
  - Storageファイル削除は確認付き
- Storageファイル削除を行う場合は確認ダイアログを出す。
- 他の記事で同じ画像URLを使っている可能性がある場合は、削除時の注意を表示する。

### 5. ファイル名と保存パスを整理する

- アップロード時の保存パスは衝突しにくい形式にする。
- 例：
  - `news/{news_id}/{timestamp}_{sanitized_filename}`
  - `news/tmp/{timestamp}_{random}.{ext}`
- 日本語ファイル名や記号を安全に扱う。
- 拡張子やMIMEタイプを検証する。
- 不正なファイル名でStorageパスが壊れないようにする。

### 6. 一般お知らせ画面でアップロード画像を表示する

- アップロードされた画像URLを、一般向けお知らせ画面で表示する。
- チケット125/126の画像表示仕様を維持する。
- 画像は右カラムからはみ出さない。
- altとキャプションを表示できる。
- 画像読み込み失敗時は代替表示を出す。

### 7. セキュリティと権限

- 管理者以外は画像アップロードできないようにする。
- 管理者以外はStorage内の画像を削除できないようにする。
- 一般ユーザーが任意のファイルをアップロードできないようにする。
- フロントエンドにSupabase service_role keyを出さない。
- SVGを許可する場合は、XSSリスクを考慮する。
- 不安がある場合は、初期実装ではSVGアップロードを禁止してよい。

### 8. 既存仕様を壊さない

- チケット126のお知らせ管理機能を維持する。
- 画像URL手入力も残すか、アップロード優先にするかを明記する。
- お知らせ画面、ゲーム選択、実プレイ、エディタ、管理者画面の既存機能を壊さない。
- 既存テーマ・背景・ボタンデザインを維持する。
- 既存ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### Storage設定

- 開発者がSupabase Storageバケットを作成する。
- OK：`news-images` バケットが作成されること。
- OK：管理者はアップロードできること。
- OK：一般ユーザーはアップロードできないこと。
- OK：公開済み記事の画像は一般画面で表示できること。
- NG：一般ユーザーが任意ファイルをアップロードできること。

### 画像アップロード

- 管理者がお知らせ編集画面を開く。
- 管理者がPNGまたはJPG画像を選択する。
- 管理者がアップロードする。
- OK：アップロードが成功すること。
- OK：記事の画像URLにアップロード画像が紐付くこと。
- OK：保存後、一般お知らせ画面で画像が表示されること。
- NG：アップロード成功しても記事に反映されないこと。

### ファイル形式チェック

- 管理者が非対応形式のファイルを選択する。
- OK：保存前にエラー表示されること。
- NG：非対応ファイルをアップロードできること。

### ファイルサイズチェック

- 管理者が上限を超える画像を選択する。
- OK：保存前にエラー表示されること。
- NG：巨大ファイルを無制限にアップロードできること。

### プレビュー表示

- 管理者が画像を選択する。
- OK：保存前プレビューが表示されること。
- 管理者が既存画像付き記事を開く。
- OK：現在の画像プレビューが表示されること。
- NG：画像がフォームからはみ出してレイアウトが崩れること。

### 画像差し替え

- 管理者が既存画像付き記事を開く。
- 管理者が別画像をアップロードする。
- 管理者が保存する。
- OK：一般お知らせ画面で新しい画像が表示されること。
- NG：古い画像URLのままになること。

### 画像解除

- 管理者が画像付き記事を開く。
- 管理者が画像を解除する。
- 管理者が保存する。
- OK：一般お知らせ画面で画像なし記事として表示されること。
- NG：壊れた画像枠だけが残ること。

### 権限確認

- 一般ユーザーで管理者画面へアクセスしようとする。
- OK：画像アップロードUIが表示されないこと。
- OK：アップロードできないこと。
- NG：一般ユーザーがアップロードできること。

### 回帰確認

- 管理者が画像なし記事を作成する。
- OK：画像なしでも保存・表示できること。
- 管理者が画像URL手入力記事を作成する。
- OK：仕様として残す場合は表示できること。
- ユーザーがゲーム選択・実プレイ・エディタを開く。
- OK：既存画面が従来どおり動くこと。
