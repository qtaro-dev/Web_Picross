# チケット122：判定ボタンで正しい位置のXを誤り扱いしない

## 目的

現在の判定ボタンでは、正しく塗らない場所に置いたXも誤りとして扱われる場合がある。

ピクロスにおけるXは「ここは塗らない」というメモ用途であり、正解として空白であるべきセルにXが置かれていても、誤りとしてカウントしないようにする。

## 対象ファイル（推定）

- `js/actions.js`
- `js/render.js`
- `js/state.js`
- `js/config.js`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. 判定ロジックのX扱いを見直す

- 判定ボタン押下時、Xマークは「塗り」として扱わない。
- 正解データ上、空白であるべきセルにXがある場合は誤り扱いしない。
- 正解データ上、塗るべきセルにXがある場合は、誤塗りではなく「未完成」または「未塗り」相当として扱う。
- Xがあること自体を誤り数に加算しない。
- 判定の基本条件は以下を基準にする。
  - 塗るべきセルが塗られているか
  - 塗ってはいけないセルを塗っていないか
- Xマークはプレイヤー補助メモとして扱う。

### 2. 塗りセルとXセルの判定を分離する

- 判定時に、セル状態を以下のように分けて扱う。
  - 塗りセル
  - Xセル
  - 空白セル
- 誤り判定の対象は、基本的に「塗りセル」と正解データの不一致とする。
- Xセルは塗りセルとしてカウントしない。
- Xセルが正解セル上にある場合は、誤りではなく未完成扱いに寄せる。

### 3. 判定結果表示との整合性を取る

- 現在の判定結果表示が「間違い数」を表示している場合、Xを誤り数に含めない。
- Xが正解セル上にあることで完成していない場合は、結果表示が不自然にならないようにする。
- チケット123で判定結果の情報量を調整する予定のため、本チケットでは既存表示を大きく変更しすぎない。
- ただし、Xを誤り扱いしない仕様に必要な最小限の文言調整は行ってよい。

### 4. 既存操作を維持する

- 右クリックでXを付ける操作を維持する。
- Xを消す操作を維持する。
- 左クリック塗り、右クリックX、ドラッグ操作の既存挙動を維持する。
- カラー問題でも同じ判定方針にする。
- Endlessでも同じ判定方針にする。
- 既存テーマ・ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### 空白正解セルにXがある場合

- ユーザーが任意の問題を開く。
- 正解では空白であるべきセルにXを置く。
- 他の正解セルは正しく塗る。
- ユーザーが判定ボタンを押す。
- OK：空白セル上のXが誤りとしてカウントされないこと。
- NG：正しい空白セル上のXが誤り扱いになること。

### 正解セルにXがある場合

- ユーザーが任意の問題を開く。
- 正解では塗るべきセルにXを置く。
- ユーザーが判定ボタンを押す。
- OK：Xは塗り扱いにならず、完成扱いにならないこと。
- OK：誤塗りというより未完成・未塗り相当として扱われること。
- NG：Xを置いただけで正解セルが塗られた扱いになること。

### 誤って塗ったセル

- ユーザーが正解では空白であるべきセルを塗る。
- ユーザーが判定ボタンを押す。
- OK：塗ってはいけないセルを塗った場合は従来どおり誤り扱いになること。
- NG：誤塗りまで許容されること。

### カラー問題

- ユーザーがカラー問題を開く。
- 空白正解セルにXを置く。
- 色セルを正しく塗る。
- ユーザーが判定ボタンを押す。
- OK：空白セル上のXは誤り扱いにならないこと。
- OK：色違いの塗りは従来どおり誤り扱いになること。

### Endless

- ユーザーがEndless問題を開く。
- 空白正解セルにXを置く。
- ユーザーが判定ボタンを押す。
- OK：Xが誤り扱いにならないこと。
- OK：Endlessの大盤面でも判定処理が極端に重くならないこと。

### 回帰確認

- ユーザーがBeginner / Easy / Normal / Hard / Endlessを一通り開く。
- OK：セル塗り、X付け、X解除、ドラッグ操作が従来どおり動くこと。
- OK：判定ボタンが押せること。
- OK：既存のクリア判定が壊れていないこと。
