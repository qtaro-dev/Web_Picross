# チケット129：お知らせ編集UIの公開操作と画像表示改善

## 目的

チケット126〜128で管理者用のお知らせ管理・画像アップロード・複数記事作成修正を実装したが、実際に投稿してみると、公開日時・保存操作・画像アップロード・本文表示の関係が分かりにくい。

特に以下の課題がある。

- 公開日時を毎回手入力するのが面倒
- 「保存」と「今すぐ公開」の違いがUI上で分かりにくい
- 画像アップロード後のURLが一般お知らせ画面の本文側にも表示されてしまう
- 本文なし・画像のみの記事が保存できない
- アップロード画像が記事のメイン画像として表示される仕様が分かりにくい
- 管理者向けに画像URLをコピーできる導線がない
- 本文でHTMLタグが使えるのか分かりにくい

これらを改善し、管理者が迷わずお知らせ記事を作成・公開できるようにする。

## 対象ファイル（推定）

- `js/admin.js`
- `js/actions.js`
- `js/render.js`
- `js/state.js`
- `js/config.js`
- `styles.css`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. 一般お知らせ画面で画像URL文字列を表示しない

- 一般向けお知らせ画面では、`image_url` のURL文字列を本文として表示しない。
- 表示する内容は以下とする。
  - タイトル
  - 公開日
  - 本文
  - 画像
  - 画像キャプション
- `image_url` は画像表示のためだけに使う。
- 本文内にStorage URLが自動挿入されないようにする。
- 管理画面ではURLを確認できてもよいが、一般画面では長いURLを表示しない。

### 2. 本文なし・画像ありの記事を許可する

- 現在は本文が空だと保存できない場合があるため、保存条件を見直す。
- 保存条件は以下を推奨する。
  - タイトル：必須
  - 本文：任意
  - 画像：任意
  - ただし、本文または画像のどちらかは必須
- つまり以下のように扱う。
  - タイトルのみ：保存不可
  - タイトル + 本文：保存可
  - タイトル + 画像：保存可
  - タイトル + 本文 + 画像：保存可
- 本文なし・画像ありの記事は、一般お知らせ画面で画像中心の記事として自然に表示する。
- 本文がない場合に、空白や不要な本文枠だけが残らないようにする。

### 3. 「下書き保存」と「今すぐ公開」を分ける

- 管理者編集フォームの保存ボタンを分かりやすくする。
- 推奨ボタン：
  - `下書き保存`
  - `今すぐ公開`
- `下書き保存` の挙動：
  - `is_published = false`
  - 公開日時は入力済みなら保持
  - 未入力なら未入力のままでもよい
  - 記事を保存する
- `今すぐ公開` の挙動：
  - `is_published = true`
  - `published_at` に現在日時をセット
  - 記事を保存する
- 既存の `公開する` チェックボックスを残す場合でも、ボタン挙動と矛盾しないようにする。
- 保存成功・失敗メッセージを明確にする。
  - 例：`下書き保存しました`
  - 例：`公開しました`
  - 例：`保存に失敗しました`

### 4. 「現在日時を入れる」ボタンを追加する

- 公開日時入力欄の近くに、現在日時を自動入力するボタンを追加する。
- ボタン例：
  - `現在日時を入れる`
  - `今の日時`
- 押下すると、公開日時欄に現在日時が入る。
- ユーザーのローカルタイムまたは既存実装の日時形式に合わせる。
- 入力後、管理者が手動で日時を修正できるようにする。
- 日時形式がDB保存時に壊れないようにする。

### 5. 画像URLコピー機能を追加する

- 管理者編集フォームに、画像URLをコピーするボタンを追加する。
- ボタン例：
  - `画像URLをコピー`
- 対象は現在の `image_url` とする。
- 画像URLが空の場合は、コピーできないことが分かる表示にする。
- コピー成功時は、短い成功メッセージを表示する。
- コピー失敗時は、手動コピーできるようURL欄を選択しやすくする。
- 一般お知らせ画面にはコピーUIを表示しない。

### 6. 画像アップロード後の反映を分かりやすくする

- 画像アップロード成功後、画像URL欄にURLが入ったことを分かりやすくする。
- 表示例：
  - `画像をアップロードしました。保存すると記事に反映されます。`
  - `この画像は記事のメイン画像として表示されます。`
- 画像アップロード後、まだ記事保存していない場合は、保存が必要であることを表示する。
- 画像プレビューは引き続き表示する。
- 画像URL解除時は、画像が記事から外れることを分かりやすくする。
- Storageから削除する操作と、記事から画像URLを外す操作は混同しないようにする。

### 7. 本文はHTML不可であることを明示する

- 管理者編集フォームの本文欄付近に、本文の扱いを短く説明する。
- 表示例：
  - `本文はプレーンテキストで表示されます。HTMLタグは使用できません。`
- 一般お知らせ画面でも、本文をHTMLとして展開しない方針を維持する。
- XSS対策として、本文やタイトルをHTMLとして無条件に挿入しない。
- 将来的にMarkdown対応する場合は別チケット扱いとする。

### 8. アップロード画像は記事のメイン画像であることを明示する

- 管理者編集フォームに、アップロード画像の表示位置を説明する。
- 表示例：
  - `アップロード画像は本文下のメイン画像として表示されます。`
- 本文中に画像タグを貼る必要がないことが分かるようにする。
- 画像URLを本文欄に自動挿入しない。
- 一般お知らせ画面では、本文と画像を別要素として表示する。

### 9. 既存仕様を壊さない

- チケット126のお知らせ管理機能を維持する。
- チケット127の画像アップロード機能を維持する。
- チケット128の複数記事作成修正とページングを維持する。
- 一般向けお知らせ画面では公開済み記事のみ表示する。
- 非公開記事は一般向け画面に表示しない。
- `data/news.json` フォールバック仕様を維持する。
- ログイン、ゲーム選択、実プレイ、エディタ、既存管理者機能を壊さない。
- 既存テーマ・背景・ボタンデザインを維持する。
- 既存ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### 一般画面で画像URLが表示されない

- 管理者が画像付き記事を公開する。
- 一般ユーザーがお知らせ画面を開く。
- OK：本文にStorageの長いURL文字列が表示されないこと。
- OK：画像は本文下または所定位置に表示されること。
- OK：画像キャプションがある場合は表示されること。
- NG：`https://...supabase.co/storage...` のようなURLが本文として表示されること。

### 本文なし・画像あり記事

- 管理者がタイトルと画像だけの記事を作成する。
- 本文は空欄にする。
- 管理者が保存または今すぐ公開する。
- OK：記事が保存できること。
- OK：一般お知らせ画面で画像中心の記事として表示されること。
- OK：不要な空本文枠が目立たないこと。
- NG：本文必須エラーで保存できないこと。

### タイトルのみ記事

- 管理者がタイトルだけを入力する。
- 本文も画像も設定しない。
- 管理者が保存しようとする。
- OK：保存できず、本文または画像が必要であることが分かること。
- NG：タイトルのみの空記事が作成されること。

### 下書き保存

- 管理者が新規記事を作成する。
- 管理者が `下書き保存` を押す。
- OK：記事が非公開状態で保存されること。
- OK：一般お知らせ画面には表示されないこと。
- OK：管理者一覧には非公開として表示されること。
- NG：下書き保存なのに一般画面に公開されること。

### 今すぐ公開

- 管理者が新規記事を作成する。
- 管理者が `今すぐ公開` を押す。
- OK：`公開する` がON相当になること。
- OK：公開日時に現在日時が入ること。
- OK：一般お知らせ画面に表示されること。
- OK：保存成功メッセージが公開向け文言になること。
- NG：公開日時未入力のままで保存失敗すること。

### 現在日時を入れる

- 管理者が公開日時欄の近くにある `現在日時を入れる` ボタンを押す。
- OK：公開日時欄に現在日時が入ること。
- OK：その後に手動修正できること。
- OK：保存後、DBの `published_at` に正しく保存されること。
- NG：日時形式が壊れて保存できないこと。

### 画像URLコピー

- 管理者が画像付き記事を開く。
- 管理者が `画像URLをコピー` を押す。
- OK：画像URLがクリップボードにコピーされること。
- OK：コピー成功メッセージが表示されること。
- NG：画像URLが空なのに成功表示になること。
- NG：一般お知らせ画面にコピーUIが表示されること。

### 画像アップロード後の説明

- 管理者が画像ファイルを選択してアップロードする。
- OK：アップロード後、画像URL欄にURLが反映されること。
- OK：保存すると記事に反映されることが分かる説明が表示されること。
- OK：プレビューが表示されること。
- NG：アップロード済みなのか保存済みなのか分からないこと。

### HTML不可説明

- 管理者がお知らせ編集フォームを開く。
- OK：本文はプレーンテキストであり、HTMLタグは使用できないことが分かること。
- 管理者が本文に `<b>test</b>` のような文字を入力する。
- 一般お知らせ画面を開く。
- OK：HTMLとして太字にならず、文字列として安全に表示されること。
- NG：HTMLとして展開されること。

- OK：保存・公開できること。

- OK：保存・公開できること。
- 管理者が画像アップロード記事を作成する。
- OK：保存・公開できること。
- 管理者が既存記事を編集する。
- OK：対象記事だけが更新されること。
- 管理者が記事を削除する。
- OK：削除できること。
- ユーザーがゲーム選択・実プレイ・エディタを開く。
- OK：既存画面が従来どおり動くこと。
