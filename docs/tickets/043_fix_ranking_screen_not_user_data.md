# チケット43: ランキング画面がユーザーデータ画面のまま表示される問題の修正

## 目的

チケット43としてランキング画面を実装したはずだが、実際にメニューの「ランキング」を押しても、ランキング専用画面ではなくユーザーデータ画面が表示されている。

現在の実装報告では `ranking` 画面を作成したことになっているが、画面上では「ユーザーデータ」と表示されており、ランキング画面が実際には表示されていない。

このため、ランキングボタンから専用ランキング画面が確実に表示されるように修正する。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\main.js`
- `E:\Dev\web_picross_Ver2\js\userData.js`
- `E:\Dev\web_picross_Ver2\styles.css`
- `E:\Dev\web_picross_Ver2\server.js`
- `E:\Dev\web_picross_Ver2\README.md`

必要に応じて:

- `E:\Dev\web_picross_Ver2\js\ranking.js`

## 現状の症状

`http://127.0.0.1:8000/` で確認したところ、メニューのランキング導線を開いても以下の画面が表示されている。

```text
ユーザーデータ
```

表示内容もユーザーデータ画面のままであり、ランキング画面ではない。

想定される原因:

```text
- メニューの「ランキング」ボタンがまだ userData 画面へ遷移している
- screen = "ranking" は作られているが render 側で分岐されていない
- renderRanking() が定義されているが実際に呼ばれていない
- ranking画面用のstateが存在するが、actions側の遷移処理が未接続
- APIは実装されたが、画面表示処理が未接続
- ブラウザキャッシュで古いJSを読んでいる
- チケット43実装が途中で止まっている
```

## 実装内容

### 1. メニューの「ランキング」ボタン押下時の遷移先を確認・修正する

メニュー画面の「ランキング」ボタン押下時に、必ずランキング画面へ遷移するようにする。

期待状態:

```text
ランキングボタン押下
→ state.screen = "ranking"
→ render()
→ renderRanking()
→ ランキング画面表示
```

禁止状態:

```text
ランキングボタン押下
→ state.screen = "userData"
→ ユーザーデータ画面表示
```

確認箇所候補:

```text
- renderMenu()
- actions.showRanking()
- actions.openRanking()
- actions.showUserData()
- メニュー用ボタン定義
```

### 2. render() 内に ranking 画面分岐が存在するか確認する

メイン描画処理で、`ranking` 画面が正しく分岐されていることを確認する。

期待例:

```js
if (state.screen === "ranking") {
  renderRanking();
}
```

確認すること:

```text
- state.screen = "ranking" の分岐が存在する
- 分岐順で userData 側に吸われていない
- ranking と userData が同じ描画関数を使っていない
```

### 3. renderRanking() が実際に呼ばれているか確認する

`renderRanking()` が存在するだけでなく、ランキングボタンから実際に呼ばれることを確認する。

一時的にconsole.logを入れてもよい。

```js
console.log("[ranking] renderRanking called");
```

ただし、確認後に不要なログを残す場合は開発用であることが分かる形にする。

### 4. ランキング画面のヘッダーを明確にする

ランキング画面では、画面タイトルとして必ず以下を表示する。

```text
ランキング
```

表示してはいけないタイトル:

```text
ユーザーデータ
```

### 5. ユーザーデータ画面とランキング画面を完全に分離する

以下の導線を明確に分ける。

```text
メニュー → ランキング
→ ランキング画面

メニュー → ユーザーデータ
→ ユーザーデータ画面
```

注意:

- ユーザーデータ画面は壊さない
- ランキング画面から戻るとメニュー画面へ戻る
- ユーザーデータ画面から戻るとメニュー画面へ戻る
- どちらも別画面として扱う

### 6. ランキング画面の最低表示を実装する

ランキングデータ取得が未完了でも、最低限以下の画面が表示されるようにする。

```text
← 戻る

ランキング

[ビギナー] [イージー] [ノーマル] [ハード] [エンドレス]

現在の自分の順位
まだランキングデータがありません。

ランキング一覧
まだランキングデータがありません。
```

これにより、APIや集計が未完成でも画面遷移の確認ができる。

### 7. ランキングデータ取得処理を接続する

Node.jsサーバ側のランキングAPIが存在する場合、画面側から実際に取得する。

候補API:

```text
GET /api/ranking?difficulty=beginner&username=<currentUser>
GET /api/ranking/beginner?username=<currentUser>
```

確認すること:

```text
- fetchが実行されている
- APIエラー時に画面が壊れない
- 空データ時に空メッセージが出る
- 取得データが表に表示される
```

### 8. 難易度タブ切り替えを確認する

ランキング画面の難易度タブが、ランキング画面内で動作することを確認する。

対象:

```text
- ビギナー
- イージー
- ノーマル
- ハード
- エンドレス
```

### 9. 現在ユーザー順位表示を接続する

ランキング画面には、現在ログイン中ユーザーの順位を表示する。

表示例:

```text
現在の自分の順位:
ビギナー #01  2位 / 4人中  00:28
```

未クリアの場合:

```text
現在の自分の順位:
まだこの難易度のクリア記録がありません。
```

### 10. ブラウザキャッシュ対策を行う

修正後、古いJSが読み込まれて誤判定しないよう、確認手順にハードリロードを含める。

確認方法:

```text
Ctrl + F5
または
DevTools → Network → Disable cache → Reload
```

### 11. READMEのランキング説明を現状に合わせる

READMEにランキング画面の説明を追記または修正する。

記載内容:

```text
ランキング画面は、Node.jsサーバ起動時に user/*.json からクリアタイムを集計して表示する。
メニューの「ランキング」から専用画面へ遷移する。
ユーザーデータ画面とは別画面である。
```
