# チケット74: 管理者専用ページの追加

## 目的

通常ユーザー画面から管理・デバッグ系機能を分離し、`profiles.role = admin` のユーザーだけが利用できる管理者専用ページを追加する。

DBを直接編集しなくても、アプリ上からユーザー情報・進行状況・ランキングなどを確認できる管理画面の土台を作る。

## 背景

現在、ユーザーデータ画面やゲームセレクト画面に管理者向け・開発者向けの情報が混在していた。

チケット73で通常画面から管理・デバッグ情報を非表示化するため、今後は管理者専用ページへ分離する。

## 管理者アカウント方針

管理者判定は、ユーザー名の先頭に `admin` を付ける方式にはしない。

理由:

```text
ユーザー名は後から変更される可能性がある
admin という文字列を含む一般ユーザー名と衝突する可能性がある
見た目の名前で権限を判断すると危険
```

管理者判定は `profiles.role` を使う。

```text
profiles.role = 'admin' → 管理者
profiles.role = 'user'  → 一般ユーザー
```

初期管理者はSupabase Table Editorで `profiles.role` を `admin` に変更して作成する。

将来的に管理者追加UIを作る場合も、内部的には `profiles.role` を更新する。

## 実装内容

### 1. 管理者判定

- ログイン中ユーザーの `profiles.role` を確認する
- `role = admin` の場合のみ管理者専用ページへの導線を表示する
- `role = user` の場合は管理者導線を表示しない
- 未ログイン時も管理者導線を表示しない
- Supabase未設定時は管理者ページを無効化する

### 2. 管理者専用ページの追加

新しい画面を追加する。

画面名例:

```text
管理者ページ
管理画面
Admin Panel
```

表示導線例:

```text
メニュー → 管理者ページ
```

ただし、表示されるのは管理者のみ。

### 3. アクセス制御

- 一般ユーザーがURLや内部状態操作で管理者ページを開こうとしても拒否する
- 拒否時は日本語メッセージを表示する

表示例:

```text
管理者権限がありません
```

- フロント側の表示制御だけに頼らず、Supabase RLS方針も確認する
- service role key はフロントへ絶対に出さない

### 4. 管理者ページの初期UI

まずは土台のみ作る。

表示するセクション候補:

```text
ユーザー管理
ユーザー進行状況
ランキング管理
デバッグ操作
システム情報
```

各セクションはボタンまたはカード形式にする。

このチケットでは詳細な編集機能までは実装しない。  
ユーザー編集やランキング修正は後続チケットで実装する。

### 5. 管理者ページの見た目

- なるべく分かりやすいUIにする
- 通常メニューと見た目を合わせる
- 管理者ページであることが分かる見出しを付ける
- 危険操作を行う機能は赤系・警告枠などで区別できるようにする
- スマホ幅でも崩れないようにする

## 受け入れ条件

- `profiles.role = admin` のユーザーだけ管理者ページへの導線が表示される
- `profiles.role = user` のユーザーには管理者ページ導線が表示されない
- 未ログイン時に管理者ページ導線が表示されない
- 一般ユーザーが管理者ページを開こうとすると拒否される
- 管理者ユーザーは管理者ページを開ける
- 管理者ページに以下の入口がある
  - ユーザー管理
  - ユーザー進行状況
  - ランキング管理
  - デバッグ操作
  - システム情報
- service role key をフロントに出していない
- 既存のログイン・メニュー・ユーザーデータ画面が壊れていない
- `node --check` が通る
- ビルド番号を +1 する

## 初期管理者作成手順

READMEに以下のような手順を追記する。

```text
1. Supabase Dashboardを開く
2. Table Editor → profiles を開く
3. 管理者にしたいユーザーの role を user から admin に変更する
4. アプリに再ログインする
5. 管理者ページ導線が表示されることを確認する
```
