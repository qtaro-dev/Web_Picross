# チケット88：停止済みアカウントのログイン後遷移不具合修正

## 背景

チケット86・87の実装後、削除申請を承認して `profiles.account_status = disabled` になった `testuser2` でログイン確認を行った。

ログイン時に停止アカウントとして検出され、停止メッセージ自体は表示された。

しかし、停止メッセージのOKボタンを押すと、ユーザーデータ画面へ遷移してしまう。

停止済みアカウントはゲーム画面・ユーザーデータ画面へ入れない状態にするべきなので、現在の挙動は不具合。

## 現在の問題

停止済みアカウントでログインした場合、

```text
このアカウントは停止されています
```

という趣旨のメッセージが表示されるが、OK後にユーザーデータ画面へ遷移してしまう。

## 期待する動作

停止済みアカウントでログインした場合は、以下の動作にする。

```text
1. ログイン処理中に profiles.account_status = disabled を検出する
2. ログイン状態を解除する
3. ログイン画面に戻す、またはログイン画面のままにする
4. ログイン画面上に「このアカウントは停止されています。」と表示する
5. ユーザーデータ画面・ゲーム画面・管理者画面などには遷移しない
```

## 対象ファイル

推定対象:

```text
js/supabaseAuth.js
js/actions.js
js/render.js
js/admin.js
styles.css
docs/ticket_status.json
```

主に確認する箇所:

```text
Supabaseログイン処理

account_status チェック処理
ログイン画面のエラー表示処理
```

## 修正内容

### 1. 停止済みアカウント検出時の遷移を止める

Supabaseログイン成功後、`profiles.account_status` を確認する。

`account_status = disabled` の場合は、通常のログイン成功処理へ進ませない。

特に以下のような処理が走らないようにする。

```text
ユーザーデータ画面への遷移
ゲーム画面への遷移
ログイン済みUIへの切り替え
ユーザー情報表示
```

### 2. 停止済みアカウントは即サインアウトする

`account_status = disabled` の場合、Supabase Auth上のセッションが残らないようにサインアウトする。

```text
supabase.auth.signOut()
```

または既存のログアウト処理に合わせて、アプリ内状態も未ログイン状態へ戻す。

### 3. ログイン画面に停止メッセージを表示する

アラートだけで終わらせず、ログイン画面側にもメッセージを表示する。

表示文言:

```text
このアカウントは停止されています。
```

可能なら補足文も表示する。

```text
管理者にお問い合わせください。
```

ただし、文言は既存のメッセージ管理方式がある場合、それに合わせる。

ハードコード禁止方針があるため、既存の定数・設定・文言管理構造がある場合はそこへ追加する。

### 4. OKボタン後にユーザーデータ画面へ遷移しないようにする

現在は停止メッセージのOK後に、後続処理としてユーザーデータ画面表示が走っている可能性がある。

停止済み判定時は必ず `return` し、後続のログイン成功後処理を中断する。

### 5. 既存の通常ログインは壊さない

`account_status = active` または `NULL` 相当の既存ユーザーは、これまで通りログインできること。

管理者ユーザーも `account_status = active` であれば通常通り管理者ページを利用できること。

## 受け入れ条件

### 停止済みユーザー

`testuser2` など、`profiles.account_status = disabled` のユーザーでログインする。

期待結果:

```text
ログイン画面に「このアカウントは停止されています。」と表示される
OKボタンを押してもユーザーデータ画面へ遷移しない
ゲーム画面へ遷移しない
ログイン済み表示にならない
Supabaseセッションが残らない
```

### 通常ユーザー

`account_status = active` の一般ユーザーでログインする。

期待結果:

```text
通常通りログインできる
ユーザーデータ画面を開ける
ゲームをプレイできる
```

### 管理者ユーザー

`AdminQtaro` など、`profiles.role = admin` かつ `account_status = active` のユーザーでログインする。

期待結果:

```text
通常通りログインできる
管理者ページを開ける
停止済みユーザーの確認・復活操作ができる
```

### 復活後ユーザー

管理者ページで `testuser2` を利用停止解除する。

期待結果:

```text
profiles.account_status = active に戻る
testuser2 で再ログインできる
ユーザーデータ画面へ正常に入れる
ゲーム利用できる
```

## メモ

削除申請フロー自体の追加テストは `testuser3` など別ユーザーで行う。

このチケット88では、削除申請処理そのものではなく、停止済みアカウントでログインした後の画面遷移不具合だけを対象にする。
