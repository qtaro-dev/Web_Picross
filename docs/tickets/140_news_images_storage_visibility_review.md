# チケット140：お知らせ画像Storageの公開範囲見直し

## 目的

現在、`news-images` Storage bucket は public bucket として運用している。

公開済みお知らせに表示する画像としては public bucket で問題ないが、下書き記事の画像、未使用画像、誤アップロード画像も、URLを知っている人には閲覧可能になる。

現状の運用で許容するか、private bucket + signed URL などの設計へ変更するかを検討し、必要であれば最小限の改善を行う。

## 実装内容

### 1. 現在のStorage公開範囲を確認する

- `news-images` bucket の設定を確認する。
- public bucket であることを確認する。
- 一般ユーザーがアップロード・更新・削除できないことを確認する。
- 管理者のみアップロード・更新・削除できることを確認する。
- URLを知っている人が画像を読める状態であることを確認する。

### 2. 現状維持の可否を判断する

以下を整理する。

- 公開済みお知らせ画像はpublicで問題ないか
- 下書き画像がURLを知っていれば読めることを許容するか
- 誤アップロード画像を削除できる運用があるか
- 未使用画像がStorageに残り続けるリスク
- private化した場合の一般お知らせ画面への影響
- signed URLを使う場合の有効期限・表示切れリスク

### 3. 改善方針を決める

以下のどれかを採用する。

#### 案A：public bucket継続

- 現状維持。
- READMEに「お知らせ画像はURLを知っていれば閲覧可能」と明記する。
- 下書き画像や未使用画像は管理者が削除する運用にする。
- 管理者以外のアップロード・削除ができないことだけ確認する。

#### 案B：private bucket + signed URL

- bucketをprivate化する。
- 一般お知らせ画面では、公開記事の画像だけsigned URLを取得して表示する。
- signed URLの有効期限を設定する。
- 期限切れ時の再取得処理を実装する。
- 実装が大きくなるため、影響範囲を慎重に確認する。

#### 案C：公開済み記事用と下書き用を分離

- 下書き用private bucketと公開用public bucketを分ける。
- 今すぐ公開または公開保存時に公開用へ移す。
- 実装負荷が高いため、別チケット化してもよい。

### 4. 最小改善を行う

このチケットでは、まず以下の最小改善を推奨する。

- READMEに `news-images` public bucket の意味を明記する。
- 管理者UIで、画像アップロード時に「URLを知っている人は閲覧可能」と説明する。
- 未使用画像削除の導線があるか確認する。
- Storage削除操作が管理者限定であることを確認する。
- 下書き画像を完全非公開にしたい場合は、別チケットでprivate化を扱う。

### 5. 既存仕様を壊さない

- お知らせ画像の表示を壊さない。
- 画像アップロードを壊さない。
- 画像URLコピーを壊さない。
- 画像URL解除・Storage削除を壊さない。
- 一般お知らせ画面を壊さない。
- 管理者お知らせ管理を壊さない。
- ログイン、ゲーム選択、実プレイ、エディタを壊さない。
- 既存テーマ・ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### Storage権限確認

- 一般ユーザーでStorageアップロードを試す。
- OK：アップロードできないこと。
- OK：削除できないこと。
- NG：一般ユーザーが画像をアップロード・削除できること。

### 管理者アップロード

- 管理者がお知らせ編集画面で画像をアップロードする。
- OK：アップロードできること。
- OK：一般お知らせ画面に画像が表示されること。
- NG：既存画像アップロードが壊れること。

### public bucket説明

- READMEまたは管理UIを確認する。
- OK：`news-images` の画像はURLを知っている人が閲覧可能であることが説明されていること。
- NG：完全非公開であるかのような誤解を招く説明になっていること。

### 下書き画像の扱い

- 下書き記事に画像をアップロードする。
- OK：現状public運用なら、URL共有時に閲覧可能であることを仕様として把握していること。
- OK：必要ならStorage削除できること。
- NG：下書き画像が完全非公開だと誤認すること。

### Storage削除

- 管理者が不要画像を削除する。
- OK：Storageから削除できること。
- OK：記事から画像URLを外せること。
- NG：削除しても壊れた画像枠が一般画面に残ること。

### private化する場合の確認

- private bucket化を採用した場合のみ確認する。
- OK：公開済み記事の画像が一般お知らせ画面で表示されること。
- OK：signed URL期限切れ時に再取得できること。
- NG：画像がすぐ表示切れになること。

- 一般お知らせ画面を開く。

- OK：画像アップロード・URLコピー・URL解除・削除が従来どおり使えること。
