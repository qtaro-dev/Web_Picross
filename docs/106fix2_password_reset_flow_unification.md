# チケット106fix2：管理者パスワードクリア後の二重パスワード変更導線を廃止する

## 目的

管理者がユーザーに対してパスワードクリアを実行した後、ユーザー側で「メールリンクから新パスワード設定」と「ログイン後の強制パスワード変更画面」が二重に発生している。

この二重導線を廃止し、管理者パスワードクリアは Supabase のパスワード再設定メール導線だけで完結させる。

ユーザーには「管理者によりパスワードクリアされました」などの追加通知画面を表示しない。

---

## 背景

チケット106fix1で、管理者ページからパスワードクリアを実行すると、Supabase の Reset password メールが送信され、本番URLへ正しく遷移して新パスワード設定画面が表示されるところまで確認できた。

しかし、メールリンクから新パスワードを設定したあと、ログイン画面へ戻ると、再度アプリ側の強制パスワード変更画面が表示される挙動が確認された。

これはユーザー目線では「一度パスワードを変更したのに、もう一度変更を求められる」状態であり、不要な混乱を招く。

## 実装内容

### 1. 管理者パスワードクリア時に `password_clear_required = true` を設定しない

管理者がパスワードクリアを実行した場合、ユーザー本人には Supabase の Reset password メールを送信するだけにする。

メール送信成功後に更新してよい情報は、送信履歴・送信回数・送信日時などの管理用情報に限定する。

残す想定：

- `password_clear_count`
- `password_clear_requested_at`
- `password_reset_request_logs`
- 1時間5回の送信制限

廃止または更新しない想定：

- `password_clear_required = true`

### 2. ログイン後の強制パスワード変更画面を出さない

`password_clear_required` を見て、ログイン後に強制パスワード変更画面へ遷移する処理を廃止または無効化する。

以下のような表示は出さない。

- 「管理者によりパスワードクリアが行われました」
- 「新しいパスワードを設定してください」
- 管理者クリア後専用の強制パスワード変更画面

### 3. メールリンク経由のパスワード再設定だけで完結させる

ユーザーは Supabase の Reset password メールから本番URLへ遷移し、そこで新パスワードを設定する。

パスワード更新後はログイン画面へ戻り、新しいパスワードでログインできること。

ログイン後は通常メニューへ進み、追加のパスワード変更画面を表示しない。

### 4. 既存データに `password_clear_required = true` が残っている場合の扱い

既存テストデータなどで `password_clear_required = true` が残っている場合でも、ログイン後の強制変更画面を出さないようにする。

必要であれば、管理者パスワードクリアAPI成功時、またはログイン成功後のプロフィール更新時に `password_clear_required = false` へ戻す。

ただし、今後の仕様ではこのフラグを主導線に使わない。

### 5. UI文言を整理する

管理者ページ上の文言は、「パスワードを直接クリアする」印象ではなく、以下の意味が伝わる表現に寄せる。

例：

- 「パスワード再設定メール送信」
- 「対象ユーザーへパスワード再設定メールを送信します」
- 「ユーザーはメール内リンクから新しいパスワードを設定します」

ユーザー本人側には、管理者操作を示す追加通知は表示しない。

### 6. ドキュメント更新

README、Vercel/Supabase本番チェックリスト、チケット状態ファイルを更新する。

記載内容：

- 管理者パスワードクリアは Reset password メール送信に一本化
- ログイン後の強制パスワード変更画面は使用しない
- 1時間5回制限は継続
- Reset password メールリンクの有効期限は Supabase 側の Email OTP Expiration で管理

### 7. Build番号更新

`js/config.js` の Build 表示を更新する。

例：

- `Build #0000118`

既存ルールに合わせること。

## 受け入れ条件

### 管理者操作

1. AdminQtaroでログインする。
2. 管理者ページを開く。
3. 対象ユーザーを選択する。
4. パスワード再設定メール送信を実行する。
5. 実行成功メッセージが表示される。
6. 対象ユーザーに Reset password メールが届く。

OK：

- メール送信成功時のみ送信回数・送信日時・ログが更新される。
- 1時間5回制限は維持される。
- `password_clear_required = true` を新規設定しない。

### ユーザー操作

1. 対象ユーザーのメールボックスを開く。
2. 新しく届いた Reset password メールを開く。
3. メール内リンクを押す。
4. `https://web-picross.vercel.app/` の新パスワード設定画面へ遷移する。
5. 新しいパスワードを設定する。
6. ログイン画面へ戻る。
7. 新しいパスワードでログインする。

OK：

- ログイン後、通常メニューへ進む。
- 「管理者によりパスワードクリアが行われました」画面は出ない。
- 追加のパスワード変更画面は出ない。
- 同じパスワード変更を二度求められない。

### 既存フラグ残存時

既存DB上に `password_clear_required = true` のユーザーが残っていても、ログイン後に強制変更画面を出さない。

OK：

- 既存フラグが原因で二重導線にならない。
- 必要に応じて `password_clear_required = false` に戻る。

### NG条件

以下のいずれかが発生した場合はNG。

- メールリンクからパスワード変更後、ログイン時に再度パスワード変更を求められる。
- `localhost:3000` に遷移する。
- メール送信失敗時に送信回数やログだけが増える。
- 1時間5回制限が効かない。
- 管理者以外が再設定メール送信APIを実行できる。
