# チケット107：ユーザー本人による登録メールアドレス変更機能

## 背景

現在、管理者ページではユーザーのメールアドレスを確認できるが、管理者がユーザーのメールアドレスを直接変更する機能は実装していない。

メールアドレスはログインIDであり、パスワード再設定メールの送信先でもあるため、管理者が任意に変更できる機能は強すぎる。

一方で、ユーザー本人が正しくログインできている場合に、自分の登録メールアドレスを変更したい要望は自然に発生する。

そのため、管理者による直接変更ではなく、ユーザー本人がログイン済み状態でメールアドレス変更申請を行い、確認メールを通して変更する導線を追加する。

## 目的

ユーザー本人が、ユーザーデータ画面から登録メールアドレス変更を申請できるようにする。

変更はSupabase Authの本人向けメール変更フローを利用し、確認メールによる本人確認を経て反映する。

管理者ページではメールアドレスを直接編集できない状態を維持する。


## 実装内容

### 1. ユーザーデータ画面にメールアドレス変更欄を追加する

ログイン済みユーザーが開くユーザーデータ画面に、以下の表示・入力欄を追加する。

```text
現在のメールアドレス
新しいメールアドレス
新しいメールアドレス確認
メールアドレス変更申請ボタン
```

現在のメールアドレスは表示のみとする。

新しいメールアドレス欄は、入力可能にする。

### 2. 入力チェックを追加する

メールアドレス変更申請時に、以下をチェックする。

```text
新しいメールアドレスが空ではない
新しいメールアドレスがメールアドレス形式である
新しいメールアドレス確認欄と一致している
現在のメールアドレスと同じではない
50文字以内など既存仕様と矛盾しない
```

エラーメッセージは日本語で表示する。

例:

```text
新しいメールアドレスを入力してください
メールアドレスの形式が正しくありません
新しいメールアドレスと確認欄が一致しません
現在のメールアドレスと同じです
```

### 3. Supabase Authの本人向けメール変更処理を使う

ログイン済みユーザー本人のセッションを使って、Supabase Authのメール変更処理を呼び出す。

想定処理:

```text
supabase.auth.updateUser({ email: newEmail })
```

管理者用の `SUPABASE_SECRET_KEY` やAdmin APIは使用しない。

この処理はブラウザ側のログイン済みユーザー操作として行う。

### 4. 確認メール送信後のメッセージを表示する

変更申請が成功した場合、以下のようなメッセージを表示する。

```text
メールアドレス変更確認メールを送信しました。
現在のメールアドレスと新しいメールアドレスに届く確認メールを確認してください。
確認完了後、新しいメールアドレスでログインできるようになります。
```

Supabase側の設定によっては、旧メール・新メールの両方に確認が必要な場合があるため、説明文は「確認メールを確認してください」とする。

### 5. profiles.emailとの同期方針を整理する

Webピクロス側で `profiles.email` を保持している場合、Supabase Auth側のメールアドレス変更後に `profiles.email` とズレる可能性がある。

このチケットでは、以下のどちらか安全な方法を採用する。

#### 推奨案A：ログイン後にAuth emailをprofiles.emailへ同期する

ログイン成功時、またはユーザーデータ画面表示時に、Supabase Authの現在ユーザー情報を取得する。

Auth側のメールアドレスと `profiles.email` が異なる場合、自分自身の `profiles.email` をAuth側メールへ更新する。

条件:

```text
ログイン中ユーザー本人のみ
profiles.id = auth.uid()
```

管理者が他人のメールを直接変える処理にはしない。

#### 代替案B：メール変更確認完了後の復帰時に同期する

メール変更確認リンクから戻ってきたタイミングで、Auth側の現在メールアドレスを取得し、`profiles.email` を更新する。

ただし、確認リンク後のセッション復帰処理が不安定になる場合は、案Aを優先する。

### 6. 管理者ページでは直接編集不可を維持する

管理者ページのユーザー詳細では、メールアドレスを表示するだけにする。

管理者がメールアドレスを直接変更する入力欄・保存処理は追加しない。

必要なら補足表示を追加する。

```text
メールアドレス変更はユーザー本人のユーザーデータ画面から行います。
```

### 7. 変更中・送信完了状態を分かりやすくする

変更申請ボタン押下後は、処理中の二重送信を防ぐ。

```text
ボタンを一時的にdisabledにする
処理中メッセージを表示する
成功/失敗後に再度操作可能にする
```

### 8. Supabase Redirect URLを確認する

メールアドレス変更確認リンクがVercel版Webピクロスへ戻るよう、READMEまたは本番確認チェックリストに確認手順を追記する。

確認場所:

```text
Supabase Dashboard
→ Authentication
→ URL Configuration
→ Redirect URLs
```

必要URL例:

```text
https://web-picross.vercel.app/
http://127.0.0.1:8000/
```

### 9. 既存ログイン・登録・パスワード再設定を壊さない

以下の既存機能が壊れないようにする。

```text
通常ログイン
ユーザー登録
パスワード再設定メール送信
管理者パスワードクリア
パスワード変更
ADMINバッジ表示
ランキング表示
```

## 受け入れ条件

### ユーザーデータ画面表示

1. 一般ユーザーでログインする。
2. メニュー画面からユーザーデータ画面を開く。

期待結果:

```text
現在のメールアドレスが表示される
新しいメールアドレス入力欄が表示される
新しいメールアドレス確認欄が表示される
メールアドレス変更申請ボタンが表示される
```

### 入力チェック

新しいメールアドレス欄に不正な値を入れて申請する。

期待結果:

```text
空欄はエラーになる
メール形式でない場合はエラーになる
確認欄と一致しない場合はエラーになる
現在のメールアドレスと同じ場合はエラーになる
```

### 変更申請

1. ログイン中ユーザー本人が、新しい有効なメールアドレスを入力する。
2. 確認欄にも同じメールアドレスを入力する。
3. メールアドレス変更申請ボタンを押す。

期待結果:

```text
Supabase Authへメール変更申請が送信される
確認メール送信済みのメッセージが表示される
画面上にSUPABASE_SECRET_KEYやsb_secretは表示されない
```

### 確認メール

1. 新しいメールアドレスの受信箱を確認する。
2. Supabaseから届いた確認メールを開く。
3. メール内URLをクリックする。

期待結果:

```text
https://web-picross.vercel.app/ に戻る
localhostに飛ばない
ログイン状態または再ログイン導線が自然に表示される
```

### 新メールアドレスでログイン

確認完了後、新しいメールアドレスでログインする。

期待結果:

```text
新しいメールアドレスでログインできる
ユーザーデータ画面の現在メールアドレスが新しいものになる
profiles.email と Auth email が一致する
```

### 管理者ページ確認

AdminQtaroで管理者ページを開き、対象ユーザーを表示する。

期待結果:

```text
メールアドレスは表示される
管理者が直接メールアドレスを編集する欄はない
本人変更後の新しいメールアドレスが表示される
```

## NG条件

```text
管理者ページから他ユーザーのメールアドレスを直接変更できる
SUPABASE_SECRET_KEYをブラウザで使う
sb_secret_... が画面やNetworkレスポンスに表示される
確認メールなしでメールアドレスが変わる
profiles.email と Auth email がズレたままになる
メール変更後にログインできなくなる
既存のパスワード再設定導線が壊れる
```

## メモ

このチケットは、管理者によるメール変更ではなく、ユーザー本人によるメールアドレス変更機能である。

管理者がユーザーのメールアドレスを直接変更する機能は、セキュリティ・倫理面で強すぎるため、このチケットでは実装しない。

管理者による救済は、チケット106の「パスワードクリア後の再設定メール送信導線」で対応する。
