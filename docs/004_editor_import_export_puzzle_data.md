# 共通前提

- AGENT.md が存在する場合、その内容を最優先で遵守する
- ユーザーはコードを直接編集しない前提
- 実装・修正はすべて AIエージェント が行う
- 既存設計を破壊しない
- 既存テーマ・ライブラリ構成を維持する
- 既存の動作確認済み導線を壊さない
- ハードコード文字列は避け、既存の定数・状態管理・描画構造に合わせる
- 問題データの既存JSON構造を不用意に壊さない
- 変更後は対象JSファイルに対して `node --check` を実行する

# チケット4: エディタのパズルデータ入出力対応

## 目的

エディタ機能で、既存のローカルパズルデータを読み込み、編集し、JSONとして出力できるようにする。  
各難易度ごとの問題データを扱えるようにし、将来的に自作問題や追加問題を管理しやすくする。

あわせて、パズルデータに以下の管理項目を持たせられるようにする。

- 難易度フラグ
- カラー / モノクロ フラグ

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\styles.css`
- `E:\Dev\web_picross_Ver2\data\*.json`

## 実装内容

### 1. 既存パズルデータをエディタへインポートできるようにする

エディタ画面に、ローカルJSONファイルを読み込むためのUIを追加する。

想定UI:

```text
- JSON読込
- 読み込み対象の難易度選択
- 読み込み結果表示
```

ブラウザ上でローカルファイルを選択し、既存の `data/*.json` と互換性のある形式を読み込めるようにする。

### 2. 各難易度のデータを扱えるようにする

読み込み・出力時に、難易度フラグを扱えるようにする。

想定する難易度:

```text
beginner
easy
normal
hard
endless
```

UI表示名は既存の表示に合わせる。

```text
ビギナー
イージー
ノーマル
ハード
エンドレス
```

注意:

- 既存の難易度タブや問題選択構造と矛盾しないようにする
- 難易度名の表記ゆれを増やさない
- 内部値と表示名を分けられるなら分ける

### 3. カラー / モノクロ フラグを扱えるようにする

パズルデータに、カラー問題かモノクロ問題かを示す項目を持たせられるようにする。

想定例:

```json
{
  "mode": "mono"
}
```

または

```json
{
  "colorMode": "mono"
}
```

想定値:

```text
mono
color
```

注意:

- 既存データにこの項目がない場合は、モノクロ扱いを初期値にする
- 既存問題が読み込めなくならないようにする
- カラー問題の描画本格対応は今回必須ではない
- 今回はデータとして保持・入出力できることを優先する

### 4. エディタで作成したパズルをJSONとして出力できるようにする

エディタ画面に、現在のパズルをJSONとしてダウンロードするUIを追加する。

想定UI:

```text
- JSON出力
- 難易度
- カラー / モノクロ
- パズル名
- サイズ
```

出力形式は、既存の `data/*.json` と互換性を持つ形式にする。

注意:

- 既存の `loadPuzzles()` で扱える形を優先する
- 既存問題データと混ぜても破綻しない構造にする
- 不要な独自形式を増やさない

### 5. 読み込んだデータをエディタ盤面に反映する

インポートしたパズルデータを、エディタの盤面に反映する。

最低限必要な反映内容:

```text
- 盤面サイズ
- 正解セル配置
- パズル名
- 難易度
- カラー / モノクロ
```

既存エディタの操作方法は壊さない。

### 6. 入力チェックを追加する

インポート時に、最低限のチェックを行う。

チェック例:

```text
- JSONとして読めるか
- puzzles配列、または既存形式として扱えるか
- 盤面サイズが取得できるか
- セルデータが取得できるか
- 難易度フラグが不正値でないか
- カラー / モノクロ フラグが不正値でないか
```

不正な場合は、画面上のメッセージまたは `alert` で分かるようにする。

### 7. 既存データ互換を優先する

既存の `data/*.json` を読み込めることを優先する。

注意:

- 既存データに難易度フラグやカラー / モノクロフラグがない場合も読み込めること
- 不足項目には安全な初期値を入れること
- 既存問題のゲームプレイ導線を壊さないこと

## 受け入れ条件

- エディタ画面を開ける
- エディタ画面でローカルJSONを選択して読み込める
- 既存の `data/*.json` と互換性のあるデータを読み込める
- 読み込んだパズルがエディタ盤面に反映される
- 難易度フラグを設定・保持できる
- カラー / モノクロフラグを設定・保持できる
- 既存データに難易度フラグがない場合も読み込める
- 既存データにカラー / モノクロフラグがない場合もモノクロ扱いで読み込める
- エディタで作成・編集したパズルをJSONとして出力できる
- 出力JSONが既存構造と大きく矛盾しない
- 不正なJSONを読み込んだ場合に、エラーが分かる
- 既存のタイトル → メニュー → ゲームセレクト → 問題選択 → ゲーム画面の導線が壊れない
- `node --check js/editor.js` が通る
- 変更したJSファイルすべてで `node --check` が通る
