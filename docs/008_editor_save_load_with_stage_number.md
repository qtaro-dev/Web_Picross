# チケット8: 難易度・面数指定付きエディタ保存と読み込み対応

## 目的

エディタモードで作成したパズルを、難易度と面数を指定して保存できるようにする。  
また、保存したデータを再度読み込み、エディタやエディットプレイで利用できるようにする。

現在はJSONダウンロード機能はあるが、保存ボタンや「どの難易度の何面か」を管理する仕組みが不足しているため、パズルデータ管理として扱いやすい形に整える。

- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 実装内容

### 1. エディタ画面に保存UIを追加する

エディタ画面に、保存用のUIを追加する。

必要な項目:

```text
- 難易度
- 面数
- パズル名
- 盤面サイズ
- モノクロ / カラー
- 保存ボタン
```

既存のJSONダウンロードボタンがある場合は、役割を整理する。

候補:

```text
保存:
- ブラウザ内のローカル保存 localStorage へ保存

JSONダウンロード:
- ファイルとして書き出し
```

または、最小実装では「保存」ボタンでJSONダウンロードを実行してもよい。  
ただし、ボタン名と動作が分かりやすいようにする。

### 2. 面数を指定できるようにする

面数は、各難易度内の問題番号として扱う。

例:

```text
ビギナー #1
ビギナー #2
イージー #1
ノーマル #12
```

内部項目の候補:

```json
{
  "difficulty": "beginner",
  "stageNo": 1
}
```

注意:

- 既存の `id` がある場合は、それとの関係を整理する
- `stageNo` と `id` を両方持つ場合、混乱しないようにする
- 数値は 1 以上にする
- 不正値は保存させない

### 3. 保存データ形式を定義する

保存データには、最低限以下を含める。

```text
- id または stageNo
- difficulty
- title / name
- width
- height
- colorMode
- solution / cells
- updatedAt などの更新日時
```

既存の `data/*.json` と互換性を優先する。  
既存の `loadPuzzles()` が扱いやすい形にする。

### 4. ローカル保存に対応する

ブラウザ上で保存したデータを、再読み込み後も読めるようにする。

候補:

```text
localStorage
```

保存キー例:

```text
web_picross_editor_puzzles
```

注意:

- 既存のクリア状況や設定保存キーと衝突しないこと
- 通常問題データと自作保存データを混ぜないこと
- localStorage容量を考慮し、大きすぎるデータを無制限に保存しないこと

### 5. 保存済みデータを読み込めるようにする

エディタ画面で、保存済みデータを選択して読み込めるようにする。

想定UI:

```text
保存済みパズル一覧
[ ビギナー #1 エディタ作成 ▼ ]
[ 読込 ]
[ 削除 ] ※可能なら
```

最小実装では、保存済み一覧と読込だけでもよい。

### 6. 保存済みデータをJSON出力できるようにする

保存済みデータをまとめてJSONとして出力できると望ましい。

候補:

```text
- 現在編集中の1問をJSON出力
- 保存済み全件をJSON出力
```

最小実装では、現在編集中の1問出力を維持し、保存済み読み込み後に出力できればよい。

### 7. 読み込んだ保存データをエディットプレイできるようにする

保存済みデータを読み込んだ後、チケット5のエディットプレイ機能で遊べるようにする。

注意:

- 保存済みデータをプレイしても、エディタ上の正解盤面を壊さない
- 通常問題の進捗やクリア済みには混ぜない
- エディットプレイ用の一時データとして扱う

### 8. 上書き保存時の確認

同じ難易度・同じ面数に保存しようとした場合は、上書き確認を出す。

例:

```text
ビギナー #1 は既に保存されています。上書きしますか？
```

最小実装では `confirm()` でよい。

## 受け入れ条件

- エディタ画面に保存ボタンが表示される
- 難易度を指定して保存できる
- 面数を指定して保存できる
- パズル名を指定して保存できる

- 保存したデータをエディタ画面で読み込める
- 読み込んだ保存データがエディタ盤面に反映される
- 保存済みデータをエディットプレイできる
- 同じ難易度・同じ面数に保存する場合、上書き確認が出る
- 通常問題データと自作保存データが混ざらない
- 通常のゲームセレクト導線が壊れない
- 既存のJSON読込・JSONダウンロード機能が壊れない
- `node --check js/editor.js` が通る
- `node --check js/state.js` が通る
- `node --check js/data.js` が通る
- 変更したJSファイルすべてで `node --check` が通る
