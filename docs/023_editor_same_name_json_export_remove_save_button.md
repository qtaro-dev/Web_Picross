# チケット23: エディタのJSON上書き出力ボタン追加と紛らわしい保存ボタン削除

## 目的

エディットモードで、現在開いているJSONファイルを編集したあと、ファイル名を変えずに上書き用として出力できるボタンを作る。

また、パズル名の横にある「保存」ボタンは、スロット保存・JSON保存との違いが紛らわしいため削除する。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\styles.css`

## 重要な前提

ブラウザ上では、セキュリティ上の制限により、読み込んだローカルJSONファイルを勝手に直接上書きできない場合がある。

そのため、このチケットでいう「上書き」は以下の意味とする。

```text
現在読み込んでいるファイル名と同じファイル名でJSONをダウンロードする。
ユーザーが保存先で既存ファイルへ上書き保存する。
```

File System Access API等を使う本格的な直接上書き保存は、今回の必須範囲に含めない。

## 実装内容

### 1. 開いているJSONファイル名を保持する

JSONファイルを読み込んだとき、読み込んだファイル名をstate等に保持する。

例:

```text
beginner.json
normal.json
edit_puzzles.json
```

注意:

- フルパスは取得できなくてよい
- ファイル名だけ保持できればよい
- ファイル未読込の場合は安全な初期名を使う

### 2. ファイル名を変えずに出力するボタンを追加する

現在読み込んでいるJSONファイル名を使って、JSONをダウンロードするボタンを追加する。

ボタン名候補:

```text
同名でJSON出力
読込ファイル名で保存
上書き用JSON出力
```

期待動作:

```text
beginner.json を読み込む
→ 編集する
→ スロット保存で画面内データへ反映
→ 同名でJSON出力
→ beginner.json という名前でダウンロードされる
```

注意:

- 実際にPC上の元ファイルを直接更新するわけではない
- UI上では「上書き用JSON出力」と分かる文言にする
- 出力前に、現在編集中の盤面がスロットへ未反映なら注意表示することが望ましい

### 3. 別名JSON出力機能は維持する

既存の別名出力、またはチケット20で追加した別名JSON出力は維持する。

役割:

```text
同名でJSON出力:
- 読み込んだ元ファイル名で出力

別名でJSON出力:
- edit_puzzles_日時.json 等で出力
```

### 4. パズル名の横の「保存」ボタンを削除する

パズル名の横にある「保存」ボタンは紛らわしいため削除する。

理由:

```text
- スロット保存と混同する
- JSONファイル保存と混同する
- 何を保存しているのか分かりづらい
```

注意:

- 削除しても、スロット保存機能は残す
- 削除しても、JSON出力機能は残す
- 削除しても、一時保存機能は残す
- 保存系操作は「スロット保存」「同名でJSON出力」「別名でJSON出力」に整理する

### 5. 保存導線を分かりやすくする

保存操作の意味が分かるように、ボタン名や説明文を整理する。

推奨整理:

```text
スロット保存:
- 画面内の読み込み済みJSONデータへ反映

同名でJSON出力:
- 読み込んだファイル名でダウンロード

別名でJSON出力:
- 別名のJSONファイルとしてダウンロード

一時保存:
- ブラウザ内の作業バックアップ
```

### 6. JSON出力内容は最新のスロットデータを使う

同名でJSON出力する場合、対象は読み込み済みスロット全体とする。

注意:

- 空スロットは原則として出力しない
- stageNo順に並べて出力する
- 既存idを維持する
- 新規スロットは安全なidを生成する
- サムネイル画像をbase64で保存しない方針を維持する

- 再読込後、スロットデータが復元される
- エディットプレイ導線が壊れない
- 通常プレイ導線が壊れない
