# チケット131：profiles自己更新による管理者権限昇格リスクの修正

## 目的

コードレビューで、認証ユーザーが自分の `profiles` 行を任意更新できる場合、`role` を `admin` に変更して自己昇格できる可能性が指摘された。

`public.is_admin()` が `profiles.role = 'admin'` を信頼しているため、この問題は管理者RLS、Storage管理、お知らせ管理、各種管理APIに波及する重大リスクである。

一般ユーザーが自分で更新できる項目を安全な項目に限定し、`role` / `account_status` / `email` などの管理系列は管理者APIまたはservice role経由のみで更新されるようにする。

## 対象ファイル（推定）

- `docs/supabase/002_rls.sql`
- `docs/supabase/008_fix_profiles_update_policy.sql`（新規追加候補）
- `js/supabaseAuth.js`
- `js/actions.js`
- `js/admin.js`
- `js/config.js`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. profiles自己更新ポリシーを見直す

- `profiles_update_own_or_admin` 相当のRLSポリシーを確認する。
- 一般ユーザーが自分の `profiles` 行を任意更新できる状態を禁止する。
- 少なくとも以下の列を一般ユーザーが直接更新できないようにする。
  - `role`
  - `account_status`
  - `email`
  - 管理者用フラグ
  - 管理者用カウンタ
  - 削除申請・制限系の内部状態
- 一般ユーザーが変更してよい項目がある場合は、対象列を明確に限定する。
  - 例：`display_name`
  - 例：ユーザー表示設定
- PostgreSQLのRLSだけで列単位制御が不十分な場合は、自己更新を禁止し、専用RPCまたは管理API経由へ寄せる。

### 2. 管理者更新経路を維持する

- 管理者がユーザー情報を更新する既存機能は維持する。
- 管理者による利用停止・解除、メール修復、ユーザー管理機能が壊れないようにする。
- 管理者操作は既存の `is_admin()` またはservice role API経由で実行する。

### 3. SQLマイグレーションを追加する

- 本番DBへ適用するためのSQLファイルを追加する。
- 新規SQLファイル候補：
  - `docs/supabase/008_fix_profiles_update_policy.sql`
- 既存の `002_rls.sql` も、今後の初期構築用として修正する。
- SQLは可能な限り冪等にする。
  - `drop policy if exists`
  - `create policy`
  - 必要に応じて関数再定義

### 4. 既存プロフィール更新機能への影響を確認する

- ユーザー自身が更新する機能がある場合、どの項目が必要か確認する。
- 必要な項目があれば安全な専用関数/APIに分離する。
- 直接 `profiles.update()` で管理系列まで送れる実装があれば修正する。

### 5. 既存仕様を壊さない

- ログイン、ユーザー登録、ユーザーデータ画面、管理者画面を壊さない。
- 管理者によるユーザー管理機能を維持する。
- Supabase Authのメール・パスワード再設定機能を壊さない。
- 既存テーマ・ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### 一般ユーザーの自己昇格防止

- 一般ユーザーでログインする。
- ブラウザ開発者ツールやSupabaseクライアント操作相当で、自分の `profiles.role` を `admin` に更新しようとする。
- OK：更新が拒否されること。
- OK：`role` が変更されないこと。
- NG：一般ユーザーが自分の `role` を `admin` に変更できること。

### account_status変更防止

- 一般ユーザーでログインする。
- 自分の `profiles.account_status` を変更しようとする。
- OK：更新が拒否されること。
- NG：一般ユーザーが自分の停止状態を変更できること。

### 管理者のユーザー管理維持

- 管理者でログインする。
- 管理者ページでユーザー管理を開く。
- 管理者がユーザーの利用停止・解除など既存管理操作を行う。
- OK：既存どおり操作できること。
- NG：RLS修正により管理者操作まで失敗すること。

### 既存ログイン・登録回帰

- 一般ユーザーがログインする。
- 新規ユーザー登録を行う。
- パスワード再設定、確認メール再送を確認する。
- OK：既存機能が従来どおり動くこと。
