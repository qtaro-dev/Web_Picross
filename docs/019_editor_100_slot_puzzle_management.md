# チケット19: エディタの最大100スロット管理とサムネイル対応

## 目的

エディタでパズルデータを読み込んだあと、最大100個のパズルスロットを作成し、各スロットに対して個別に読み込み・保存できるようにする。

また、各スロットに以下の情報を表示できるようにする。

```text
- スロット番号
- モノクロ / カラー種別
- タイトル
- 完成したピクロスのサムネイル
```

これにより、1つのJSONファイル内で複数のパズルを管理しやすくする。

## 対象ファイル（推定）

- `E:\Dev\web_picross_Ver2\js\editor.js`
- `E:\Dev\web_picross_Ver2\js\render.js`
- `E:\Dev\web_picross_Ver2\js\state.js`
- `E:\Dev\web_picross_Ver2\js\data.js`
- `E:\Dev\web_picross_Ver2\styles.css`

必要に応じて:

- `E:\Dev\web_picross_Ver2\js\actions.js`
- `E:\Dev\web_picross_Ver2\js\thumbs.js`

## 実装内容

### 1. パズルデータ読み込み後に最大100スロットを生成する

エディタでJSONを読み込んだあと、左カラムに最大100個のスロットを表示する。

スロット番号:

```text
#1 ～ #100
```

期待動作:

```text
- 読み込んだJSON内に存在するパズルは該当スロットに表示する
- データがないスロットは空スロットとして表示する
- 最大100件まで扱う
- 101件以上のデータがある場合は、警告表示または100件までに制限する
```

注意:

- stageNo がある場合は stageNo をスロット番号として扱う
- stageNo がない場合は配列順で補完してよい
- 既存idは不用意に変更しない
- 空スロットにも保存できるようにする

### 2. 各スロットに表示する情報を整理する

各スロットには、最低限以下を表示する。

```text
- スロット番号
- モノクロ / カラー
- タイトル
- サムネイル
```

表示例:

```text
#1 [モノクロ] クロス
[サムネイル]

#2 [カラー] 花
[サムネイル]

#3 [空]
```

注意:

- 情報量が多すぎて左カラムが崩れないようにする
- タイトルが長い場合は省略表示してよい
- 選択中スロットが分かるようにする
- 空スロットは「空」または「未登録」と分かる表示にする

### 3. スロットごとの読込ボタンを設置する

スロットごと、または選択中スロットに対して「読込」できるボタンを設置する。

候補:

```text
- 各スロット内に「読込」ボタン
- スロットを選択して、下部の「読込」ボタンを押す
```

どちらでもよいが、操作が分かりやすい方を採用する。

期待動作:

```text
スロットを選択
→ 読込
→ そのスロットのパズルデータを中央のエディタ盤面へ反映
```

反映対象:

```text
- パズル名
- 難易度
- 面数 / stageNo
- 盤面サイズ
- モノクロ / カラー
- grid / grid_strings / cells / solution
- カラーID
- パレット状態
```

空スロットを読み込もうとした場合:

```text
- 空スロットであることを表示する
- 盤面を空データとして初期化するか、読み込みを中止する
```

どちらかに仕様を決めること。

### 4. スロットごとの保存ボタンを設置する

中央のエディタ盤面の現在内容を、指定したスロットへ保存できるようにする。

候補:

```text
- 各スロット内に「保存」ボタン
- スロットを選択して、下部の「保存」ボタンを押す
```

期待動作:

```text
中央盤面を編集
→ 保存先スロットを選択
→ 保存
→ そのスロットに現在のパズルデータを書き込む
```

保存する項目:

```text
- id
- stageNo
- title / name
- difficulty
- mode / colorMode
- w / h
- grid
- grid_strings
- updatedAt
- thumbnail 情報またはサムネイル生成用データ
```

注意:

- 保存時、stageNo はスロット番号に合わせる
- 既存スロットへ保存する場合は上書き確認を出す
- 空スロットへ保存する場合は新規登録として扱う
- 保存後、左カラムのスロット表示を更新する
- 保存はメモリ上の読み込み済みJSONデータに対して行う
- ファイルとして確定するにはJSONダウンロードが必要であることを分かるようにする

### 5. サムネイルを生成する

完成したピクロスのサムネイルを、各スロットに表示できるようにする。

サムネイル生成対象:

```text
- モノクロ問題
- カラー問題
```

サムネイルの仕様候補:

```text
- 小さなCSSグリッドで表示
- canvasで生成
- 既存thumbs.jsがある場合はそれを利用
```

最小実装では、CSSグリッドで小さく表示する方式でよい。

期待動作:

```text
- モノクロ問題は塗りマスが分かる
- カラー問題は各色が反映される
- 空スロットはサムネイルなし、またはプレースホルダ表示
```

注意:

- サムネイルは表示用であり、正解データそのものを壊さない
- 50x50など大きい盤面でも、左カラムに収まる縮小表示にする
- サムネイル生成が重くなりすぎないようにする
- JSONにサムネイル画像をbase64で保存するかどうかは慎重に判断する
- 原則として、サムネイルはgridから都度生成する方式を優先する

### 6. 100スロット分のJSON出力に対応する

JSON全体ダウンロード時、最大100スロット分のうち、データが存在するスロットを配列として出力する。

期待動作:

```text
#1, #2, #10 にデータがある
→ JSON出力では stageNo 1, 2, 10 のデータを含める
```

空スロットの扱い:

```text
- 原則として空スロットはJSON出力しない
- 必要なら空スロットを出力しないことを仕様とする
```

注意:

- stageNoの順に並べて出力する
- idがない場合は安全に生成する
- 既存idがある場合は維持する
- 既存のdata/*.jsonとして読み込める形式を維持する

### 7. 読み込み済みJSONと一時保存の役割を維持する

このチケットのスロット管理対象は、読み込み済みJSONデータとする。

一時保存は引き続き、ブラウザ内の作業用保存として扱う。

```text
読み込み済みJSONスロット:
- 最大100スロット
- JSON全体ダウンロード対象
- 各スロットに読込/保存

一時保存:
- ローカル作業用
- 一時保存読込/削除
- JSON全体とは別管理
```

### 8. 既存機能を壊さない

以下を維持する。

```text
- エディタ盤面編集
- モノクロ / カラー切り替え
- 16色パレット
- JSON読込
- JSON全体ダウンロード
- 一時保存
- 一時保存読込
- 一時保存削除
- エディットプレイ
- 通常ゲームセレクト
- 通常プレイ
```
