# チケット123：判定結果の情報量を調整する

## 目的

現在の判定ボタンでは、間違い数などの情報が分かることで、何度も判定を押すだけで攻略のヒントになりすぎる可能性がある。

判定ボタンは完成確認として使えるようにしつつ、途中攻略の補助になりすぎないよう、判定結果の表示情報を調整する。

## 対象ファイル（推定）

- `js/actions.js`
- `js/render.js`
- `js/state.js`
- `js/config.js`
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. 判定結果の詳細な間違い数表示を控える

- 判定ボタン押下時に、具体的な誤り数や残り数を出しすぎないようにする。
- 現在「何個間違っている」などの表示がある場合は、より抽象的な表示に変更する。
- 推奨表示例：
  - 正解の場合：`正解です`
  - まだ完成していない場合：`まだ違うところがあります`
  - 未入力が残っている場合：`まだ完成していません`
- 具体的な数値を出さないことで、判定連打による攻略補助を抑える。

### 2. 判定結果の分類を整理する

- 判定結果を大きく以下のように分ける。
  - 完全正解
  - 未完成
  - 誤った塗りがある
- ただし、ユーザーに表示する文言は詳細すぎないようにする。
- チケット122の仕様に合わせ、Xマーク自体は誤り数として扱わない。
- 正解セルにXがある場合は、完成ではないが、詳細な場所や数は表示しない。

### 3. 判定ボタンの役割を完成確認に寄せる

- 判定ボタンは「現在の盤面が正解か確認する」用途に寄せる。
- 判定結果から、あと何マス直せばいいかが分かりすぎないようにする。
- ペナルティや時間減少は本チケットでは実装しない。
- チャレンジモードやミスペナルティは別チケット扱いとする。

### 4. クリア処理は維持する

- 完全正解時には、従来どおりクリア処理へ進む。
- クリア時の保存、ランキング、進行状況更新などの既存処理を壊さない。
- 管理者用のデバッグ・即クリア系機能がある場合は、既存挙動を維持する。

### 5. 既存UIと整合性を取る

- 判定結果の表示場所やモーダル・メッセージ領域は既存UIに合わせる。
- 既存テーマ・背景・ボタンデザインを維持する。
- 日本語UIのトーンを維持する。
- ハードコード文字列は禁止。既存の文言管理方針がある場合はそれに従う。
- ICommand構造を崩さない。

## 受け入れ条件（目視確認基準）

### 完全正解時

- ユーザーが問題を完全に正しく解く。
- ユーザーが判定ボタンを押す。
- OK：正解であることが分かる表示になること。
- OK：従来どおりクリア処理が実行されること。
- OK：進行状況やランキング保存が既存どおり動くこと。
- NG：正解なのに未完成扱いになること。

### 未完成時

- ユーザーが塗るべきセルを一部未入力のままにする。
- ユーザーが判定ボタンを押す。
- OK：未完成またはまだ違うことが分かる表示になること。
- OK：具体的な残りマス数を表示しないこと。
- NG：「あと何マス」など、攻略に使える詳細数が表示されること。

### 誤塗りがある場合

- ユーザーが塗ってはいけないセルを塗る。
- ユーザーが判定ボタンを押す。
- OK：まだ違うところがあることが分かる表示になること。
- OK：具体的な誤り数を表示しないこと。
- NG：誤り数が表示され、判定連打で修正箇所を推測しやすくなること。

### Xマークとの整合性

- ユーザーが空白正解セルにXを置く。
- ユーザーが判定ボタンを押す。
- OK：Xマーク自体が誤り扱いされないこと。
- ユーザーが正解セルにXを置く。
- ユーザーが判定ボタンを押す。
- OK：完成扱いにはならないこと。
- OK：ただし、Xの数や場所を詳細表示しないこと。

### カラー問題

- ユーザーがカラー問題を開く。
- 色違いのセルを塗る。
- ユーザーが判定ボタンを押す。
- OK：まだ違うことが分かる表示になること。
- OK：色違いの数など詳細情報を表示しすぎないこと。

### Endless

- ユーザーがEndless問題を開く。
- 未完成または誤塗りの状態で判定ボタンを押す。
- OK：処理が極端に重くならないこと。
- OK：詳細な誤り数を出しすぎないこと。
- OK：完全正解時には従来どおりクリア処理へ進むこと。

### 判定連打

- ユーザーが未完成状態で判定ボタンを複数回押す。
- OK：表示される情報が攻略補助になりすぎないこと。
- OK：連打しても残り数や誤り数が分からないこと。
- NG：判定を押すたびに修正すべき数が分かること。

### 回帰確認

- ユーザーがBeginner / Easy / Normal / Hard / Endlessを一通り開く。
- OK：判定ボタンが従来どおり押せること。
- OK：完全正解時のクリア処理が壊れていないこと。
- OK：ヒント、ギブアップ、やりなおし、メニューへ戻る、セレクトに戻るが従来どおり動くこと。
