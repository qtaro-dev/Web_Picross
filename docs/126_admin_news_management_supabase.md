# チケット126：管理者用お知らせ管理機能（Supabase保存）

## 目的

チケット125で `data/news.json` を使ったお知らせ画面を実装したが、記事内容を更新するにはファイル編集とPRが必要になる。

管理者がWeb画面からお知らせ記事を作成・編集・削除・公開管理できるようにし、一般ユーザー向けのお知らせ画面には公開済み記事を表示する。

画像については、本チケットでは「画像URL指定」までを対象とし、画像ファイルのアップロード機能はチケット127で扱う。

## 対象ファイル（推定）

- `index.html`
- `styles.css`
- `js/render.js`
- `js/actions.js`
- `js/state.js`
- `js/admin.js`
- `js/supabaseAuth.js`
- `js/config.js`
- `docs/supabase/006_news_posts.sql`（新規追加候補）
- `README.md`
- `docs/ticket_status.json`

## 実装内容

### 1. Supabaseにお知らせ記事テーブルを追加する

- Supabaseにお知らせ記事用テーブルを追加する。
- 新規SQLファイル候補：`docs/supabase/006_news_posts.sql`
- テーブル名候補：`news_posts`
- カラム候補：
  - `id uuid primary key`
  - `title text not null`
  - `body text not null`
  - `published_at timestamptz`
  - `is_published boolean not null default false`
  - `image_url text`
  - `image_alt text`
  - `image_caption text`
  - `display_order integer`
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`
- RLSを有効化する。
- 一般ユーザーは `is_published = true` の記事のみ読み取り可能にする。
- 管理者は全記事の読み取り・作成・更新・削除ができるようにする。
- 既存の `is_admin()` 方針がある場合は、それを利用する。
- 既存テーブルや既存RLSを破壊しない。

### 2. お知らせ画面の読み込み元をSupabaseへ対応させる

- 一般ユーザー向けのお知らせ画面は、Supabaseの `news_posts` から公開済み記事を読み込むようにする。
- 表示対象は以下を満たす記事とする。
  - `is_published = true`
  - `published_at` が現在時刻以前、または `published_at` 未指定でも公開扱いにする仕様なら明記する
- 並び順は以下を推奨する。
  1. `published_at desc`
  2. `display_order asc`
  3. `created_at desc`
- Supabase読み込みに失敗した場合は、既存の `data/news.json` をフォールバックとして使ってもよい。
- フォールバックを使う場合は、READMEに仕様を記載する。
- お知らせ0件時は、チケット125の `現在お知らせはありません` 相当表示を維持する。

### 3. 管理者画面に「お知らせ管理」セクションを追加する

- 管理者ページに「お知らせ管理」セクションを追加する。
- 管理者のみアクセス可能にする。
- 一般ユーザーには表示しない。
- 管理者画面内で以下を行えるようにする。
  - お知らせ一覧表示
  - 新規作成
  - 既存記事の編集
  - 削除
  - 公開 / 非公開切り替え
- 一覧には以下を表示する。
  - 日付
  - タイトル
  - 公開状態
  - 更新日時
- 選択中の記事が分かる見た目にする。

### 4. お知らせ編集フォームを追加する

- 管理者用のお知らせ編集フォームを追加する。
- 入力項目：
  - タイトル
  - 本文
  - 公開日時
  - 公開/非公開
  - 表示順
  - 画像URL
  - 画像alt
  - 画像キャプション
- 本文は複数行入力できるようにする。
- HTMLを直接保存・展開する前提にしない。
- 一般表示側では本文をプレーンテキストとして扱う。
- タイトルと本文は必須にする。
- 画像URL、alt、キャプションは任意とする。

### 5. 記事の作成・更新・削除処理を実装する

- 管理者が新規記事を作成できるようにする。
- 管理者が既存記事を更新できるようにする。
- 管理者が既存記事を削除できるようにする。
- 削除時は確認ダイアログを出す。
- 公開/非公開切り替えを保存できるようにする。
- 保存成功・失敗のメッセージを表示する。
- API経由またはSupabaseクライアント経由のどちらでもよいが、RLSと管理者権限を破壊しない。
- service_roleキーをフロントエンドへ露出しない。

### 6. 画像URL指定に対応する

- 本チケットでは画像アップロードは実装しない。
- 管理者が画像URLを入力すると、一般向けお知らせ画面で画像として表示されるようにする。
- 画像URLには以下を想定する。
  - `assets/news/...`
  - 将来のSupabase Storage公開URL
  - 外部URLは許可する場合のみ仕様を明記する
- 画像読み込み失敗時はチケット125の代替表示を維持する。

### 7. 既存のJSONお知らせとの関係を整理する

- `data/news.json` は初期データ・フォールバック・開発用サンプルのいずれかとして扱う。
- どの扱いにするかREADMEへ記載する。
- Supabaseに記事がある場合は、Supabase側を優先表示する。
- `data/news.json` を完全に廃止する場合は、既存表示が壊れないようにする。

### 8. 既存仕様を壊さない

- ログイン、ユーザー登録、ゲーム選択、実プレイ、エディタ、管理者機能を壊さない。
- 管理者判定を維持する。
- 既存テーマ・背景・ボタンデザインを維持する。
- 既存ライブラリ構成を維持する。
- ハードコード文字列は禁止。
- ICommand構造を崩さない。
- 画像アップロード機能は本チケットでは実装しない。
